## MQ-R1 — 스냅샷을 지금(메모리) 만들까, 문서 영속(백엔드) 뒤로 미룰까

- [사실 L1] 저장소는 메모리 구현뿐이다. 새로고침하면 프로젝트·문서가 사라진다(편집기 빈 상태 문구가 이미 고지). `createSnapshot`·`restoreSnapshot`·`resolveConflict` = `missing`(`app/src/data/memoryProjectRepository.ts:101-103`).
- [사실 L1] 내보내기 완료 문구는 이미 "내보내기 전 스냅샷"을 말하지만 열어 볼 곳이 없다(ER SPEC 3.4).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A ★** | 메모리(탭) 스냅샷을 지금 구현. 수명 = 프로젝트와 같음 · 대화상자 캡션 "이 탭에만 보관됩니다" | 편집 안전망(복원·충돌 보존)이 지금 생김 · QB-10 스냅샷 경로·잃은 이미지 둘째 경로 검증 가능 · 서버 구현 때 같은 인터페이스 그대로 | 새로고침 소실(문서와 같음) · 레인 2개(ER-3a·3b) [추정 5~7시간] |
| B | 문서 영속(백엔드) ADR 뒤로 스냅샷 전체 보류 | 한 번에 영속 스냅샷 | 편집기 a4 E-AC-31 계속 미충족 · 내보내기 문구와 실제 불일치 지속 · 백엔드 미정(ADR 없음)이라 시점 불명 |
| C | 화면만 먼저(목록 읽기 전용 — 내보내기 전 스냅샷만), 수동·복원은 B 때 | 작은 비용 [추정 2시간] | 복원 없는 스냅샷은 안전망이 아님 |

- 백엔드(문서 영속) 자체는 이 MQ의 범위 밖 — 고르시면 별도 ADR로 올린다.
