# ADR-007 (초안) — 문서 영속: 브라우저 로컬 우선, 파일 묶음으로 백업·이동, 서버는 별도 결정

- 상태: **초안 — 결정 전** (Designer, 2026-10-07). 확정·`docs/decisions/` 이동·번호 확정은 영환님 결정(MQ.md) 뒤 Jarvis.
- 번호 주의: `docs/06-handoff/REF-LLM-PIPELINE_BRIEF.md:178`이 "ADR-007"을 다른 제목으로 **제안만** 했다(파일 없음). 확정 때 번호 충돌 여부를 Jarvis가 정한다.
- 근거 표기: [L1] 코드·문서 직접 확인(`dev/active/persist-adr/FACTS.md`) · [L3] 외부 일반 지식, 이 레인에서 네트워크 확인 안 함(확인 필요) · [추정] 측정 없음.

## 1. 문제

프로젝트·편집 문서·스냅샷·프로필 계열·비교 보드·생성 결과는 `createStudioStore()`·`createDocBook()` 클로저(탭 메모리)에, 이미지는 편집 틀 React state에, 저장한 레퍼런스는 React context에 있다 [L1]. 새로고침·탭 닫기 = 전부 소실(BACKLOG B-M2C-03), 편집기 이탈 = 이미지 소실(m2c SPEC r3). 지금까지의 결정(MQ-C2 ★A · MQ-S1 ★A · MQ-R1 ★A)은 모두 "문서 영속은 별도 ADR"로 미뤄 두었다. 이 ADR이 그 자리다.

결정할 것: 어디에(브라우저/파일/서버) · 무엇을 · 어떤 순서로 영속하는가.

## 2. 지금 구조에서 영속에 걸리는 사실 (요약, 상세 FACTS.md)

1. **경계는 대부분 있다.** `ProjectRepository`·`ProfileRepository`·`CompareBoardRepository`·`GenerationRepository`는 비동기(Promise) 인터페이스이고 구현은 동적 import [L1]. 화면을 바꾸지 않고 구현만 바꿀 수 있다.
2. **공유 store는 동기다.** `StudioStore.transact(work)`는 동기 draft 커밋 [L1 `studioStore.ts:716`]. IndexedDB는 비동기라 직접 끼울 수 없다 → **메모리 store를 그대로 두고 "하이드레이션(시작 때 읽기) + 커밋 뒤 비동기 기록(write-through)"** 방식이 유일하게 코드 변경이 작은 길이다.
3. **"청크 받기 전엔 문서 없음" 불변식.** `memoryProjectRepository`는 `book?.docOf()`로 읽어 DocBook 청크를 받기 전엔 문서가 없다고 본다 [L1 `memoryProjectRepository.ts` summaryOf·getDoc]. 새로고침 뒤엔 문서가 있는데 `hasDoc:false`로 읽힌다 → 하이드레이션이 **DocBook 상태까지 채운 뒤** 첫 읽기가 일어나야 한다.
4. **순번 id.** `profile-${size+1}`·`project-${length+1}`(`memoryBoardConfirm.ts:142`)·`snapshot-${length+1}`·`export-${size+1}` [L1]. 복원 시 상태가 같이 오면 순번도 이어지지만, (i) **두 탭이 같은 상태를 하이드레이트하면 같은 id를 각자 발급**하고 (ii) **삭제가 생기면(MQ-P3·P8) 길이 기반 순번이 지운 id를 다시 발급**한다 → 단조 카운터를 `meta`에 영속해야 한다.
5. **문서에 스키마 버전 필드가 없다.** PageDoc은 엔진 계약(engineImportGuard) — 건드리지 않고 **저장 레코드 봉투**에 `schemaVersion`을 둔다.
6. **용량은 이미지가 지배.** 이미지 탭 24개·60MB, 파일 1개 10MB, 변형본 640/1280/1920 [L1]. 문서·스냅샷 JSON은 수~수십 KB [추정]. 스냅샷은 상한·삭제 없음(2a-05 5.11) [L1] → 영속하면 무한 누적.
7. **이미지 메타는 `WeakMap<Blob, ImageMeta>`** [L1 `imageStore.ts:13`] — Blob 정체성 기반이라 복원되지 않는다. 메타는 Blob 옆에 함께 저장해야 한다.
8. **변형본은 디코드 후 재인코딩**(`createImageBitmap` → 캔버스 인코딩) [L1 `ingestImage.ts:104·110`] — 원본 파일 바이트를 보관하지 않으므로 EXIF(GPS 등)는 저장 대상에 없다 [L1 + L3: 캔버스 인코딩은 메타데이터를 옮기지 않음].
9. **예산 측정 방식.** "진입 직후" 합계 = 첫 화면 + **사용자 조작 없이 바로 받는 dynamic import의 정적 closure** [L1 `app/scripts/check-bundle-size.mjs:6·90`]. 즉 지연 청크라도 진입 때 자동으로 받으면 예산에 든다 — `memoryDocBook`을 조작 뒤 청크로 뺀 C4 수정(`memoryDocBook.ts` 머리 주석)과 `memoryProjectRepository` 미리받기 +0.04(`m2cBaseline.json` note)가 그 예. `/studio` 진입 실측 128.51 · 판정선 128.58 · 여유 **0.07KB** · 개정 8 배분 끝 [L1 `m2cBaseline.json`]. 최근 레인들은 추정(+0.04~0.35) 대비 실측(+0.58~0.73)이 컸다(ADR-004 개정 5·6) → **이 ADR은 KB를 추정하지 않고 "진입 청크에 무엇을 두지 않는가"만 정하고 E0 실측을 관문으로 둔다.**
10. **화면 분기.** `ProjectPersistence = "memory" | "server"`, "이 탭에 저장됨" 문구, `needsUnloadGuard`는 memory면 항상 경고 [L1]. 로컬 영속이면 문구·떠나기 경고 조건이 바뀌어야 한다(진입 청크 코드).

## 3. 후보

### (a) 브라우저 로컬 영속 — IndexedDB(이미지 Blob 포함)

- **사용자 가치**: 새로고침·탭 닫기·브라우저 재시작 뒤에도 프로젝트·문서·스냅샷·이미지가 남는다. 서버 0·계정 0·비용 0. 한계 = 그 브라우저 프로필 1개에만 있음(다기기·공유 없음), 브라우저 데이터 삭제·축출 시 소실.
- **데이터 모델(안)**: DB 1개, 오브젝트 스토어
  - `meta` — `{ key: "schema", schemaVersion }` · **단조 순번 카운터**(profile·project·snapshot·이미지 id — 삭제·다중 탭 뒤 재발급 방지, 판정 코드의 `length+1`을 카운터 읽기로 바꿈)
  - `studio` — StudioState 직렬화(series·commits·adjustCommits·projects; 생성 잡은 `job`만, `hidden`·`attempts` 제외)
  - `docs` — projectId → `{ schemaVersion, doc: PageDoc, saves 멱등 키 }`
  - `snapshots` — `[projectId, snapshotId]` → `{ schemaVersion, snapshot }`
  - `images` — `[projectId, localId]` → `{ variants: {640?,1280?,1920?}: Blob, width, height, format, bytes }` (메타 동봉)
  - `board`·`saved` — 비교 보드 1개 · 저장한 레퍼런스 id 집합
  - **영속하지 않음**: 내보내기 잡·`downloadRef`(blob: URL — 탭 수명), 생성 잡 진행 중 `hidden`, object URL, 실행 취소 기록, 대화상자 상태.
- **쓰기 방식**: 기존 메모리 store가 진실의 원천(동기 판정·`commit()` 규칙 불변) → 커밋된 변경을 **직렬 큐**로 IDB 트랜잭션 1개씩 기록. 큐는 순서를 보장(revision 역전 0)하고, 실패하면 `INFRA`로 SaveStatus 재시도 경로에 올린다(조용한 소실 금지). 문서 저장은 자동 저장 디바운스(2초·최대 30초, 2a-05 Q5)가 이미 묶어 주므로 IDB 쓰기 빈도 추가 조절 불필요 [추정].
- **하이드레이션(2단)**: 새로고침 뒤 `/studio/:projectId` 직접 진입은 IDB 읽기 경로가 **진입 직후 합계**에 든다(사실 9). 그래서 둘로 나눈다.
  1. **진입 읽기기(진입 자동 로드)** — IDB 열기 + StudioState 읽기 + 그 projectId의 문서 1건 읽기만. 판정 로직 0. 이 결과로 `getDoc`·`listProjects`(hasDoc)가 바로 답한다 → "DocBook 받기 전 = 문서 없음" 불변식을 "진입 읽기기가 준 문서 머리가 있으면 그것을 읽는다"로 바꾼다.
  2. **조작 뒤 청크** — 쓰기 큐·스키마 이행·스냅샷·이미지 읽기·DocBook 판정. 첫 편집·저장·스냅샷 열기 때 받고, DocBook은 진입 읽기기가 가진 상태를 **넘겨받아** 시작한다(C4 수정 유지 — DocBook을 진입에 되돌리지 않는다).
  - `profiles`는 즉시 생성되어 store를 읽는다 → 그 메서드들이 진입 읽기기 Promise를 기다리는 지점이 진입 코드다. 이 구조의 실제 KB는 **P1-E0 실측**으로만 정한다.
  - 스키마 이행이 필요한 경우(봉투 버전 < 앱 버전)만 진입 때 이행 청크를 받는다(드문 경로 — 예산 시나리오 밖, 크기만 보고).
- **다중 탭**: 의존성 0 후보 둘 —
  1. **Web Locks 단일 작성자** [L3: `navigator.locks`]: 먼저 연 탭만 쓰기, 다른 탭은 "다른 탭에서 편집 중 — 읽기 전용" 안내 + `BroadcastChannel`로 갱신 알림. ★(id 충돌 원천 차단, 구현 작음)
  2. 탭마다 쓰기 허용 + 쓰기 전 IDB 재읽기·버전 비교 → 충돌 시 STALE_*. id를 순번 대신 무작위로 바꿔야 함 → 판정 로직 변경 큼.
- **마이그레이션**: 봉투 `schemaVersion` + IDB `onupgradeneeded`의 버전별 단계 함수(순수 함수 — 단위 테스트 가능). 읽은 레코드는 경계 검증(zod — 이미 의존성 있음 [L1 package.json]) 후 하이드레이트, 실패 레코드는 격리(삭제하지 않고 "읽지 못한 항목" 표시) [추정 설계].
- **용량·축출** [L3, 확인 필요]: 브라우저별 출처당 할당량이 다르고, 저장 압박 시 best-effort 저장소는 축출될 수 있다. `navigator.storage.persist()`는 축출 면제를 요청하지만 브라우저가 거절할 수 있고(Chrome은 휴리스틱, Safari는 비활성 출처 데이터 7일 정책 이력), `navigator.storage.estimate()`로 사용량 표시 가능. → 화면에 "이 브라우저에 저장됨 · 사용량 N MB"와 (b) 파일 백업 유도를 둔다.
- **보안**: 같은 출처 XSS면 IDB 전체(문서·이미지)를 읽고 지울 수 있다 — 지금(탭 메모리)도 XSS면 현재 탭 데이터는 노출되므로 **증가분은 "과거·다른 프로젝트 데이터까지"와 "디스크 잔존"**. 렌더 iframe은 `sandbox="allow-scripts"`(불투명 출처) [L1] → iframe 안 코드는 앱 출처 IDB에 접근 불가 [L3] — 이 경계(allow-same-origin 금지)를 유지하는 것이 핵심 완화. 공용 PC에 사용자 사진이 남는다 = MQ-C2 ★A 근거("사진이 남지 않음")를 뒤집는 결정 → **MQ**. 상세 THREATS.md.
- **번들**: 쓰기 큐·이행·스냅샷·이미지·DocBook 판정 = 조작 뒤 청크. **진입 직후 합계에 드는 것** = 진입 읽기기(IDB 열기·단건 읽기·봉투 zod 검증 중 진입 몫) · 대기 Promise · `"local"` 문구 분기 · 떠나기 경고 조건. 여유 0.07KB로는 들어가지 않을 가능성이 높다 [추정] → **P1-E0에서 "영속 문서가 있는 상태로 새로고침 후 `/studio/:projectId` 직접 진입" 시나리오를 실측**, 128.58 넘으면 멈추고 예산 MQ(MQ-P5).
- **새 의존성**: 0 가능. 원시 IndexedDB API를 Promise로 감싸는 얇은 어댑터(트랜잭션 1개 = Promise 1개)를 직접 쓴다. `idb`(래퍼)는 편의만 주므로 불필요 — 쓰려면 MQ.
- **테스트**: `StudioPersistence` 어댑터 인터페이스(load/apply) + **메모리 가짜**로 하이드레이션·큐 순서·실패·마이그레이션 단위 테스트(의존성 0). 실제 IDB 동작(트랜잭션·Blob 저장·업그레이드)은 jsdom에 없음 → (i) `fake-indexeddb` 개발 의존성(MQ) 또는 (ii) Ego Lite로 build+preview 브라우저 실측(새로고침 생존·탭 2개 잠금) 중 택1. ★ (ii) + 순수 함수 단위 테스트.
- **되돌리기**: 저장소 구현 선택 1곳(`deferredStudio` 조립)을 메모리로 돌리면 즉시 복귀. IDB 데이터는 남지만 읽지 않음 → "이 브라우저 데이터 지우기"로 제거. 스키마 이행은 앞으로만(다운그레이드 시 봉투 버전이 높으면 읽지 않고 안내).

### (b) 로컬 우선 + 파일 내보내기·가져오기(프로젝트 묶음 파일)

- **사용자 가치**: 백업·기기 이동·축출 대비. 서버 0. (a) 없이 단독이면 새로고침 생존 0 — 매번 파일을 직접 열어야 함 → 단독 안으로는 약하고 **(a)의 보완**으로 가치가 크다.
- **데이터 모델**: 프로젝트 1개 = 파일 1개. 내용 = 봉투 `{ format: "design-studio-project", schemaVersion, exportedAt, project, profileSeries(해당 계열), doc, snapshots, images }`. 이미지 직렬화 두 갈래:
  1. **JSON + base64** — 의존성 0, 크기 ×1.33 [L3]. 최악 60MB → 약 80MB 파일 [추정]. 대용량 문자열 메모리 피크 주의.
  2. **zip(무압축 store 방식 직접 구현 또는 라이브러리)** — 이미지 원바이트, 라이브러리면 새 의존성(MQ). 정적 HTML·React zip(M4)과 공유 여지.
- **가져오기 규칙**: 같은 projectId·profileId가 이미 있으면 **새 id로 다시 매김**(순번 충돌 방지) · 모양 검증 `checkSaveDoc`·zod 봉투 · 이미지 바이트는 `formatFromMagic`·크기 상한(10MB/개, 60MB/프로젝트) 재검사 · 실패 시 쓰기 0(전부 아니면 전무).
- **보안**: 가져온 파일은 **신뢰할 수 없는 입력** — 문서 텍스트는 이미 렌더러가 이스케이프·sandbox로 다룸 [L1 staticMarkup 결과 규칙], 이미지 바이트는 디코드 재인코딩을 다시 거치게 한다(악성 이미지 표면 축소). zip이면 경로 순회·압축 폭탄 상한.
- **번들**: 내보내기·가져오기 코드는 메뉴 조작 뒤 청크 — 진입 0 목표(툴바 "더보기" 메뉴 본문이 이미 조작 뒤 청크 `MoreMenuBody` [L1 m2cBaseline note]).
- **새 의존성**: base64 안 0 · zip 라이브러리 안 1(MQ).
- **테스트**: 직렬화·가져오기 검증·id 재매김은 순수 함수 단위 테스트(jsdom Blob 충분). 파일 선택·내려받기는 Ego Lite.
- **형식 이행**: 봉투 `schemaVersion` — 가져오기 때 IDB 이행과 같은 순수 함수 단계로 올려 읽는다. 앱보다 높은 버전 파일은 거부 + 안내.
- **단계**: (a) P1 뒤 P2 — IDB 직렬화 코드를 재사용한다.
- **되돌리기**: 기능 메뉴 제거만으로 복귀. 이미 내보낸 파일은 사용자 소유 — `schemaVersion`으로 장래 가져오기 호환 유지 의무가 생김(되돌려도 남는 부채).

### (c) 서버 영속 — 계정·API·DB·객체 저장소

- **사용자 가치**: 다기기·공유(FR-CMP-04 조직 공유 P1, FR-PUB-06 미리보기 링크 P1 [L1 PRD]) · 축출 없음 · 백업은 운영이 담당.
- **데이터 모델**: 저장소 인터페이스 주석이 이미 REST(GET/PUT/POST · If-Match)로 쓰여 있어 API 모양은 정해져 있다 [L1 `projectRepository.ts:143-163`]. DB(프로젝트·프로필 버전·문서·스냅샷), 객체 저장소(이미지). TRD v0.2는 AOS PostgreSQL `design_studio` 스키마 + S3 호환을 전제 [L1 TRD 74행].
- **ADR-001과의 관계**: ADR-001은 "독립 저장소, AOS 변경 0, 백엔드는 이 인터페이스를 유지한 채 이후 단계"로 정했고 TRD의 AOS 의존 부분은 개정 대상으로 남겼다 [L1]. 따라서 **`~/Work/shared-infra`(AOS와 공유하는 PostgreSQL/Redis)에 이 앱의 데이터를 두는 것은 ADR-001 위반 소지** — 쓰려면 ADR-001 개정이 먼저다. 독립을 지키려면 자체 DB·객체 저장소·인증을 새로 마련해야 한다(호스팅 사업자·비용·계정 = 전부 MQ).
- **보안·개인정보**: 인증·권한(조직 분리 TR-SEC-01), 업로드 이미지 개인정보 처리방침·보관 기간·삭제 요청, 전송 암호화, 백업, 감사. 운영 책임이 생긴다.
- **번들**: fetch 기반 클라이언트는 작지만 인증 상태·토큰 갱신·오프라인 처리가 진입에 닿는다 [추정] — 실측 필요.
- **새 의존성**: 서버 프레임워크·DB 드라이버·인증 라이브러리 등 다수 + 외부 서비스 가입 → 이 레인 범위 밖, 전부 MQ.
- **테스트**: API 계약 테스트 · 메모리 구현과 같은 인터페이스 테스트를 서버 구현에 재사용(현 테스트의 delay·fail 주입 모양이 이미 네트워크 경로를 흉내 냄 [L1]).
- **이관(로컬 → 서버)**: (b) 파일 묶음 형식 = 업로드 형식으로 재사용 — 로그인 뒤 "이 브라우저 프로젝트를 계정으로 올리기" 1회 이관, id는 서버가 다시 발급.
- **단계**: 별도 ADR(호스팅·인증·처리방침) → API·DB 레인 → 서버 구현을 같은 인터페이스에 조립 → 이관 화면.
- **되돌리기**: 가장 길고 되돌리기 어려움(사용자 데이터가 서버에 생기면 삭제·이관 의무).

## 4. 추천 ★ — (a) 로컬 IndexedDB를 먼저, 이어서 (b) 파일 묶음, (c)는 별도 ADR

이유:
1. 사용자 문제(새로고침 소실)를 서버·계정·비용 없이 푼다. ADR-001 독립 원칙에 그대로 맞는다.
2. 저장소 인터페이스를 바꾸지 않는다 — (c)로 갈 때 같은 인터페이스에 서버 구현을 꽂고, 로컬 데이터는 (b) 형식으로 "서버로 올리기"에 재사용된다.
3. MQ-S1이 지적한 "이미지만 영속하면 이득 0"을 피한다 — 문서·스냅샷·이미지를 **한 번에** 영속한다(이미지 분리 영속 안은 탈락).
4. 의존성 0으로 가능하다(원시 IDB + 기존 zod).

탈락·보류: (b) 단독(새로고침 생존 없음) · 이미지만 IDB(MQ-S1) · (c) 지금(계정·비용·운영·ADR-001 개정이 먼저, 공유 요구 P1이라 급하지 않음).
