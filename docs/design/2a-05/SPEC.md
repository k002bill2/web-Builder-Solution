## 2. IA · 라우트 · 흐름

### 2.1 프로젝트 단위 (Q1=A · ADR-005 Q1 이행)
- **프로젝트 = 이름 + 프로필 계열 1개 + 편집 문서 1개(Q3) + 발행(2a-05b).** 프로필 계열과 1:1이다 — 프로필 버전은 프로젝트 안의 이력이고, 편집 문서는 그중 한 버전(과 한 안)을 가리키는 필드를 가진다(Q3).
- 프로젝트는 **보드 확정 때만** 생긴다(Q2 · ADR-005 Q1 "확정 시 프로젝트를 만들거나 골라"). 이름 입력 대화상자는 없다 — 기본 이름으로 만들고 나중에 바꾼다(Q2).
- 기본 이름 = `"<기준 레퍼런스 제목> 프로젝트"`(기준 = 프로필 `baseReferenceId`, 2a-04 A-Q1). 같은 이름이 있으면 `" 2"`, `" 3"`…을 붙인다(순수 함수 `defaultProjectName(title, existingNames)` — 목록에서 두 줄을 구별하기 위해서다).
- 보드는 사용자당 1개(ADR-005 Q1)라 **보드 `confirmed`가 가리키는 프로젝트 = "보드의 현재 프로젝트"**다. 다른 프로젝트를 고르는 방법은 "현재 프로젝트 새 버전 / 새 프로젝트" 두 가지뿐이다(12.2 — 임의의 다른 프로젝트로 확정하면 이어받기 기준(`confirmedBase`)이 없는 계열에 보드 값을 쓰게 되어 2a-04 6.1-3 규칙이 성립하지 않는다).

### 2.3 흐름

```
GNB "새 프로젝트" ──▶ /compare?new=1
                       ├─ 보드가 비었음 ──▶ 기존 보드 빈 상태("카탈로그에서 고르기")
                       └─ 선택 → 확정 대상 [새 프로젝트 | <현재 프로젝트> 새 버전 (vN)] (J-S10)
```

| 1280 | **3단** 왼쪽 약 220 · 가운데 나머지 · 오른쪽 약 300(목업 비율. 값은 spacing 토큰, px 하드코딩 금지) | 왼쪽 열 + 아래 "테마" | 오른쪽 열: 편집 → 게이트 | 가운데 |
| 1024 (1024~1279) | **2단** 캔버스 · 오른쪽 약 300 | 툴바 `Select` "섹션"(선택 바꾸기) + 오른쪽 열 맨 위 `details` "섹션 목록 · 순서"(기본 접힘, 펼치면 1280 목록과 같은 부품 · "섹션 추가") | 오른쪽 열: 섹션 목록(접힘) → 편집 → 테마 → 게이트 | 왼쪽 |
| 768 (768~1023) | **탭**(390과 같은 구성) | "섹션" 탭 | "편집" 탭 · "검사" 탭 | 탭 패널 아래 |
| 390 (<768) | **탭** — 툴바 → 탭 목록(섹션 · 편집 · 검사) → 탭 패널 → 캔버스 | "섹션" 탭: 목록 + 위로/아래로(선택 섹션) + 섹션 추가 + 테마 | "편집" 탭: 선택 섹션 필드·변형·순서·삭제 / "검사" 탭: 게이트 + 내보내기 | 맨 아래 h2 "구조 미리보기", 폭 컨트롤은 캔버스 머리 |

- 5폭 모두 **가로 넘침 0**(`scrollWidth − clientWidth`). 넓은 프레임(태블릿 768 · 데스크톱)이 캔버스보다 넓으면 축소 보기(`transform: scale`, 캡션 "축소 보기 · 48%")이고 가로 스크롤을 만들지 않는다.
- ≥1024: 화면 높이 = 뷰포트(`100dvh`), 툴바 고정, **열마다 따로 스크롤**. 캔버스 열은 포커스 가능한 요소가 없을 수 있으므로 스크롤 영역에 `tabindex=0` + 접근 이름 "구조 미리보기"(키보드 스크롤, axe `scrollable-region-focusable`). <1024: 문서 전체가 한 번에 스크롤, 고정 요소 없음(포커스 가림 2.4.11 부담 0).
- 1024~1279의 `Select`와 `details` 목록은 **같은 선택 상태**를 쓴다. `Select`는 선택만, 순서·추가·삭제는 목록·편집 패널에서.
- 탭 전환은 문서·선택·스크롤을 잃지 않는다. 폭이 바뀌어 배치가 바뀌어도(회전·창 크기) 선택 섹션·열린 대화상자는 유지되고, 포커스가 사라진 요소에 있었다면 새 배치의 같은 기능 요소로 옮긴다(없으면 h1).

### 4.2 툴바 넘침 규칙

| 요소 | ≥1280 | 1024 | <1024 |
|---|---|---|---|
| "프로젝트로 돌아가기" | 아이콘 버튼(`chevron-left`) | 같음 | 같음, 조작 크기 ≥ 32 |
| h1 프로젝트 이름 | 한 줄 말줄임 | 같음 | 같음 + **아래 줄에 저장 상태** |
| 문서 Tag "B안 · 프로필 v3" | 툴바 | 오른쪽 "테마" 영역으로 | "섹션" 탭 "테마" 영역으로 |
| 저장 상태 글자 | 툴바 | 툴바 | h1 아래 줄 |
| "섹션" `Select` | 없음 | 툴바 | 없음(탭) |
| 미리보기 폭 | 툴바 가운데 | 툴바 | 캔버스 머리 |
| "스냅샷" | 툴바 | "더보기" 안 | "더보기" 안 |
| "더보기" | 실행 취소 · 다시 실행 | + 스냅샷 | + 스냅샷 |
| 검사·내보내기 | "검사 · 내보내기"(primary) | 같음 | "검사"(primary, 접근 이름 "검사 · 내보내기" — 보이는 글자 포함 2.5.3) |

- "더보기" = 버튼(`aria-expanded`) + 바로 아래 버튼 목록. `role=menu`를 쓰지 않는다(항목 2~3개 — 일반 버튼 목록이 Tab 순서·낭독 모두 단순). Esc = 닫고 "더보기"로 포커스.
- 1280에서도 한 줄에 안 들어가면(긴 이름·확대 200%) 이름이 먼저 줄어든다(말줄임). 버튼 글자는 줄지 않는다.

### 4.3 DOM 순서 = 보이는 순서 = Tab 순서
- ≥1280: 건너뛰기 링크 → 툴바 → 섹션 열(페이지 정보 · 섹션 줄 · 섹션 추가 · 테마) → 캔버스 영역 → 편집 패널 → 게이트 · 내보내기.
- 1024: 건너뛰기 → 툴바 → 캔버스 영역 → 오른쪽(섹션 목록 `details` → 편집 → 테마 → 게이트).
- <1024: 건너뛰기 → 툴바 → 탭 목록 → 탭 패널 → 캔버스 영역.
- 폭마다 배치가 달라 순서도 다르다 → CSS `order`로 흉내 내지 않고 **배치별로 트리를 다르게 그린다**(`matchMedia` 한 곳, 상태는 공유). 건너뛰기 링크 "본문으로"의 대상은 앱 셸 `main` 그대로.

## 5. 상호작용

URL 상태는 `projectId`뿐이다. 선택 섹션 · 미리보기 폭 · 탭 · 스냅샷 미리보기는 화면 상태다(문서 정본은 저장소 — 2a-04 2.1과 같은 원칙). 모든 편집 연산은 **문서를 새로 만드는 순수 함수**(L4 엔진, 8.2)이고 화면은 결과만 그린다.

### 5.1 섹션 선택
- 섹션 줄 = `button`(이름 + 변형 이름표 캡션 + 게이트 표시 글자 "경고 1"/"차단 1" Tag). 선택 줄: `aria-current="true"` + 굵기 700 + `primary-container` 면 + 왼쪽 막대 `primary`(3:1, 7절) — 색 외 단서 2개(B-01의 "색만 다른 이름" 해소).
- 맨 위 "페이지 정보" 줄은 섹션이 아니다(이동·삭제 없음). 고르면 편집 패널이 SEO 메타 필드(5.6)를 보인다.
- 캔버스에서 섹션을 누르면(포인터) 같은 선택이 된다. 캔버스 섹션은 Tab 정지가 아니다 — 같은 기능을 목록·`Select`·탭이 키보드로 준다(2.1.1 충족, Tab 정지 중복 방지).
- 선택이 바뀌면 캔버스는 그 섹션이 보이게 스크롤(`scrollIntoView({block:"nearest"})`, `prefers-reduced-motion`이면 즉시). 포커스는 옮기지 않는다.

### 5.2 순서 바꾸기 (Q6=A — 1280·1024·390 같은 버튼 한 벌, 드래그 없음)
- 편집 패널 머리(≥1024)와 "섹션" 탭·"편집" 탭(<1024)에 **같은 부품** "위로" · "아래로"(글자 버튼, 아이콘 없음 — P-B3). 선택 섹션을 한 칸 옮긴다.
- 옮긴 뒤 포커스는 누른 버튼에 그대로(버튼이 편집 패널에 있어 움직이지 않는다). 섹션 목록에서 누른 경우(<1024 "섹션" 탭)는 버튼이 선택 줄 옆에 따라 붙어 있으므로 역시 그대로. 알림 `role=status` "Services를 4번째로 옮겼습니다".

| 경계 | 버튼 | 이유(보이는 글자) |
|---|---|---|
| 맨 위 본문 바로 아래가 Hero | "위로" `aria-disabled` | "Hero 위로는 옮길 수 없습니다 (R-02 Hero는 첫 본문)" |
| Hero 자체 | 둘 다 `aria-disabled` | "Hero는 첫 본문 자리에 고정됩니다 (R-02)" |
| Header · Footer | 둘 다 `aria-disabled` | "Header는 맨 위에 고정됩니다" / "Footer는 맨 아래에 고정됩니다" (R-01) |
| 마지막 본문 | "아래로" `aria-disabled` | "Footer 아래로는 옮길 수 없습니다" |

- 목적 R-03("문의" → cta-band·contact가 후반 1/3)을 깨는 이동은 **막지 않는다** — 게이트 "필수 섹션"이 차단으로 알린다(편집 중 임시 상태 허용).

### 5.3 섹션 추가 (E-08 · R-01)
- "섹션 추가"(아이콘 `plus` + 보이는 글자 "섹션 추가" — 목업은 아이콘뿐, B-10) → 모달 대화상자(네이티브 `dialog`, 5.15) "섹션 추가": ① 유형 라디오 목록(라이브러리 순서, 이름표 + 한 줄 설명) → ② 그 유형의 변형 라디오 목록(이름표 + 구조 썸네일 `aria-hidden`) → "추가"(primary) · "취소".
- Header·Footer는 이미 있으면 유형 목록에서 `aria-disabled` + 이유 "Footer는 하나만 둘 수 있습니다". Hero도 같음(R-02 정확히 1개).
- 넣는 자리: 선택 섹션 바로 뒤(선택이 Header·"페이지 정보"면 Hero 뒤, Footer면 Footer 앞). 새 섹션의 슬롯 = 엔진 기본 슬롯 콘텐츠(TRD 6.2 "기본 슬롯 콘텐츠"), 모션 = 문서 모션 프리셋과 L1 중 낮은 값(R-07 예산을 새로 쓰지 않음).
- 추가 뒤: 대화상자 닫힘 → 새 섹션 선택 → 포커스 = 새 섹션 줄(<1024는 "섹션" 탭의 그 줄) → 알림 "FAQ를 6번째에 추가했습니다".
- 상한: 본문 9개면 버튼 `aria-disabled` + 이유(E-S12). 대화상자는 열리지 않는다.

### 5.4 삭제 · 되돌리기 (Q7=A)
- "삭제"(글자 버튼, 편집 패널 머리 "위로·아래로" 옆 — 목업 2a-07 314행 배치). 확인 대화상자 없음, 즉시 삭제.
- 알림 줄(섹션 목록 위, <1024는 탭 목록 아래 — 늘 보이는 자리): "Services를 삭제했습니다" + "되돌리기"(버튼). **다음 편집 연산이 생기면 사라진다**(Q7). 알림 줄은 `role=status` 영역 안의 글자 + 형제 버튼(D-QA06 "담았습니다 + 보드 열기" 형식).
- 포커스: 삭제 → 다음 섹션 줄(없으면 이전 줄). 되돌리기 → 되살린 섹션 줄 + 선택 복원 + 알림 "Services를 되돌렸습니다".

| 삭제할 수 없는 섹션 | 조건 | 이유 문장 |
|---|---|---|
| Header · Footer | 늘 | "Header는 페이지에 꼭 하나 있어야 합니다 (R-01)" |
| Hero | 늘 | "Hero는 첫 본문으로 꼭 있어야 합니다 (R-02)" |
| Contact(예약 변형) | 목적 "예약"이고 그것이 유일 | "목적이 '예약'이라 Contact(예약)가 필요합니다 (R-04)" |
| cta-band · contact | 목적 "문의"이고 둘 중 남은 하나 | "목적이 '문의'라 문의 섹션이 하나는 필요합니다 (R-03)" |
| 본문 | 본문이 5개 | 막지 않는다 — 게이트 "필수 섹션" 차단으로 알린다(추가로 고칠 수 있음) |

- 목적은 프로필 조정 값(`adjustments.purpose`, 2a-04 Q5)이다. 편집기는 목적을 바꾸지 않는다(프로필 소유) — 이유 문장 옆 링크 "프로필에서 목적 바꾸기".

### 5.5 변형 교체 (E-11)
- 편집 패널 머리 "변형: 풀블리드 이미지 + 좌측 카피" + "변형 바꾸기"(`details`/펼침). 펼치면 라디오 목록: 변형 이름표 + 캡션 **"유지 4 · 잃음 1 (부제)"**(슬롯 스키마 비교 — 같은 키·같은 종류면 유지, 없으면 잃음, 8.2 `diffSlots`). 잃음 0이면 "슬롯 모두 유지".
- 고르면 바로 적용(확인 없음, Q7과 같은 되돌리기 모델) → 알림 줄 "스플릿으로 바꿨습니다 · 잃은 슬롯 1개(부제)" + "되돌리기". 포커스는 라디오에 그대로.
- 목업의 `chevron-down` 버튼("fullbleed-left ▾")은 변형 **키**를 보인다 → 이름표로(2a-04 M-06 원칙, EM).

### 5.6 필드 편집 (E-13 · FR-EDT-05)
- 슬롯 종류: 짧은 글(`TextField`) · 긴 글(`textarea`, 같은 토큰) · 링크 라벨 · 이미지(5.9). 라벨 = 슬롯 이름표(한국어), 필수 표시 = 라벨 옆 글자 "(필수)".
- 카운터 "18 / 24자"(`tabular-nums`, `aria-describedby`로 입력과 연결, **알림 영역 아님** — 매 글자 낭독 금지). 슬롯 스키마의 두 값: **상한**(`maxLength`, R-13 차단) · **권장**(넘치면 2줄·잘림 위험, FR-EDT-05 경고). 권장이 없으면 상한만.
- 권장 초과: 카운터 뒤 "권장 28자 — 넘으면 2줄이 될 수 있습니다"(`status-cautionary-text`, 경고). 상한 초과: `aria-invalid=true` + "상한 40자를 6자 넘었습니다 — 내보내기를 막습니다 (R-13)"(`status-negative-text`). 두 경우 모두 **입력은 막지 않는다**(붙여 넣고 줄이는 흐름 보호).
- 필수 슬롯 빈 값: 포커스를 떠날 때(blur) "필수 입력입니다" + `aria-invalid`(입력 중에는 알리지 않음).
- "페이지 정보"(SEO 메타, R-11): 제목(title) · 설명(description) — 문서 단위 필드. 권장 길이 제목 60자 · 설명 160자(검색 결과 표시 폭 관행, L3 — 정본은 L4 슬롯 스키마), 빈 값 = 차단. canonical은 캡션 "발행 주소가 정해지면 채웁니다(2a-05b)" — 2a-05에서는 검사하지 않는다(발행 도메인이 없다, TRD R-11 부분 이행 → EM).
- 입력마다 문서가 바뀌고 자동 저장·게이트 재계산이 디바운스로 따라온다(5.10·5.12). 실행 취소 기록은 **입력칸 포커스가 떠날 때 한 번**(글자마다 쌓지 않음).

### 5.7 캔버스 표시 (Q12 · FR-EDT-05 "경고가 섹션을 가리킴")
- 섹션 블록 = 2a-04c 구조안 와이어프레임(블록·막대, 프로필 토큰 색) + **실제 슬롯 글자**. 색은 문서 테마(프로필 버전 적용된 팔레트)를 CSS 변수로 넘긴다 — 컴포넌트 hex 0(`noHardcodedStyle`, 목업 252~260행 hex는 EM).
- 캡션 상시(캔버스 머리): **"구조 미리보기 — 섹션 구성과 실제 문구입니다. 실제 페이지는 생성기 연결 후(M2) 만들어집니다."**
- 선택 섹션: 2px `primary` 테두리 + 라벨 칩 "Hero · 풀블리드 이미지 + 좌측 카피"(12px·700, `on-primary` 글자 / `primary` 면 4.95, B-12).
- 문제 표시(B-03): 문제 요소에 **2중 테두리**(안쪽 2px 흰 간격 `background-normal` + 바깥 2px `status-cautionary-text`(경고) / `status-negative-text`(차단)) + 모서리 번호 배지 글자 "경고 1"/"차단 1"(상태 글자 토큰 on 흰 면). 요소 아래 문장 "3번 카드 제목이 권장 28자를 넘었습니다 (34/28자)"(상태 글자 토큰). 흰 간격 때문에 사용자 데이터 색(프로필 면) 위에서도 테두리는 늘 흰 면과 맞닿는다 → 3:1 판정이 데이터와 무관(7절).
- 문제 문장 ↔ 필드 연결: 필드의 `aria-describedby`가 캔버스 문장과 카운터를 함께 가리킨다. 캔버스 배지를 누르면(포인터) 그 필드로 포커스.
- 이미지 슬롯: 자체 플레이스홀더 패턴(대각 줄무늬 토큰, `aria-hidden`) 또는 사용자 로컬 이미지(EQ-3). 외부 URL·레퍼런스 캡처 0(PRD 원칙 4).
- 사용자 사이트 글자 대비(프로필 색 위 글자)는 앱 UI 대비가 아니라 **게이트 "대비 AA"의 검사 대상**이다(B-12). 캔버스는 불투명도 글자를 쓰지 않는다(목업 `rgba(255,255,255,.6)` → EM).

### 5.8 테마 바꾸기 (E-12 · FR-EDT-03)
- 테마 = **문서가 가리키는 프로필 버전**(Q3 "프로필 버전은 문서 필드"). 무드 테마(M2)는 같은 자리로 확장한다.
- "테마 바꾸기" → 대화상자: 이 프로젝트의 프로필 버전 라디오 목록(버전 · 출처 · 요약 — 2a-04 3.5 줄 문장 재사용 · 대비 결과 "대비 미달 1"/"대비 통과" 글자) → "바꾸기".
- 적용 = 문서의 프로필 버전 필드만 바뀐다. 섹션·변형·슬롯 값은 그대로 → **검증 결과를 글자로**: 적용 전후 모든 슬롯 값을 비교(`diffSlotValues`)해 "슬롯 값 23개 모두 그대로입니다". 다르면(결함) "슬롯 값 2개가 달라졌습니다: Hero 제목, …" + 자동 되돌리기 없이 "되돌리기" 제공(E-AC로 0건 보장).
- 새 버전이 목적(`purpose`)을 바꿨다면 필수 섹션 판정이 바뀐다 → 게이트가 다시 계산해 알린다(편집기는 섹션을 자동 추가하지 않는다).
- "프로필 보기" = `/profile/:profileId?v=<문서 버전>` 링크(같은 탭 이동. 메모리 store는 유지).

### 5.9 이미지 슬롯 (E-14 · B-18)
- 스위치 = `button role=switch aria-checked` + 보이는 라벨 "배경 이미지 사용"(`aria-labelledby`) + 캡션 "끄면 이미지 없이 색 면으로 보이고 대체텍스트 검사에서 빠집니다"(B-18). Switch 부품이 DS에 없다 → studio 청크 안 작은 부품(10.2 S-B6).
- 켜진 슬롯: 이미지 미리보기(플레이스홀더 또는 EQ-3 로컬 이미지) + "대체텍스트"(`TextField`, 필수 — 비면 게이트 R-09 차단) + `Checkbox` "장식 이미지 — 대체텍스트 없이 둡니다"(체크하면 대체텍스트 입력 `aria-disabled` + 이유, 게이트 통과).
- 파일 고르기·교체·실패(형식·크기)는 EQ-3 결정에 따른다. 추천안 A의 실패 문장: "JPEG·PNG·WebP만 쓸 수 있습니다" · "5MB까지 쓸 수 있습니다 (7.2MB)" — 필드 오류(`aria-invalid` + 설명), 이전 이미지 유지.

### 5.10 자동 저장 (Q5=A · FR-EDT-06)
- 문서 연산이 생기면 **마지막 변경 뒤 2초 디바운스, 첫 미저장 변경부터 최대 30초**(maxWait)에 저장한다. 저장은 한 번에 하나 — 저장 중에 생긴 변경은 끝난 뒤 다음 저장에 모은다.
- 저장 요청 = 문서 전체 + `expectedRevision`(보고 있던 revision) + 문서 해시. 불일치 → `STALE_DOC`(E-S09). 같은 revision·같은 해시 재요청은 멱등(응답 실패 뒤 재시도가 두 revision을 만들지 않음 — 2a-04 6.3 멱등 선례).
- 상태 전이·문구는 E-S06~E-S10. 알림은 **단계가 바뀔 때만**: "저장하지 못했습니다"(alert 1회) · "다시 저장했습니다"(실패에서 회복할 때만 status). 평상시 "저장됨"은 낭독하지 않는다(글자로만) — 매 2초 낭독 금지.

- 차단 1건 이상: 두 버튼 `aria-disabled` + 보이는 이유 "차단 1건(SEO 메타: 설명 없음) — 고치면 열립니다" + 링크 "첫 차단으로 이동"(B-09).
- 경고만: 누르면 확인 대화상자(E-S24). 경고 목록(원인 · 이동 링크는 대화상자를 닫고 이동) + "경고를 확인했습니다 · 내보내기" / "취소". 체크박스 확인은 요구하지 않는다(Q8=A — B안 기각).
- 시작: 게이트 결과가 오래됐으면 먼저 다시 계산 → 자동 스냅샷(내보내기 전) → `requestExport(projectId, format, docRevision)` 잡 → E-S27. 같은 (문서 revision · 형식) 재요청은 같은 잡(멱등).

### 5.14 실행 취소 모델 (E-20 · Q7)
- 문서 연산(추가·삭제·이동·변형·필드 확정·이미지·테마·복원)은 기록 스택에 쌓인다(최대 50). 실행 취소도 **새 문서 상태**를 만들고 자동 저장된다.
- Q7 알림 줄의 "되돌리기" = 바로 앞 연산 하나의 실행 취소와 같다. 다음 연산이 생기면 알림 줄은 사라지지만 기록 스택으로는 계속 되돌릴 수 있다(E-20 범위, 단계 a4 — 13.1).
- 복원·충돌 해결은 스냅샷으로도 보존되므로, 기록 스택은 세션(탭) 안에서만 유지한다.

### 5.15 대화상자 공통
- 네이티브 `dialog` + `showModal()`(새 의존성 0). 제목 h2 = 접근 이름(`aria-labelledby`). 열 때 포커스 = 첫 입력(없으면 제목), 닫을 때 = 연 버튼. Esc = 취소. 바깥 클릭으로 닫지 않는다(입력 보호).
- 쓰는 곳 4개: 섹션 추가 · 테마 바꾸기 · 스냅샷 · 경고 확인. 모두 **조작 뒤 로드 청크**(10절).

## 6. 접근성

### 6.1 제목 구조 (B-05)
- **편집기**: h1 = 프로젝트 이름(툴바 안, 시각 크기는 툴바 글자 — `text-body1` 700, 제목 요소만 h1). h2 = "섹션" · "테마" · "구조 미리보기" · "편집 · Hero" · "품질 게이트". h3 = 게이트 안 "내보내기". 대화상자 제목 = h2. <1024 탭에서도 같은 h2가 각 탭 패널 안에 있다(탭 이름 ≠ 제목이어도 된다 — "검사" 탭 안 h2 "품질 게이트").
- `document.title` = "<프로젝트 이름> 편집"(B-05) · `/projects` = "프로젝트".
- **프로젝트 목록**: h1 "프로젝트", 줄마다 h2 = 프로젝트 이름(제목 탐색으로 줄 이동).
- 목업의 `t-h2` 모양 `span`(Hero · 품질 게이트)은 제목 요소로(EM).

### 6.2 랜드마크 · 영역
- 편집기 툴바 = `header`(앱 GNB 대신, 랜드마크 banner 1개 유지). 섹션 열 = `nav aria-label="섹션"`(문서 안 이동 목록), 캔버스 = `section aria-labelledby`(h2 "구조 미리보기"), 오른쪽 열 = `aside`가 아니라 `section` 둘(편집 · 품질 게이트 — 보조 정보가 아니라 주 작업 영역).
- <1024 탭: `role=tablist aria-label="편집 도구"` + `role=tab`(`aria-selected`·`aria-controls`) + `role=tabpanel`(`aria-labelledby`, `tabindex=0`). 방향키 ←/→ · Home/End, **자동 활성**(패널이 가볍고 이미 그려져 있음). 기존 `rovingFocus.ts` 재사용. Tabs 부품이 DS에 없다 → studio 청크 안 작은 부품(10.2 S-B6).

### 7.2 규칙
- **사용자 데이터 색 위의 표시는 2중으로**: 캔버스 섹션 면은 프로필 색(데이터)이라 대비를 미리 알 수 없다. 그래서 선택 테두리·문제 테두리 모두 **안쪽 2px 흰 간격(`background-normal`) + 바깥 2px 토큰색**(v2 3.4 포커스 2중 링과 같은 방법) → 테두리는 늘 흰 간격과 맞닿아 N-1·N-2·N-6 값이 보장된다. 배지·라벨 칩은 자기 면(흰 면 · `primary`)을 가지므로 데이터와 무관하다.
- 목업 경고 점·테두리 `--warning`(`--status-cautionary` 계열, 흰 면 1.80 — v2 3.4)은 **혼자 알리는 곳에 쓰지 않는다**(B-01·B-03). 장식 점(게이트 줄, 6.6 표)만 `--status-*`.
- 목업 게이트 값 글자 `--warning-text` 4.26 · `--danger-text` 3.84 · 통과 `--caption` 3.61(v2 원값, 배경 집합 최저 — B-02) → 보정 토큰 `status-cautionary-text` · `status-negative-text` · `label-alternative`(v2 3.2 최저 4.64~4.68).
- 입력 테두리 = `line-strong`(3:1, v2 Q4 — B-13). 목업 `.in` `--border-strong` 1.45는 쓰지 않는다.
- 캔버스의 사용자 사이트 글자(프로필 색 위)는 앱 UI 대비 대상이 아니다 → 게이트 "대비 AA"(5.12)가 판정한다. 불투명도 글자(`rgba(255,255,255,.6)`, 목업 260행)는 캔버스에서 쓰지 않는다(C-12 opacity 금지 이어받음).
- 다크: 앱에 `data-theme="dark"`를 켜는 코드가 없다(v2 3.1). 2중 테두리의 간격 색이 `background-normal`이므로 다크에서도 "상태 글자 토큰 / 자기 배경"이 되고, 그 값은 v2 3.2 다크 상태 글자(최저 4.62 이상)로 이미 검증돼 있다.
