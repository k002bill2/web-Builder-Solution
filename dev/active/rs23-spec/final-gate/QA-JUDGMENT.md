## 3. 새 지적 (QA)

### QA-1 [P2 · 사용자 결과] R-E6/C-E6 복구 안내 "편집기에서 한 번 저장하면 확인됩니다"를 사용자가 따를 수단이 없다
- 근거(L1): 편집기는 `idle`로 시작한다(`useAutosaveScheduler.ts:59` — SPEC 2.3). 저장은 편집(dirty)에서만 일어나고, 수동 저장 버튼은 없다. "다시 저장"은 실패 상태에서만 보인다(`components/studio/SaveStatus.tsx:20,58-59`).
- 결과: 경로 ②(그 사이 편집이 commit 뒤 실패)에서 R-E6/C-E6는 기억을 지우고 링크를 되살린다 → `/projects` 게이트가 사라지고, 편집기는 `idle`(상태 글자 없음·떠나기 경고 없음)로 열린다. 사용자는 "한 번 저장"할 방법을 찾지 못하거나 이미 저장됐다고 여기고 새로고침할 수 있다 → **메모리에만 있던 그 사이 편집이 소실**. 문구는 "확인하지 못했을 수 있습니다"로 정직하지만, 행동 지시가 실행 불가능하고 게이트 해제 뒤 남는 신호는 1회성 알림뿐이다(알림 수명은 미구현 — **미확인**).
- 이 위험은 MQ-3-4(경고 없음 선택, 사용자 재확인 대기)·RS3-R1과 같은 부류다. r0.2가 새로 연 경로(고착 해소의 대가)이므로 SPEC 5.3 "남는 경로" 표에 올라 있어야 하는데, RS3-R1은 history 재진입만 다루고 R-E6/C-E6 게이트 해제 뒤 경로는 적혀 있지 않다.
- 판정: 새 P2 사용자 결과 결함 → 지시대로 **수정하지 않고 구현 BLOCKED**.

### 관찰(결함 아님)
- R-E6/C-E6 경로 ①(그 사이 편집 저장 성공)은 편집 저장이 레코드 전체 flush라 실제로 영속됐다 — 문구가 "할 수 있다"로 완화돼 거짓은 아니다.
- "확인 저장(같은 내용 `saveDoc`) 같은 새 쓰기는 하지 않는다"는 결정 자체는 일관적이다. QA-1은 그 대가를 안내 문구·남는 경로 표가 정확히 드러내지 못한 점이다.
