## MQ-C1 업로드 파일 크기 상한 (2a-05 5MB vs TR-SEC-04 10MB)
- [사실] 2a-05 SPEC 5.9(309행)는 파일당 **5MB**(L3 제안), TRD TR-SEC-04는 **10MB·40MP**. 두 값이 다르다.
- [사실] M2c는 원본을 보관하지 않고 재인코딩한다(SPEC 2.6) → 입력 크기는 변환 중 메모리에만 영향.
- [추정] 최근 휴대폰 12MP JPEG는 3~6MB, 고화소(48MP 모드)·PNG 스크린샷은 10MB 안팎.

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 10MB · 40MP (TR-SEC-04 그대로). 문서·탭 한도는 변환 결과 바이트로 | 폰 사진을 그대로 넣을 수 있음. 변환 중 메모리 순간 사용 ↑(디코드 전 헤더 검사로 폭탄은 막음) |
| B | 5MB (2a-05) · 40MP | 큰 폰 사진이 실패 → "줄여서 다시"가 사용자 몫. TRD보다 엄격 |
| C | 20MB · 40MP | TRD 개정 필요. 이득 적음 |

## MQ-C2 이미지 보관 방식 (서버 0 전제)
- [사실] 2a-05 5.9: 탭 메모리 · "새로고침하면 다시 골라야" 캡션. Opus r2 174행: IndexedDB가 백엔드 없는 다음 단계.

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 탭 메모리(2a-05 그대로). 잃은 이미지 = 자체 그래픽 + 안내 | 구현 작음 · 공용 PC에 사진이 남지 않음. 새로고침마다 다시 골라야 |
| B | IndexedDB(프로젝트별 · 문서가 참조하는 id만 · 편집기 밖에서 지우기 버튼) | 새로고침 생존. 저장소 할당량·브라우저 정리(eviction)·공용 기기 개인정보·삭제 UI 추가 → **+0.5~1주 [추정]**, 보관소 테스트 증가 |
| C | A로 시작, 메모리 저장소(projectRepository) 교체 때(백엔드 ADR) 함께 | 결정 미루기 — B 수요가 생기면 재론 |

## MQ-C3 정적 HTML 크기 (이미지 동봉 뒤)
- [사실] 폰트만으로 HTML ≈ 0.72MB(Pretendard 2굵기 538KB × base64 1.33 — SPEC-MOTION-FONT 299-300행). [추정] 이미지 12장 최대면 HTML 4~5MB.
- [사실] 단일 파일에서 `srcset`은 크기만 늘린다 → SPEC 5.2에서 넣지 않기로 결정(MQ 아님).

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 차단 없음 · 결과 화면에 크기 표시 · 3MB 넘으면 안내 한 줄 | 사용자가 판단. 큰 파일이 나올 수 있음(zip은 M4) |
| B | 상한(예 5MB) 초과 시 내보내기 차단 | 확실하지만 이미지를 빼라는 요구 = 흐름 끊김 |
| C | 상한 초과 시 이미지 동봉 폭을 한 단계 자동 낮춤(1920→1280 …) | 크기 맞춤 자동. 화질이 말없이 바뀜 · 결정성 규칙 추가 |

## MQ-C4 원본 비율 메타의 위치 (MQ-B3 이월)
- [사실] `ImageSlotValue`에 크기 없음(`pageDoc.ts:51-59`) · `validatePageDoc`는 정해진 키만 허용(strict record).

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 보관소 항목 + 렌더 메시지(`images` 값 = `{blob,width,height}`). 문서 계약 변경 0 | 엔진·저장 문서 그대로. 이미지가 사라지면 메타도 사라짐(어차피 쓸 데 없음) |
| B | `ImageSlotValue`에 선택 필드 `width`·`height` 추가 | 이미지 없이도 칸 비율 유지 가능 · **엔진 계약 변경**(검증·마이그레이션·스냅샷 호환·테스트 다수) · 사용자 문서에 이미지 관련 숫자 저장 |
