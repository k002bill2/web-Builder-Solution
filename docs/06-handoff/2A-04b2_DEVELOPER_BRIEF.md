## 1. 범위 (2a-04b의 프로필 화면 쪽 — 보드·저장소는 b1에서 끝남)
1. **배선**: deferred 프로필 래퍼·`ProfileRepositoryContext`·`AppProviders`를 `ProfileReadRepository` → `ProfileRepository`로 넓힌다(`getAdjustmentRange`·`saveAdjustments`·`revertTo` 위임). 공통 증가는 P-B2 목록만, 실측 보고.
2. **조정 컨트롤(3.4)**: 밀도·대비·모션·사이트 목적 4개 라디오 그룹(`SegmentedControl`). `SegmentedControl` 확장 1개 = 옵션별 `disabled` + 그룹 설명 캡션(`aria-describedby`, "촘촘: 이 테마에서 쓸 수 없음"), 비활성 옵션 roving 건너뜀. 모션 L3 옵션 없음 + 캡션 "높음(L3)은 생성 상한 밖이라 고를 수 없습니다". 범위는 `getAdjustmentRange`.
3. **저장 흐름**: P-S10 "저장하지 않은 조정 N개" + "조정 저장 (vN)"·"조정 취소" → P-S11 저장 중(`aria-busy`, 연타 1회)·저장됨("vN로 저장했습니다", 프로필 알림)·실패(`role=alert`, 조정 유지, 다시 시도) → P-S12 `STALE_PROFILE`(최신 반영 + 입력 유지 + 문장). 응답 실패 뒤 같은 인자 재시도는 b1 멱등 키로 같은 결과 — 화면은 "저장됨"으로 처리(가짜 STALE 문장 0).
4. **적용된 값 표시**: 값 목록·팔레트는 `effectiveProfile(base, adjustments)`. 조정된 값은 캡션 "조정됨 · 보드 값 L2"(5.4). 밀도 촘촘 = sectionGap 96 → 72.
5. **대비 보정(3.3)**: "보정값 쓰기"(Q6) → 저장 안 된 조정 `corrections`에 추가 → 저장하면 적용된 팔레트 = 보정값, 해당 검사 "통과". 충돌(P-S15, ref-b ink)은 버튼 없음 + 대체안 + "비교 보드에서 카드 바꾸기"(기존). 대비 "강화"면 목표 7.0 · 제안값 = 3.3 강화 열.
6. **P-S13**: 이어받은 값이 범위 밖이면 해당 그룹에 `Callout tone=cautionary` + "맞추기"(→ 허용 값으로 저장 안 된 조정). 메모리 구현에 좁은 `range` 주입으로 테스트.
7. **이전 버전 보기(P-S07)**: 조정 컨트롤 `aria-disabled` + 이유(기존 P-AC-08 유지). 되돌리기는 기존 경로 유지.

## 2. 번들 (ADR-004, 예산 상수 변경 금지)
- `/profile`이 진입 때 `getAdjustmentRange`를 **자동** 호출하면 `memoryProfileAdjust`(+revertIn, 약 2.4KB)를 스크립트 `/profile` 시나리오 **자동**으로 옮긴다(Q-F4-1 규칙). 추정 ≈ 121KB. 되돌리기 청크 분리(Q-F3-2)는 이 결과로 판단해 REPORT에 적는다.
- **`/compare`는 늘지 않게**: 현재 99.48 / 124.43(여유 0.52 / 0.57). 요약 바 개수(Q7)는 인라인 한 줄. 공통 증가(P-B2 배선)로 `/compare`·`/catalog`가 줄면 단계별 실측. **어느 시나리오든 여유 < 0.3이면 예산 변경 없이 멈추고 근거 커밋**.
- `SegmentedControl` 확장은 카탈로그·보드와 공유 청크가 될 수 있다(P-B7) → `/catalog`(여유 0.98)·`/compare` 재측정.
- 새 의존성·아이콘 파일 0, `import type` 필수(P-B5).
