## 1. 범위
### A. 프로젝트 페이지(2a-04) — 목업 ↔ SPEC r6 ↔ 현재 구현(main) 3자 대조
1. 127.0.0.1에서 현재 앱(`app/`, main 기준)을 띄워 `/profile`의 상태별 화면을 1280·1024·768·390에서 캡처: 확정 프로필 없음(빈 상태)·확정 직후·이전 버전 보기·저장 실패 등 재현 가능한 것. 보드에서 확정하는 흐름으로 상태를 만든다.
2. 목업 2a-04와 비교해 차이를 분류: **(a) b2 범위에서 해결 예정**(브리프 1절과 대조) / **(b) 2a-04c 범위** / **(c) SPEC에 없는 새 차이** / **(d) 의도된 차이**(SPEC·ADR 근거 있음 — 근거 절 번호).
3. (c)는 기능 → 사용성·접근성 → 일관성 → 목업 순(ADR-003)으로 채택 여부를 제안.
4. IA 확인: 헤더 "프로젝트"가 프로필 한 장으로 가는 것이 맞는지(목업에 프로젝트 목록 화면이 있는지 확인). 없으면 설계 질문으로.

### B. 편집 페이지(2a-05·2a-07) — 구현 전 디자인 준비도 검토
1. 목업 편집기 두 화면을 v2 SPEC 규칙으로 점검: 토큰·대비(특히 품질 게이트 상태 점 = `status-*-text` 대상, v2 SPEC 3.4·584행), 헤더 52px 일관성(C-06), 포커스·키보드(섹션 순서 바꾸기의 키보드 대안), 390 폭 조작 크기, 가로 넘침.
2. 목업에 **없는 상태·흐름** 목록: 자동 저장 실패·오프라인, 품질 게이트 차단·경고 상세, "검사 후 발행" 확인·실패, 스냅샷 목록·복원, 미리보기 링크 만료, 섹션 추가·삭제 되돌리기, 빈 섹션·긴 문구·글자 수 초과, 권한(viewer) 등 — 각 항목에 우선순위(P0/P1/P2).
3. 2a-05 설계서(SPEC)를 쓸 때 먼저 결정할 **설계 질문** 목록(번호, 추천안 표시). SPEC 자체는 쓰지 않는다.
