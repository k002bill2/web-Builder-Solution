## MQ-M2B3-1 등장 모션 정책 (SPEC 1절)
1. **★A 첫 화면 3섹션만 1회 등장** — hero + 뒤 본문 2개. L1 = 투명도만, L2 = 투명도 + 짧은 이동·순차(≤3단)·hero 이미지 약한 확대. 내보낸 정적 HTML에서만 재생(최대 0.96초), 캔버스·PNG·감소 설정은 항상 최종 상태.
2. B 등장 0 — L1·L2 = 메뉴 시트 열림만. 첫 그리기도 항상 최종이지만 L1과 L2가 사실상 같아진다(레벨 선택이 의미를 잃음).
3. C A + CSS 스크롤 연동(`animation-timeline: view()`)으로 아래 섹션도 등장 — 스크롤 연동은 MQ-B6 결정("CSS만")에 맞지만, 타임라인이 비활성일 때(캡처·짧은 문서) 출발 상태로 남을 위험이 있어 비추천 [추정].
- 추천 근거: 스크립트 0으로 "고른 레벨이 실제로 보이는" 최소안. 사용자가 보지 못하는 화면 밖 시간 기반 등장은 넣지 않는다.

## MQ-M2B3-2 서브셋 문자 범위 (SPEC 2.3)
1. **★A KS X 1001 한글 2,350자 + 기본 라틴·숫자 + 고정 기호(약 224자)** — 굵기당 Pretendard 267~271KB [사실, 저장소 파일] · Noto Sans KR 약 250~300KB · Noto Serif KR 약 330~450KB [추정]. 목록 밖 음절은 시스템 글꼴로 글자 단위 대체(□ 0, 모양만 섞임).
2. B 완성형 11,172자 — 굵기당 약 0.8~1.2MB [추정]. 단일 정적 HTML이 base64로 2~3MB대 [추정].
3. C 사이트 글자만 동적 서브셋 — 수십 KB [추정]이지만 내보내기 때 서브셋 도구(새 의존성·런타임)가 필요 → M4 이후 후보.

## MQ-M2B3-3 정적 HTML의 폰트 탑재 (SPEC 2.4 · 코드 제약: 생성기가 `data:` 밖 `url()`을 거부)
1. **★A `data:` base64 인라인** — 단일 파일·외부 요청 0 유지. 파일 크기 woff2 × 약 1.33(Pretendard 사이트 약 0.72MB [추정]).
2. B 폰트 미탑재 — 정적 HTML은 시스템 글꼴. 크기 최소지만 미리보기·PNG와 글자 모양이 달라진다(K-AC "같은 결과" 원칙 위반).
3. C 폴더/zip 내보내기로 바꿔 woff2·OFL.txt를 별도 파일로 — 내보내기 형식 변경이라 M4(React zip) 범위.

## MQ-M2B3-4 Pretendard 원본 사용 방식 (SPEC 2.1 · RFN)
1. **★A 업스트림 공식 `woff2-subset` 무수정 사용** — 저작권자가 배포한 서브셋 = Original Version이라 이름 `Pretendard` 유지 가능. 저장소에 이미 있는 Regular·Bold 2파일 재사용(새 바이너리 0). 단 이 파일은 npm 패키지 복사본이라 공식 릴리스 ZIP과 sha256 대조가 선행 [확인 필요].
2. B Noto와 같이 직접 서브셋 + 새 이름(`Kit Sans P` 등) — 규칙이 하나로 통일되지만 새 바이너리 2개 추가·이름 교체 작업, 크기 이득은 작다 [추정 — 한글 글리프가 크기 대부분].
