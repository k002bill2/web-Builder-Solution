## 1. 목적
사용자가 저장한 레퍼런스 2~6개를 항목별로 비교하고, 항목마다 원하는 요소를 골라 **디자인 프로필 초안**을 만드는 화면을 설계한다. 이 화면은 "레퍼런스 탐색"과 "프로필 확정·생성"을 잇는 핵심 결정 지점이다.

## 2. 입력
1. PRD `docs/02-prd/PRD.md` — FR-CMP-01~04, FR-SEL-01·02·06, FR-PRF-01~04, 원칙(권리 경계·결정적 생성·품질 게이트)
2. TRD `docs/03-trd/TRD.md` — 4.3 DesignProfile, 4.4 SectionDefinition, 7절 조합 규칙 R-01~R-15, 5절 API(compare, compare-boards picks, profiles)
3. 목업 `design/claude-design-handoff/project/Design Studio Mockups.dc.html` **184~229행**(1a-03) + 612~691행(`rowDefs`, `cmpCols`, `draft`) — 구조·위계 참고
4. 현재 구현: `app/src` (카탈로그·상세·비교 트레이·저장 Context, DS 컴포넌트, 토큰), `dev/active/m1-ui-01-fix/REPORT.md`
5. ADR-002(브랜드), ADR-003, ADR-004

## 3. 설계해야 할 것 (산출물: `docs/design/1a-03/SPEC.md`)
1. **사용자 흐름** — 진입 경로(트레이 "비교 보드 열기", GNB "비교 보드", 상세의 비교 추가), 이탈·복귀, 프로필 확정 후 다음 단계(1a-04)로의 연결
2. **정보 구조** — 비교 항목 행(FR-CMP-02의 10개 항목 + 목업의 카드 스타일·Footer 포함 여부 결정), 열(레퍼런스), 초안 패널의 구성
3. **요소 선택 규칙** — 항목당 1개 선택, 선택 해제, 서로 다른 레퍼런스에서 고른 요소의 조합 가능 여부(TRD R-01~R-15 중 비교 단계에서 미리 경고할 것), 비교 불가 항목(목업 `picked=-2` 팔레트처럼 요소 단위 선택이 아닌 것) 처리, 사용자 지정 색·폰트 입력의 위치
4. **상태** — 빈 보드(0개), 1개만(비교 불가 안내), 2~6개, 6개 초과 시도, 레퍼런스가 회수됨(라이선스 변경), 선택 충돌·대비 경고(목업 Callout), 초안 저장 전/저장됨, 로딩·오류
5. **반응형** — 1280·768·390에서의 비교 표 처리(가로 스크롤 vs 카드 전환 vs 항목 아코디언) — 정보 손실 없이
6. **접근성** — 비교 표의 표 의미 구조(행/열 헤더), 키보드로 "이 요소 선택", 선택 상태 알림(`aria-pressed`/live region), 색만으로 선택을 표시하지 않기
7. **컴포넌트** — 기존 DS 재사용 목록, 새로 필요한 컴포넌트(예: ComparisonTable, PickCell, DraftPanel)의 props·상태·토큰 사용
8. **데이터 계약 초안** — 비교 행 정의, picks 구조, 프로필 초안 → DesignProfile 매핑(TRD 4.3), 필요한 저장소 메서드
9. **수용 기준** — Developer가 테스트로 옮길 수 있는 Given/When/Then 목록(10~20개)
10. **목업과 다르게 설계한 부분** — 항목별 한 줄 사유(ADR-003)
