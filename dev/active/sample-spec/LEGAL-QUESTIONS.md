# 외부 URL 디자인 특징 추출 — 법무 자문 질문서

Jarvis 검토용 초안 · 외부 전달 전 영환님 승인 필요
기준: 2026-10-25 KST / 한국법 중심, 미국 제공은 질문 5에서 별도 검토 요청

## 배경
상업 서비스의 새 시안 출발점으로, 사용자가 입력한 단일 URL에서 색 팔레트 값·글꼴 계열 이름·정규화한 간격 범주·통상적 섹션 구조 태그만 추출하려고 합니다. 사용자 PC의 로컬 CLI로 실행하며(정적 fetch 우선·JS 끔), 허용 목록 도메인만 대상으로 합니다. 원문·이미지·로고·폰트 파일·원사이트 스크린샷은 저장·재배포하지 않는 설계입니다. 아직 경로 B 코드는 없으며, 비저장·폐기 등은 구현 검증 전 계획입니다. 원문을 처리 중 일시적으로 읽는 행위와 후속 시안 생성을 함께 검토해 주십시오. Newton의 리스크 등급 ‘중간’은 조사자의 정성 판단이지 법률 판단이 아니며, 법무 확인 전 공개하지 않습니다.

## 질문 5개

### 1. 일시적 복제와 상업 이용의 법적 근거
질문: 원문을 일시적으로 읽고 속성만 남기는 위 방식이 저작권법 제35조의2의 필요 범위에 해당합니까? 아니라면 제35조의5 공정이용 검토와 권리자 허락 중 어느 경로가 필요합니까?
왜 묻는지: 영구 저장하지 않더라도 일시적 복제와 후속 이용의 적법성이 해결된 것은 아닙니다.
관련 근거: [17] — 제35조의2·제35조의5 관련 원장 조사; 본 구현 적용은 [미확인]입니다.
바뀌는 결정: 이용 근거에 따라 대상별 허락 확보 여부와 처리 중 복제·폐기 정책을 정합니다.

### 2. 원사이트 약관의 적용과 허용 목록 승인 기준
질문: 원사이트 약관이 비회원 사용자와 서비스 운영자 각각에게 성립·편입되는 조건은 무엇이며, 로컬 CLI 방식에서도 적용됩니까? ‘접근 금지’와 ‘취득 정보 이용 금지’를 구분하여, 허용 목록 편입 시 필요한 근거를 약관상 허용·별도 허락·승인 불가 중 선택해 주십시오.
왜 묻는지: 공개 접근 가능 여부, 약관상 이용 허용 여부, 접근권한 제한은 구분해야 합니다.
관련 근거: [11][19][20] — 개별 약관과 접근·이용 제한 구분; 본 서비스에 대한 편입·적용은 [미확인]입니다.
바뀌는 결정: 도메인별 승인 증빙과 사용자·운영자 확인 절차, 별도 허락 필요 대상을 정합니다.

### 3. 추출 속성의 구체성과 원디자인 재현의 경계
질문: 팔레트·font-family·간격·섹션 순서의 결합이 창작적 배열·성과 사용 또는 출처 혼동 문제로 이어지지 않도록, 간격 범주·일반 섹션 태그만 남기고 동일 순서 복원을 금지하는 제한이 충분합니까? 부족하다면 추출·표시·후속 생성 중 어느 단계의 정보를 더 줄여야 합니까?
왜 묻는지: 개별 속성이 추상적이어도 결합 결과까지 보호 대상이 아니라고 단정할 수 없습니다.
관련 근거: [3][16] — 보호·적용 범위의 개별 검토가 필요하며, 법적 임계값·안전한 유사도 수치는 [미확인]입니다.
바뀌는 결정: 결과 스키마의 상세도와 원본 순서·특징적 조합의 표시 및 생성 제한을 확정합니다.

### 4. 서비스 전체 누적 추출과 데이터베이스·성과 보호
질문: 사용자별 단일 페이지 요청이 서비스 전체에서 누적될 때 저작권법 제93조 및 현행 부정경쟁방지법 제2조 제1호 (카)목·(파)목에 따른 제한이 필요합니까? 필요하다면 도메인별 누적량·동시 요청 통제와 중단 기준에 어떤 조건을 두어야 합니까?
왜 묻는지: 사용자별 1회 요청을 서비스 전체의 반복·체계적 수집과 동일하게 평가할 수는 없습니다.
관련 근거: [3][18][20] — 현행 (카)목은 데이터 부정사용, (파)목은 성과도용 일반 조항입니다. 누적 추출의 안전선은 [미확인]입니다.
바뀌는 결정: 로컬 CLI에서도 필요한 서비스 전체 누적 통제 방식과 승인·중단 기준을 설계합니다.

### 5. 미국 제공 시 웹사이트 외관 보호와 준거법
질문: 미국 대상 제공 시 웹사이트 외관을 product design·packaging 중 어느 쪽으로 검토해야 합니까, 아니면 개별 판단이 필요합니까? 비기능성·식별력·혼동 가능성과 준거법을 검토할 때, 미국 제공을 허용·조건부·불가 중 어떻게 판단하십니까?
왜 묻는지: 한국법 검토나 일반 상품 디자인 법리를 미국 웹사이트 외관에 그대로 적용할 수 없습니다.
관련 근거: [9] — Wal-Mart는 웹사이트 직접 판례가 아닙니다. 웹사이트 특화 직접 판례·관할별 차이·본 서비스 준거법은 [미확인]입니다.
바뀌는 결정: 미국 제공 여부와 별도 검토·표시·생성 제한 조건을 정합니다.

## 우리가 지금 계획한 안전장치

아래는 Newton 원장 ★ 조건을 로컬 CLI·허용 목록 결정에 맞춰 요약한 계획이며, 구현 완료 사항이 아닙니다.

1. 접근 자격: 소유·관리 또는 추출·상업 이용 허락이 있거나 약관상 허용 근거가 확인된 도메인만 승인하며, 사용자 체크를 허락의 대체물로 보지 않고 로그인·유료벽·CAPTCHA·접근거부·우회 필요 대상과 GDWEB·dbcut·갤러리 수집을 차단합니다.
2. 수집 범위: 명시 요청의 단일 페이지만 처리하고 순회·자동 재방문·백그라운드 갱신·공동 갤러리화를 금지하며, CLI의 식별 가능한 에이전트·robots 존중·도메인별 누적량 및 동시 요청 통제·차단 시 중단을 계획합니다(클릭 1회와 robots·리디렉션·외부 CSS 등의 총 HTTP 요청 수는 구분).
3. 저장 범위: 네 가지 추상 속성만 남기고 원문·자산·DOM 스냅샷·스크린샷·자산 URL을 결과·로그·캐시·외부 모델 입력에서 배제하며, 일시적 복제·폐기 시점을 정하고 폰트 자동 다운로드·핫링크·재호스팅 없이 별도 사용권을 확인한 폰트만 시안에 적용합니다.
4. 표시·생성: 원본 화면·정밀 DOM·좌표·동일 섹션 순서 복원 템플릿을 제공하지 않고 독립 레이아웃·새 문구·허가 자산을 사용하며, 특징적 조합·브랜드 혼동·‘복제/클론’·제휴 암시를 피하고 출처 링크를 허락으로 취급하지 않습니다.
5. 고지·중단: 사전 권한·약관 확인, 비보증 고지, 권리자 신고·삭제·향후 차단 절차를 마련하고 참고용·사용자 책임 문구만으로 면책된다고 표시하지 않으며, 보관·후속 생성 정책을 함께 법무 승인받습니다.

위 다섯 조건이 충분한지, 추가하거나 수정할 조건이 있는지 확인해 주십시오.

## 답변 요청 형식
질문별로 ‘결론(허용/조건부/불가) → 적용 조건·추가 확인 자료 → 근거 법령·판례’를 부탁드립니다. 국내·미국 판단과 적용 전제를 구분하고, 로컬 CLI·허용 목록 방식에서도 남는 운영자 책임을 표시해 주십시오.
