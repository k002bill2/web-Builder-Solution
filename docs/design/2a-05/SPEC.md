## 2. IA · 라우트 · 흐름

### 2.1 프로젝트 단위 (Q1=A · ADR-005 Q1 이행)
- **프로젝트 = 이름 + 프로필 계열 1개 + 편집 문서 1개(Q3) + 발행(2a-05b).** 프로필 계열과 1:1이다 — 프로필 버전은 프로젝트 안의 이력이고, 편집 문서는 그중 한 버전(과 한 안)을 가리키는 필드를 가진다(Q3).
- 프로젝트는 **보드 확정 때만** 생긴다(Q2 · ADR-005 Q1 "확정 시 프로젝트를 만들거나 골라"). 이름 입력 대화상자는 없다 — 기본 이름으로 만들고 나중에 바꾼다(Q2).
- 기본 이름 = `"<기준 레퍼런스 제목> 프로젝트"`(기준 = 프로필 `baseReferenceId`, 2a-04 A-Q1). 같은 이름이 있으면 `" 2"`, `" 3"`…을 붙인다(순수 함수 `defaultProjectName(title, existingNames)` — 목록에서 두 줄을 구별하기 위해서다).
- 보드는 사용자당 1개(ADR-005 Q1)라 **보드 `confirmed`가 가리키는 프로젝트 = "보드의 현재 프로젝트"**다. 다른 프로젝트를 고르는 방법은 "현재 프로젝트 새 버전 / 새 프로젝트" 두 가지뿐이다(12.2 — 임의의 다른 프로젝트로 확정하면 이어받기 기준(`confirmedBase`)이 없는 계열에 보드 값을 쓰게 되어 2a-04 6.1-3 규칙이 성립하지 않는다).

### 2.3 흐름

```
GNB "새 프로젝트" ──▶ /compare?new=1
                       ├─ 보드가 비었음 ──▶ 기존 보드 빈 상태("카탈로그에서 고르기")
                       └─ 선택 → 확정 대상 [새 프로젝트 | <현재 프로젝트> 새 버전 (vN)] (J-S10)
```
