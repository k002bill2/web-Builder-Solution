## 1. 고칠 것 (각 항목: SPEC 본문 수정 + 수용 기준 추가/수정 + 변경 이력 1줄)
1. **[high] 문서 최초 생성 경쟁·멱등** (8.3 `startDoc`, 517행 부근 · E-S03 · 2a-04c 경계 12.3)
   - `create` = 원자적 create-if-absent. 이미 문서가 있으면 덮지 않고 결정적 결과(예: `DOC_EXISTS` + 기존 문서 동봉 → 화면은 "이미 편집 중인 문서를 엽니다"). `restart`는 `expectedRevision` 필수, 불일치 `STALE_DOC`.
   - 멱등 키 = (projectId, mode, profileVersion, candidateId[, expectedRevision]) — 응답 실패 뒤 재시도는 이전 결과.
   - 판정 순서를 2a-04 10.0.2 Q-F2 선례 형식으로 적는다.
   - AC: 두 탭 동시 시작 → 문서 1개 · 한쪽은 기존 문서 열기 / 응답 실패 뒤 재시도 → 같은 문서 / `restart` 경합 → `STALE_DOC` + 편집 보존.
2. **[medium] 내보내기 전 스냅샷 책임 한 곳** (5.13, 347행 부근 ↔ 8.3 `requestExport`)
   - **저장소 한쪽**(`requestExport` 안, 같은 트랜잭션)으로 통일하고 5.13 화면 흐름 문장을 고친다. 같은 멱등 키 재호출은 스냅샷을 새로 만들지 않는다. `GENERATOR_UNAVAILABLE`(EQ-1 A)이면 **스냅샷을 만들지 않는다**(판정이 먼저) — 판정 순서에 명시.
   - AC: 연속 2회 내보내기(같은 revision) → 스냅샷 +1 이하 / 생성기 없음 → 스냅샷 0.
3. **[medium] 로컬 이미지 자원 한도·URL 수명** (5.9 · EQ-3 A · E-S20)
   - EQ-3 A(브라우저 안, 서버 전송 0, JPEG·PNG·WebP, 5MB, SVG 불가)는 유지. 추가: 문서당 이미지 **개수 상한**과 **총 바이트 상한**(값 제안 + 근거), 초과 시 문구.
   - 참조 수 기반 해제 규칙: 현재 문서·스냅샷·실행 취소 스택 어디에도 참조가 없을 때만 `revokeObjectURL`. 편집기를 떠날 때(언마운트) 전부 해제. 해제된 참조를 가진 스냅샷 복원·실행 취소 → 이미지 슬롯은 "이미지를 다시 골라 주세요" 빈 슬롯 상태(E-S20 변형)로, 대체텍스트는 보존.
   - 문서에는 object URL 문자열을 저장하지 않고 **로컬 참조 id**만(8.1 슬롯 값 `source` "로컬 이미지 참조"와 일치 — 이름 유지).
   - AC: 상한 초과 · 교체 반복 뒤 살아 있는 URL 수 = 참조 수 · 떠난 뒤 0 · 해제 뒤 복원.
4. **[medium] 공통 청크 순증가 ≤ 0 근거** (10절, 551~566행)
   - 기준을 **2a-04b2 실측**으로 바꾼다: `/compare` 99.60 / 124.60(여유 0.40 / 0.40), `/profile` 99.24 / 124.57(0.43), `/catalog` 99.37 / 101.75. (FIX-2A04b2 F2·F3가 진행 중이라 a1 착수 때 재실측 — 이 문장 유지)
   - 표 추가: 변경 항목(S-B1 각 줄 · S-B2 · S-B3 · S-B9)별 **추정 증감(L3) · 상쇄 항목 · 상쇄 추정량 · 순증감**. 추정 근거(예: 비슷한 과거 변경의 실측 — 2a-04b1 REPORT·b2 REPORT에서 찾아 인용)를 붙인다. `git show`/REPORT 인용만, 빌드는 하지 않는다.
