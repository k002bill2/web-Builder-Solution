### 0.2 이 문서에서 새로 정하는 공통 규칙 (본문 12변형에만)
1. **3폭 표**: m2a는 1280·390을 검수 폭으로 두고 768을 각 절 2에만 적었다. 이 문서는 모든 변형의 2 반응형을 **`lg` 이상(1280) · `md`~`lg`(768) · `md` 미만(390)** 세 줄로 적는다(M2B 3폭 검수).
2. **벽돌형 = CSS만**(B1-4 · B1-6): 다단(`columns`) 배치 + 항목 `break-inside: avoid`. JS 배치·높이 측정·`grid-template-rows: masonry`(실험 기능, 브라우저 대부분 미지원) 0. **읽기·Tab 순서 = 문서 순서**(다단은 문서 순서대로 위→아래, 왼쪽 단→오른쪽 단으로 흐른다 — WCAG 1.3.2 의미 있는 순서 · 2.4.3 초점 순서). 어느 항목이 어느 단에 놓이는지는 브라우저의 단 균형 계산이 정하므로 **명세·수용 기준은 단 배정을 고정하지 않는다**(KD-AC는 문서 순서·넘침·JS 0만 단언).
3. **갤러리 공통**(portfolio 3변형): 이미지 칸마다 `figure` 1개. 목록(`ul`)을 쓰지 않는다 — 기본 상태(이미지 없음)는 칸 전부가 `aria-hidden` 그라디언트라 목록이면 "빈 항목 3개"로 읽힌다. `figure`는 그라디언트일 때 `figure` 자체에 `aria-hidden="true"`, 실제 이미지일 때만 접근성 트리에 남는다(`img alt`). 캡션 슬롯이 없으므로 `figcaption` 0.
4. **카드 면 공통**: 카드 모양을 갖는 변형(services 3변형 · testimonials · pricing)은 m2a K1-4 3의 "카드 톤 × 섹션 톤" 표를 그대로 쓴다(`--kit-card-face` · 카드 글자 `ink` · 카드 안 `muted` 0).
5. **킷 고정 문구 목록**은 각 절 1에 전부 적고, 13절(MQ)에 모은다.

### 0.3 각 절의 짜임
변형마다: 슬롯(L1) · 가장 가까운 형제 · **1 구조 ~ 7 모션**(m2a K1과 같은 7항목 — 형제와 같으면 "= K1-x"로 적고 다른 점만) · **루브릭 표**(TR-POL-04, 8항 이상). 수용 기준(KD-AC) · 시각 QA · 예산 · MQ는 2~4절에 모은다.

루브릭 8항(Jarvis 최소 기준): ① 기능 적합 ② 정보 위계 ③ 3폭 반응형 ④ 접근성 ⑤ 토큰 준수 ⑥ 예산 감각 ⑦ 독자성(특정 사이트 재현 아님 · 외부 이미지·문구·수치 0) ⑧ 근거 3개(일반 웹 패턴 · WCAG · 내부 레퍼런스 태그 — 태그는 `app/src/fixtures/referenceDetails.ts`의 섹션 `name/variant`·`references.ts`의 `layoutType`, L1). 판정 = PASS / 주의.

### B1-2. `services/list` — 목록형
슬롯(L1): `heading`(40, 필수) · `intro`(long 160, 권장 100) · `items`(long 400, 필수, 기본 "서비스 1 · 서비스 2 · 서비스 3"). 형제: K1-4 `services/cards-3`(머리 같음 · 내용이 카드 대신 목록).

1. **구조**

  <div 래퍼 2단>

### B1-4. `services/cards-masonry` — 카드 벽돌형
슬롯(L1): `cards3` 스키마 그대로(K1-4와 같은 슬롯). 형제: K1-4 `services/cards-3`(마크업 같음 · 배치만 다름).

1. **구조** = K1-4 1(같은 `ul role=list > li` 3개, 번호 순서). 다른 점은 CSS만: 목록 루트에 `data-layout="masonry"`.
2. **반응형** (0.2-2 벽돌형 규칙)
   | 폭 | 배치 |
   |---|---|
   | `lg` 이상 (1280) | **2단 다단**(`columns: 2`, 단 사이 `s5`), 카드 `break-inside: avoid` · 카드 아래 간격 `s5` · 카드 높이 = 내용 높이(행 늘이기 0) |
   | `md`~`lg` (768) | 같음(2단) |
   | `md` 미만 (390) | 1열(다단 끔) — 카드 3과 같은 모양 |
   - **단 수 근거**: 카드가 3장뿐이라 3단이면 한 줄에 높이만 들쭉날쭉한 cards-3과 구분이 안 된다. 2단이면 한 단에 2장·다른 단에 1장이 놓여 **벽돌형(엇갈린 높이)**이 보인다. 어느 단에 몇 장이 가는지는 브라우저 균형 계산(0.2-2) — 순서는 늘 1→2→3.
   - 카드 높이를 맞추지 않는다(cards-3과의 차이 = 내용 길이가 그대로 드러남). 카드 3장 글이 같은 길이면 한 단에 2장, 다른 단 아래가 빈다 — 벽돌형의 정상 모양.
3. **토큰 대응** = K1-4 3.
4. **빈 슬롯·긴 글자** = K1-4 4. 다른 점: 빈 `cardNBody` 카드는 **이웃 높이에 맞춰 늘지 않는다**(제목만의 짧은 카드). 상한 글자 카드가 한 단을 길게 만들어도 넘침 0.
5. **이미지 슬롯** — 해당 없음. **6. 상호작용** — 없음.
7. **모션** — 정적. 모션 후보(상한 L2): 카드 등장(투명도). 위치 이동 모션은 단 균형이 바뀌는 폭 전환과 겹치므로 M2B-3에서 판단.
