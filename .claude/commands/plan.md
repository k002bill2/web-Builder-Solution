# Plan Command

코드 작성 전 구현 계획을 수립한다.

## 절차

1. **요구사항 재정리** — 무엇을 만들어야 하는지. 해당 브리프(`docs/06-handoff/*_BRIEF.md`)·SPEC(`docs/design/v2/SPEC.md`)의 수용 기준(AC ID)을 인용한다
2. **제약 확인** — CLAUDE.md Rules(디자인 원본 읽기 전용, 브랜드 격리, 하드코딩 금지, 권리 경계), ADR-003(기능·사용성 우선), ADR-004(번들 예산)
3. **리스크 식별** — 깨질 기존 테스트, 번들 예산 여유 KB, 가드 테스트
4. **단계별 계획** — 3~6단계, 단계마다 RED 테스트 이름과 완료 조건
5. **확인 대기** — 사용자 승인 전 코딩 시작 금지

## 사용 시점

- 새 화면·기능 시작
- 아키텍처 변경 (ADR이 필요한지 함께 판단)
- 무엇을 바꿀지 불확실한 리팩토링 (기준은 파일 수가 아니라 불확실성)

## 후처리

승인된 계획은 `dev/active/<task>/PROGRESS.md` 상단에 단계 표(단계·상태·커밋)로 저장한다. 기존 작업 폴더의 형식을 따른다.
