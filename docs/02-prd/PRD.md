## 1. 한 줄 정의

사용자가 업종·타깃·분위기·목적을 입력하면 **디자인 레퍼런스를 추천·비교하고, 원하는 요소를 골라 디자인 프로필로 확정한 뒤, React + Tailwind + Motion 홈페이지로 생성해 미리보기·내보내기·발행**까지 이어 주는 AOS 도메인.

```
좋은 사이트 찾기 → 왜 좋은지 분석 → 원하는 요소 선택 → 디자인 시스템으로 변환 → 실제 코드·홈페이지 생성
```

## 2. 배경과 문제

1. 레퍼런스 조사·정리에 시간이 오래 걸리고, 선택 근거가 주관적이다.
2. 레퍼런스가 실제 코드로 이어지지 않아 시안과 개발 결과 차이가 크다.
3. 브랜드별 디자인 시스템을 재사용하기 어렵다.
4. 경쟁 빌더(카페24 AI 빌더·Wix·Framer·식스샵)는 AI 생성은 빠르지만, 결과를 설명·재현하기 어렵고 한국 업종 필수 요소·발행 품질을 보장하지 않는다(GPT-Sol 교차검토, 외부 공유 전 재검증 필요).
5. GDWEB은 "좋은 사이트를 찾는" 탐색 패턴(업종·타깃·표현방법·콘셉트·컬러 필터, 유사작 추천)이 강하지만 제작으로 이어지지 않는다.

## 3. 차별점

1. **탐색 → 비교 → 선택 → 코드**가 한 흐름으로 이어진다.
2. **설명 가능한 결정적 생성**: 같은 프로필이면 같은 결과, 적용 규칙을 보여준다.
3. **구조/스타일 분리**: 섹션을 바꿔도 스타일 유지, 테마를 바꿔도 콘텐츠 유지.
4. **한국 업종 규칙과 발행 품질 게이트**: 사업자정보·개인정보 동의·접근성·SEO·성능.
5. **복구 가능성**: 프로필·프로젝트 버전, 롤백, 코드 내보내기.

## 4. 원칙 — 권리·복제 경계 (모든 기능에 적용)

1. 특정 사이트 전체 복제·"이 URL처럼 만들기" 기능은 제공하지 않는다.
2. 생성 결과물에는 **자체 제작 섹션과 사용 허가된 에셋만** 들어간다. 타 사이트 이미지·문구는 넣지 않는다.
3. GDWEB은 분류 어휘·탐색 패턴·심사 관점만 참고한다. 선정작 이미지·태그 할당 데이터는 수집·저장하지 않는다(robots `Disallow: /`, 이용약관 제13조).
4. 카탈로그의 레퍼런스는 출처별 `license_status`를 가진다. **MVP 카탈로그는 `internal`(우리 섹션 라이브러리로 만든 레퍼런스 사이트)과 `licensed`(권리자 허락분)만** 노출한다.
5. 외부 URL 스크린샷 수집(`external_observed`)은 MVP 제외. 도입하려면 robots·약관 확인, 법무 승인, 조직 비공개, 생성 입력 사용 금지 조건이 필요하다 ⚖️.

## 6. 핵심 사용자 시나리오

```
1. 업종·타깃·목적·분위기를 입력한다.
2. 시스템이 레퍼런스를 추천한다(추천 근거 표시).
3. 3개 레퍼런스를 저장하고 비교 보드에 올린다.
4. 비교 보드에서 Hero·카드·Footer·컬러·폰트·모션을 고른다.
5. 디자인 프로필을 확정한다(버전 저장).
6. 홈페이지 초안을 생성한다(3안 중 선택 가능).
7. Desktop/Tablet/Mobile 미리보기에서 섹션·문구를 수정한다.
8. 품질 검사를 통과한 뒤 코드(zip)로 내보내거나 서브도메인에 발행한다.
```
