## 0. 결론

1. **두 문서의 큰 방향은 합치한다.** MVP는 제3자 선정작을 보여주는 갤러리가 아니라, 자체 제작한 섹션·테마를 `업종 → 목적 → 무드 → 3안 비교 → 제한 편집 → 발행`으로 조립하는 제품이어야 한다. GDWEB 자동 수집·스크린샷 보관·레퍼런스 URL 모사는 제외하고, 규칙 기반 조립을 중심으로 둔다.
2. **다만 “고르는 방식”만으로는 차별화가 부족하다.** [사실] 카페24는 현재 업종 선택 후 AI가 홈페이지 전체를 구성하고, 대화로 분위기·텍스트·이미지·색상을 바꾸는 공식 AI 홈페이지 빌더를 운영한다. Wix Harmony, Framer Agents, 식스샵도 페이지·블록 생성과 후속 편집을 공식 제공한다. 따라서 차별점은 `선택 UX`가 아니라 **결정적 조립·국내 업종 규칙·접근성/SEO/성능 발행 게이트·구조/스타일 분리·되돌릴 수 있는 운영**의 묶음으로 다시 정의해야 한다.
3. **MVP 수량은 축소가 안전하다.** [추정] 8~10개 업종 × 4~6개 목적 × 8개 무드 × 3안과 16개 섹션 유형 × 2~4변형을 동시에 품질 보증하면 조합 검수량이 급증한다. 베타는 **핵심 업종 5개, 목적 3개, 무드 4개, 섹션 유형 12개 × 변형 2개**로 시작하고, 사용 성공률을 본 뒤 확대한다.
4. **수집 정책은 합치하지만 provenance 설계는 수정해야 한다.** 두 문서는 생산 스키마에서 원본 URL을 제거한다. 그러나 출처를 완전히 버리면 권리 검토·재현·삭제 요청 대응이 불가능하다. 생산 라이브러리에는 외부 URL을 넣지 않되, 접근 통제된 내부 검토 원장에 URL·관찰일·약관/robots 확인·추상화 메모·승인자를 보관하는 이중 구조가 필요하다.
5. **발행 제품의 운영 계약이 빠져 있다.** 초안/미리보기/발행/롤백, 버전 이력, 도메인·TLS 실패 복구, SEO, WCAG 2.2 AA, 반응형 회귀, 성능 예산, 문의 폼 개인정보·스팸 대응, 요금제·사용량·해지·데이터 내보내기를 PRD/TRD에 추가해야 한다.

## 1. 두 산출물 교차검토

### 1-1. 합의된 판단

| 주제 | Fable | Opus 5.5 | 판정 |
|---|---|---|---|
| 제품 형태 | 섹션 조립 + 토큰 스왑 | 규칙 기반 조립 + 스키마 제한 LLM | **합의** |
| GDWEB 활용 | 사람의 소수 페이지 관찰 후 추상 태깅 | 수동 큐레이션, 자동 수집 금지 | **합의** |
| 편집 자유도 | 섹션 단위, 픽셀 배치 제외 | 섹션 단위, 임의 CSS 제외 | **합의** |
| 프리뷰 | 자체 렌더만 사용 | 사용자 브랜드가 들어간 자체 프리뷰 | **합의** |
| 생성 AI | MVP OUT | JSON 스키마 채우기 보조 | **범위 조정 필요** |

### 1-2. 충돌과 결정안

1. **LLM 포함 여부**
   - Fable: AI 문구·이미지 생성은 MVP 이후.
   - Opus: LLM이 JSON 스키마 안에서 카피 초안·변형 순위를 보조.
   - **결정안 [추정]:** 공개 베타의 핵심 경로는 LLM 없이 결정적으로 완주한다. LLM 카피는 별도 플래그의 선택 기능으로만 두고, 실패·비용·허위 문구가 조립과 발행을 막지 않게 한다. 의료·금융 업종은 사용자 확인 전 발행 금지다.
2. **발행 범위**
   - Fable: MVP는 서브도메인, 커스텀 도메인은 MVP+1.
   - Opus: 커스텀 도메인 + TLS를 MVP 발행 계약에 포함.
   - **결정안 [추정]:** 첫 검증은 서브도메인 발행으로 제한한다. 다만 도메인·TLS 데이터 모델과 배포 추상화는 처음부터 둬야 한다. 유료 전환 시점에는 커스텀 도메인이 필수다.
3. **탐색의 대상**
   - Fable의 흐름은 자체 추상 프리뷰 3~6개, Opus는 3안 비교다.
   - **결정안:** 갤러리 탐색을 별도 제품으로 만들지 않는다. 입력 축을 선택하면 자체 렌더한 3안을 비교하고, 동일 업종/무드의 대체안을 요청하는 흐름으로 통일한다.
4. **패턴 수량**
   - Fable: 섹션 패턴 30~40종.
   - Opus: 16개 유형 × 2~4변형(32~64개).
   - **결정안 [추정]:** 베타는 12개 유형 × 2변형(24개)으로 제한한다. 각 변형이 5개 핵심 업종·3개 뷰포트에서 품질 게이트를 통과한 뒤 추가한다.
5. **표현방법 축**
   - Fable은 히어로 미디어 슬롯 속성, Opus는 조립층의 비주얼 소재와 모션 수준으로 다룬다.
   - **결정안:** `media_kind(photo|video|illustration|3d|type)`는 섹션 슬롯 속성, `motion_level(L0~L2)`은 테마/페이지 정책으로 분리한다. 사용자 선택층에는 기본적으로 노출하지 않는다.

### 1-3. 수집·권리 정책 보정

- **[사실]** 두 문서 모두 GDWEB robots와 약관을 근거로 자동 수집을 배제했고, 브리프의 읽기 전용·대량 크롤링 금지와 일치한다.
- **[추정]** “수동 큐레이션만”도 무제한 허용을 뜻하지 않는다. 승인된 관찰 범위, 요청 간격, 보관 금지 항목, 중단 조건을 운영 절차로 고정해야 한다.
- **[보정]** 생산 `pattern` 객체에는 외부 URL·캡처를 넣지 않는다. 별도 `research_ledger`에는 `source_url, observed_at, terms_checked_at, robots_checked_at, abstraction_note, reviewer, disposition`을 저장하고 접근을 제한한다. 캡처·원본 에셋은 저장하지 않는다.
- **[확인 필요]** 제휴 허락을 받더라도 작품 이미지·메타데이터·태그를 어디까지 저장·학습·노출할 수 있는지는 계약 문구별 법무 검토가 필요하다.

## 3. 빠진 PRD 요구사항 후보

### 3-1. 제작·운영

1. **PRD-E-01 버전 이력:** 자동저장, 명시적 스냅샷, 미리보기, 마지막 발행본 복원, 발행본 간 변경 비교를 제공한다.
2. **PRD-E-02 발행 상태:** `draft → preview → publishing → published | failed → rolled_back` 상태와 실패 원인을 사용자에게 표시한다.
3. **PRD-E-03 소유권·이식성:** 사이트 콘텐츠·에셋·도메인의 소유 주체, 내보내기 형식, 구독 해지 후 보존·삭제 기간을 명시한다.
4. **PRD-E-04 관리자:** 섹션/테마 승인·비활성화·버전 승격·긴급 회수와 영향 사이트 목록을 제공한다.
5. **PRD-E-05 문의 운영:** 문의 수신처 검증, 스팸함, 재전송, 보존 기간, 개인정보 동의 문구를 제공한다.

### 3-2. SEO·접근성·반응형

1. **PRD-E-06 SEO:** 페이지별 title/description, canonical, robots, sitemap, Open Graph, 301 redirect를 설정·미리보기한다. Google은 canonical·sitemap을 공식 안내한다: https://developers.google.com/search/docs/fundamentals/seo-starter-guide
2. **PRD-E-07 접근성:** 발행 기준은 WCAG 2.2 AA로 하고, 키보드 탐색·포커스·대비·대체텍스트·폼 오류·모션 감소를 자동+수동으로 검사한다: https://www.w3.org/TR/WCAG22/
3. **PRD-E-08 반응형:** desktop/tablet/mobile 3개 기준 뷰와 콘텐츠 오버플로·잘림 경고를 제공한다. 자동 변환 후 사용자가 기기별 결과를 승인한다.
4. **PRD-E-09 성능:** 이미지 크기·폰트·스크립트 예산과 Core Web Vitals 목표를 발행 게이트에 포함한다. 초기 목표는 p75 기준 LCP ≤2.5s, INP ≤200ms, CLS ≤0.1이다: https://web.dev/articles/defining-core-web-vitals-thresholds
5. **PRD-E-10 미리보기 보안:** 미발행 사이트는 추측 어려운 URL과 선택적 암호/인증을 지원하고 검색 색인을 막는다.

### 3-3. 요금·사용량

1. **PRD-E-11 요금 단위:** 사이트 수, 발행 도메인 수, 저장공간, 트래픽, 문의 건수, 협업 좌석, AI 크레딧 중 어떤 항목을 제한·과금할지 명시한다.
2. **PRD-E-12 한도 UX:** 현재 사용량, 80/100% 경고, 초과 시 동작(차단/유예/종량), 업그레이드 전 예상 금액을 보여준다.
3. **PRD-E-13 결제 상태:** 체험, 활성, 결제실패 유예, 일시정지, 해지 예약, 해지 완료 상태와 사이트 공개 여부를 정의한다.
4. **PRD-E-14 가격 표시:** 부가세, 월/연 결제, 할인 종료일, 환불·도메인 비용을 결제 전에 분리 표시한다.

## 4. 빠진 TRD 요구사항 후보

### 4-1. 데이터·보안

1. **TRD-E-01 멀티테넌시:** 모든 프로젝트·에셋·배포·문의 데이터에 tenant/site 경계를 강제하고, 권한 없는 교차 접근 테스트를 둔다.
2. **TRD-E-02 권한·감사:** owner/editor/publisher 역할을 분리하고, 테마 변경·발행·도메인·결제·복원의 감사 로그를 남긴다.
3. **TRD-E-03 업로드:** 파일 형식·크기·픽셀 수 허용목록, 악성 파일 검사, EXIF 제거, 안전한 파일명, 비공개 원본과 변환본 분리를 적용한다.
4. **TRD-E-04 폼:** CSRF·rate limit·honeypot/챌린지·이메일 검증·비밀정보 마스킹·보존/삭제 작업을 구현한다.
5. **TRD-E-05 비밀·도메인:** DNS/호스팅 토큰은 사이트 데이터와 분리 암호화하고 최소 권한·회전·감사 정책을 둔다.

### 4-2. 발행·복구·관측

1. **TRD-E-06 불변 배포:** 빌드 산출물을 content hash로 버전화하고, 성공한 산출물만 원자적으로 production alias에 승격한다.
2. **TRD-E-07 롤백:** 이전 성공 배포로 즉시 되돌리고 도메인·환경설정 차이를 경고한다. Cloudflare Pages와 Vercel 모두 성공 배포 롤백을 공식 지원한다: https://developers.cloudflare.com/pages/configuration/rollbacks/ · https://vercel.com/docs/instant-rollback
3. **TRD-E-08 도메인 상태기계:** DNS 검증, CAA, 인증서 발급/갱신, 전파 대기, 실패 재시도, 도메인 분리 상태를 모델링한다: https://developers.cloudflare.com/pages/configuration/custom-domains/
4. **TRD-E-09 품질 게이트:** 스키마, 링크, 접근성 자동 검사, 3개 viewport visual regression, 성능 예산, 보안 헤더를 통과한 빌드만 발행한다.
5. **TRD-E-10 관측성:** 빌드·발행 성공률, 발행 시간, 폼 전달 실패, 인증서 만료, 4xx/5xx, Core Web Vitals를 사이트·릴리스별로 기록하고 경보한다.

### 4-3. 디자인 시스템·검증

1. **TRD-E-11 조합 커버리지:** 지원 업종×목적×무드×viewport 조합 목록을 버전화하고, 지원하지 않는 조합은 생성 전에 차단한다.
2. **TRD-E-12 섹션 호환성:** 섹션 스키마 버전, migration, deprecation, 사용 중 사이트 영향 분석을 구현한다.
3. **TRD-E-13 접근성 경계:** 자동 검사는 대체텍스트 존재·대비·ARIA·focus 순서를 검사하되 WCAG 적합 전체를 보증한다고 표시하지 않는다. 사람 검수 체크를 별도로 둔다.
4. **TRD-E-14 provenance 분리:** 생산 객체와 접근 통제된 조사 원장을 분리하고, 외부 이미지·HTML은 어느 저장소에도 보관하지 않는다.
5. **TRD-E-15 결정 재현:** 같은 입력·라이브러리 버전·seed는 같은 3안을 생성하고, 생성 로그에 규칙·버전·제외 이유를 남긴다.

## 5. 사실 / 추정 / 확인 필요

### 사실

- 두 문서는 규칙 기반 섹션 조립, 자체 프리뷰, 제한 편집, GDWEB 자동 수집 금지에 합의한다.
- 카페24는 현재 업종 기반 AI 전체 홈페이지 구성과 대화형 분위기·텍스트·이미지·색상 수정을 공식 제공한다.
- Wix는 2,000+ 템플릿과 AI/드래그앤드롭 편집, Framer는 AI agents와 발행 전 품질 검토, 식스샵은 AI 페이지/블록 및 여러 입력 변환을 공식 안내한다.
- WCAG 2.2는 W3C Recommendation이고, Google은 p75 기준 LCP·INP·CLS의 good threshold를 공개한다.

### 추정

- 베타 범위를 5업종·3목적·4무드·24개 섹션 변형으로 줄이면 품질 검수와 학습 속도가 개선된다.
- 이 제품의 방어 가능한 차별점은 생성 자체보다 결정성·업종 규칙·품질 게이트·복구성의 결합이다.
- 커스텀 도메인은 첫 사용성 검증보다 유료 전환 검증에 가깝다.

### 확인 필요

- 아임웹 공식 FAQ 2건의 현재 본문(템플릿 초기화, AI 생성 제한 수치)
- 식스샵 편집기의 정확한 drag/drop 및 breakpoint 동작 계약
- Wix Harmony 발표일과 지역별 가격 표시 기준
- Framer Marketplace 카테고리 수·유료 템플릿 가격 분포
- 법무 승인된 큐레이션 관찰 범위와 research ledger 보존 기간

## 6. PRD/TRD로 넘길 최종 결정 요약

1. MVP 탐색 대상은 GDWEB 작품이 아니라 **자체 섹션·테마로 렌더한 3안**이다.
2. MVP 생성은 **결정적 규칙 기반**이며 LLM 카피는 선택형 실험으로 격리한다.
3. GDWEB 자동 수집·캡처 저장·레퍼런스 URL 모사는 금지하고, 조사 provenance는 접근 통제 원장에만 둔다.
4. 베타는 **5업종 × 3목적 × 4무드, 12섹션 유형 × 2변형**으로 시작한다.
5. 차별점은 `선택 UX` 단독이 아니라 **국내 업종 규칙 + 구조/스타일 분리 + 접근성/SEO/성능 게이트 + 버전/롤백/내보내기**로 정의한다.
