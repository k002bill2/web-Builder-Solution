## 1. 결론 / 핵심 발견

★ 단일 추천: DigitalOcean Basic Regular 1 GiB / 1 vCPU, SGP1(싱가포르) + 일일 Percentage-based Backups.
월 기본 합계 $7.80 = VPS $6.00 + 포함 IPv4 $0 + 일일 백업 $1.80. 세금·도메인 등록비·전송 초과·추가 스냅샷·별도 오프사이트 백업은 제외합니다. 이는 사용량 무관 $10 하드캡 보장이 아니라 포함량 안의 월 기본료입니다.[1][3]
약관 판정: 허용(합법적 고객 정적 콘텐츠 호스팅, 고객에게 DO 계정/API 접근권을 넘기지 않는 본 PoC 기준). TOS §4.4가 resale, own products/services, public-facing websites 및 End Users를 직접 인정하며 §4.5–4.6에서 콘텐츠·고객 행위·운영·백업 책임을 사업자에게 둡니다.[2]

선정 이유 3줄:
- 고객 사이트 호스팅과 End Users의 명시 근거가 있고, 별도 리셀러 계약의 존재만으로 허용을 추정할 필요가 없습니다.[2]
- IPv4와 일일 백업을 포함한 기본료가 $10 아래이며 7개 일일 복구본 보존이 명확합니다.[1][3]
- 싱가포르 Basic 제공과 무료 L3/L4 방어가 확인됩니다. 서울·도쿄는 없고 L7 HTTP flood·단일 노드 장애를 해결해 주지는 않습니다.[20][21]

핵심 발견:
1. 사실/판단 분리: VPS 약관상 호스팅은 가능하지만, Caddy + 발행 API + SQLite만 설치하면 rollback·24h preview·tenant 분리가 자동 보장되는 것은 아닙니다. PoC 기술 적합성은 조건부 추정이며 실행 판정은 [미확인]입니다.
2. 사실: Let's Encrypt wildcard는 DNS-01이 필요합니다. 신규 인증서는 등록 도메인당 7일 50개, 동일 identifier 집합당 7일 5개 제한이며, ARI 갱신 등 예외가 있어 모든 갱신을 무조건 같은 제한에 넣지 않습니다.[10][11]
3. 판단: Cloudflare DNS-only는 자사 소유 발행 apex를 자사 계정에서 관리하고 DNS 접근권을 고객에게 판매하지 않는 좁은 모델로 한정하면 허용으로 해석 가능합니다. 다만 이 고객 호스팅 모델에 대한 명시적 DNS-only 계약 예외는 찾지 못했으므로 약관 판정은 모호(조건부 사용 가능 해석)로 남깁니다. VPS 허용 판정과 합쳐 전체 스택을 무조건 허용이라고 쓰지 않습니다.[14][27][28]

#### Cloudflare DNS-only 별도 판정

사실: authoritative DNS는 all plans에서 제공되며, DNS-only는 원본 IP를 응답하고 HTTP/HTTPS가 Cloudflare 네트워크를 경유하지 않습니다. 따라서 이 구성은 CF가 고객 HTML·asset을 서빙하는 Workers/프록시 모델과 다릅니다.[27][28]
사실: Self-Serve Agreement §2.2.1(a)는 여전히 “sell access to the Services to any third party, or sign up for the Services on behalf of a third party”를 제한합니다. DNS-only라고 이 일반조항이 없어지는 것은 아닙니다.[14]
판단: 우리 소유 apex의 DNS를 우리 계정으로 관리하며 DNS 서비스 접근권을 고객에게 제공/판매하지 않는 모델은 자사 DNS 사용으로 해석할 근거가 있습니다. 그러나 DNS-only 고객 사이트 SaaS를 명시 허용하는 조항/공식 답변은 [미확인]. 최종 분류는 모호이며 “문제 없음 확정”으로 ADR에 쓰면 안 됩니다. 도메인 소유 주체가 고객이거나 고객 도메인 대행 가입이면 재판정해야 합니다.
보안상 사실: DNS-only는 VPS 원본 IP가 공개되고 CF WAF·CDN·HTTP DDoS 보호가 적용되지 않습니다. 무료 DNS 보호와 HTTP 서비스 보호를 혼동하지 않습니다.[27]

### 2.7 Developer 전달용 PoC 검증 게이트 — 전부 추정/실행 미검증

1. 발행: ZIP을 격리된 임시 release에 검증·해제한 뒤 immutable release를 만들고 tenant별 active release 참조를 원자 전환하십시오. zip-slip, symlink, 압축폭탄, 확장자/MIME·용량·파일수, Host/slug/path 정규화를 점검하십시오. 고객 산출물을 서버 명령으로 실행하지 않습니다.
2. rollback: SQLite의 active-release와 서빙 경로의 단일 정본을 정하고 동시 발행·프로세스 재시작·실패중간 상태를 시험하십시오. symlink와 DB를 별도 갱신하면서 둘 다 원자적이라고 주장하지 마십시오.
3. preview: HTML뿐 아니라 CSS·폰트·이미지·HEAD·Range·304·오류경로 등 모든 요청에 동일한 tenant/release/expiry 검증을 앞단 적용하십시오. 정적 Caddy 경로·원본 IP·직접 release URL로 우회하면 실패입니다. `noindex`는 접근통제가 아닙니다. 만료 이후 서버의 새 요청 거부와 이미 다운로드한 파일/브라우저 캐시의 회수 불가능성을 구별하십시오.
4. 헤더: CSP·HSTS·nosniff·Referrer-Policy·X-Robots-Tag를 정상·redirect·error·preview·asset 경로에서 관측하십시오. preview는 no-store 등으로 캐시 재사용 요구를 명시하십시오. 헤더 설정만으로 만료 통제가 완성되지 않습니다.
5. 운영: 실제 restore 후 release·SQLite 정합성, Caddy TLS data·secrets 복구, 디스크·메모리·egress 경보, 업로드/미리보기 요청 제한, 패치·abuse 담당자·고객별 긴급 차단을 확인하십시오. Docker 이미지 build를 이 작은 VPS에서 반드시 수행해야 한다는 전제는 두지 않습니다.

이 조사는 codebase audit가 아니며 security-audit 가이드 모드로 판단 기준만 적용했습니다. 구매·배포·침투테스트·외부 서버 probing은 하지 않았습니다.

## 3. 출처 간 충돌 / 오독 방지

- Hetzner 상품표의 IPv4 포함 €5.99와 billing FAQ의 IPv4 별도 청구는 모순 아님: 상품 표시 합계와 invoice 리소스 분리입니다. 저가 플랜 `not available`은 주문가능성의 실제 제약이므로 싼 과거 가격만으로 추천하지 않습니다.[4][6]
- Vultr 전체 가격표에는 DB·VX1·Regular 등의 요금이 섞입니다. $18 DB 행을 최소 VPS 가격으로 쓰지 않고 Regular Performance의 $3.50/$5 행만 사용했습니다. 글로벌 표시료를 서울 실제 견적으로 확정하지 않았습니다.[24][25]
- Lightsail 가격표의 현행 IPv4 bundle은 0.5 GB $5, 1 GB $7인데 하단 예시에는 1 GB WordPress $5가 남아 있습니다. 현행 bundle 표를 우선하고 과거 예시 수치를 플랜 가격으로 쓰지 않습니다.[7]
- Lightsail99.99% 대99.5%, Hetzner 연 network99.9% 대 월 instance99.9%는 측정대상·배치가 다르므로 나란히 같은 지표로 순위화하지 않습니다.[5][29][39]
- 일반 TOS의 non-transferable/non-sublicensable 문구만 떼어 DO 고객 호스팅을 금지로 읽지 않습니다. §4.4의 End User·resale 허용 문맥을 함께 적용합니다. 반대로 Vultr/Linode의 End Users 문구만으로 resale 제한을 무효화하지 않습니다.[2][15][17]
- Cloudflare DNS-only가 기술적으로 HTTP를 처리하지 않는다는 사실과 계약상 모든 고객 대행 이용이 허용된다는 주장은 별개입니다.[14][27]
