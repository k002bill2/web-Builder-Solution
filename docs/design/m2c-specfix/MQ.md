## MQ-S1 잃은 이미지·새로고침 — 보관 방식을 다시 정할까 (B-M2C-03 · MQ-C2 재론)

### 사실
1. [사실 L1] 새로고침하면 **프로젝트·문서까지** 사라진다 — 프로젝트·문서 저장소가 모듈 수준 메모리다(`app/src/main.tsx` 28행 주석 "메모리 구현은 새로고침하면 비어 있다" · M2C-5 QA `shots/qb10-after-reload-1280.png` "프로젝트를 찾을 수 없습니다").
2. [사실 L1] 이미지 맵은 편집 틀의 React state다(`StudioLayout.tsx` 282~283행) — 편집기를 떠나면 이미지만 사라지고 문서는 남는다. 2a-05 E-S20이 이미 "잃은 이미지 = 편집기를 떠났다 돌아옴 · 스냅샷 복원 · 실행 취소"로 정의했고, 패널 안내도 "편집기를 나가거나 새로고침하면 다시 골라야 합니다"(`ImageSlotPanel.tsx` 44행).
3. [사실 L1] 그래서 QB-10의 "새로고침 → 잃은 이미지" 전제가 틀렸다 → **m2c SPEC r3에서 "앱 안 편집기 이탈·복귀"로 정정 완료**(9절 QB-10 · 5.2). 잃은 이미지 경로는 제품 흐름으로 도달 가능하다 [L1 코드 읽기 — 브라우저 미실측, IMPL-TODO T-5].
4. [사실 L1] 이미지만 IndexedDB에 두는 안(MQ-C2 B)은 **새로고침 생존 이득이 0**이다 — 새로고침하면 그 이미지를 쓸 프로젝트·문서가 함께 사라진다. 새로고침 생존은 문서 영속(백엔드 미정 ADR 영역)과 같이 가야 의미가 있다.

### 선택지
| 안 | 내용 | 얻는 것 | 잃는 것 · 비용 |
