## 2. 토큰 매핑

### 2.1 원칙
1. **이름은 우리 것, 값은 v2.** 현재 토큰 이름(`--label-*`·`--background-*`·`--surface-*`·`--fill-*`·`--line-*`·`--status-*`·`--shadow-*` 등)을 그대로 두고 값만 바꾼다. 이유: (a) 컴포넌트·페이지 코드와 Tailwind 유틸리티 문자열이 그대로여서 **JS 번들 증가 0**(5절), (b) 사용처 수백 줄을 고치지 않아도 되어 회귀 범위가 토큰 테스트로 좁혀진다.
2. v2 이름(`--muted`, `--caption`, `--foreground` …)은 **코드에 들이지 않는다.** 두 이름 체계가 섞이면 DS 일관성(3순위)이 깨진다. 출처는 토큰 파일 주석으로만 남긴다.
3. `apfs`·`APFS` 문자열은 **출처 경로 주석 줄에서만** 허용(ADR-002 수용 기준). v2 경로(`_ds/apfs-dashboard-ds-…`)에 들어 있으므로 브랜드 가드 marker를 고친다(6.3).
4. 브랜드 값(주 색·hover·pressed·container·accent·gradient·focus-ring)은 **`brand.css`에만**. 의미 토큰은 `--brand-*`를 참조한다(ADR-002).
5. 다크 선택자는 우리 것 `[data-theme="dark"]`를 유지한다(v2는 `.dark`). **`var()` 별칭은 다크 블록에도 같은 이름으로 재선언**한다(colors.css 160행 주석과 같은 이유).
6. 원본 CSS 번들을 앱에 넣지 않는다(ADR-006 결정 3). 파일 구조(`base·brand·colors·fonts·shape·spacing·typography.css`)는 유지.
7. v2에 없는 우리 토큰은 v2 중성 베이스 `rgb(31,54,40)`(라이트) · 흰색(다크) 알파로 **파생**하고 표에 "파생"이라 적는다.

**옵션 개수 표시 — 넣는다**(2순위 사용성: 0건 조합을 누르기 전에 알 수 있다)

| 항목 | 규칙 |
|---|---|
| 의미 | **"그 그룹만 빼고 나머지 필터를 모두 적용했을 때, 이 옵션을 가진 레퍼런스 수"**(분리형 facet count). 그룹 안은 OR(`anyOf`)이라 "현재 결과 중 이 옵션을 가진 수"로 세면 틀린다 — 예: 콘셉트 미니멀·따뜻한을 고른 상태에서 "대담한"의 수는 대담한을 **더 켰을 때 늘어날 수**여야 한다. 업종 칩(단일 선택)도 같은 규칙: 업종을 뺀 조건에서 업종별 수, "전체" = 업종을 뺀 조건의 결과 수 |
| 모집단 | 노출 레퍼런스(internal·licensed, FR-CAT-04 — 저장소 `list()`가 이미 거름). **`tab=saved`이면 저장한 레퍼런스로 한정**(목록과 개수가 같은 모집단을 보게). `tab=rec`은 목록이 없으므로 전체 기준 |
| 계산 위치 | **카탈로그 청크 안의 순수 함수**(예: `features/catalog/facetCounts.ts`). 저장소 인터페이스·`referenceRepository.ts`는 **바꾸지 않는다** — `main.tsx`가 정적 import해 진입 청크에 있으므로, 여기에 코드를 더하면 `/compare` 첫 화면 여유(B-2, 약 20바이트)를 깎는다 |
| 조회 | 선택이 **있는** 그룹마다 `repository.list(그 그룹을 뺀 조건)` 1회 + 현재 결과(`items`, 선택 없는 그룹은 이것으로 계산). 선택이 없으면 추가 조회 0. 옵션 값 추출은 참조 필드(업종·audience·visualTags·layoutType·purpose·licenseStatus·devices·`colorFamilyOf(primary)`)를 읽는다. 백엔드가 정해지면 저장소 `facets()`로 옮긴다(백엔드 ADR 몫, 지금 설계 범위 밖) |
| 표시 | 옵션 라벨 오른쪽 끝 `ds-caption2` + `text-label-alternative` + `tabular-nums`(목업 `t-caption tabular`). 칩은 라벨 뒤 같은 캡션 스타일. 응답 전에는 이전 값을 유지(`useReferenceList`와 같은 방식) |
| 0개 | **비활성화하지 않는다.** "0"을 보여줄 뿐 체크·해제 모두 가능(이미 체크된 0개 옵션을 풀 수 없게 되는 함정 방지) |
| 접근 이름 | **이름은 옵션명만**(`checkbox "미니멀"`, `button "카페·F&B"` — 기존 테스트 이름 그대로). 보이는 숫자는 `aria-hidden`, 스크린리더에는 **설명**(`aria-describedby` → 화면에 안 보이는 "N개")으로 준다. 2.5.3(보이는 라벨 ⊂ 이름): 라벨 낱말은 이름에 있고, 숫자는 라벨이 아니라 보조 수치로 본다(L2 판단) |

**"초기화 · N"과 "필터 N"** — 숫자는 그 컨트롤이 실제로 건드리는 것만 센다.

| 항목 | 규칙 |
|---|---|
| N | **레일 선택 값 수 = 체크된 옵션 수(7그룹) + 모션이 "전체"가 아니면 1.** 업종은 세지 않는다 |
| 초기화 범위 | **(Q8 추천안 — 결정 전) 레일 8그룹만 지운다. 업종은 유지**(업종은 레일 밖 칩 줄에 있고 "전체" 칩이 그 초기화다). 현재 구현(`filters: {}`로 업종까지 지움)에서 **바뀌는 동작** → Q8. 정렬·`tab`은 지금처럼 유지 |
| 보이는 글자 | N ≥ 1: "초기화 · N" / N = 0: "초기화" + `disabled`(지울 것이 없음. 비활성 글자는 1.4.3 예외) |
| 모양 | 목업처럼 ghost sm → 기존 `Button` `assistive`(V2-1에서 ghost로 재정의) `size="sm"`. 지금의 raw `button`(primary 글자)을 바꾼다 |
| 접근 이름 | **"필터 초기화" 유지**(기존 aria-label). N은 개수 규칙과 같이 설명 "선택 N개"로. 이름에 "초기화"가 들어 있어 2.5.3 충족 |
| <1024 "필터 N" 버튼 | 같은 N. 보이는 글자 N ≥ 1 "필터 N" / 0 "필터". 이름 "필터" + 설명 "선택 N개" + `aria-expanded` + `aria-controls`(레일 id). outline sm, 아이콘 없음(B-3 — 목업 `filter` 아이콘 미추가) |

**그리드·반응형** — 카드 최소 폭 240px 기준(점수 줄 "접근성 96 · 성능 92 · 09.20 측정" 12px ≈ 190 + 여백, L2 추정). 값은 현재 클래스(`px-4 md:px-7`, 레일 232 + `gap-7`, 카드 `gap-4`)로 계산.

- **카드 그리드 클래스는 지금 그대로**(`grid-cols-1 sm:grid-cols-2 xl:grid-cols-3`)이고 r2와 맞는다 → 그리드 코드 변경 0. 레일이 옆에 붙는 기준도 지금과 같은 `lg`(1024).
