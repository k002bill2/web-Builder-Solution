## 3. 검증 항목
### A. 반응형 — AC-21 정식 판정 ([Q])
| 뷰포트 | 보드 상태 | 확인 |
|---|---|---|
| 1280 × 800 | 6개 | 표만 가로 스크롤, 행 머리글 고정, 초안 패널 보임·sticky, 문서 가로 넘침 0 |
| 768 × 1024 | 3개 | 표 + 하단 요약 바, 넘침 0, "초안 보기"가 패널로 이동·포커스 |
| 390 × 844 | 3개 | 아코디언(표 없음), 처음엔 Hero만 펼침, 요약 바, 넘침 0, **모든 값이 펼침으로 확인 가능(정보 손실 0)** |
각 뷰포트 캡처 필수. 겹침·잘림·말줄임된 셀 값(SPEC S-18: 셀·초안 값은 자르지 않음)은 결함.

### B. 대비 실측 (A-10, WCAG 2.2 AA — 본문 4.5:1, 큰 글자·UI 3:1)
- 회수된 열의 흐린 셀, "기본값" 라벨(`--label-alternative`), 요약 바 텍스트와 **"초안 보기" 버튼**(Jarvis가 390 캡처에서 낮아 보인다고 지적), 선택됨/이 요소 선택 버튼, 비활성 "레퍼런스 추가"(보완 5)
- 계산된 전경·배경 색과 비율을 표로 기록(개발자 도구의 computed style 기준)

### C. 접근성·키보드
1. AC-19: 행당 Tab 1회, ←/→·Home/End 이동, ↑/↓ 무시, Space/Enter 선택
2. A-2 접근 이름: "Hero 구성: A … 의 요소 선택" 형태 — 접근성 트리에서 확인
3. A-4 알림: `role=status` 영역 텍스트가 선택·교체·해제·열 빼기·비우기마다 바뀌는지(DOM 관찰로 확인. 실제 스크린리더 청취가 불가하면 그 사실을 적는다)
4. A-7 진입 시 `document.title`, `h1` 포커스 / A-8 확정 불가 이유 연결(`aria-describedby`) / A-9 실패만 `role=alert`
5. A-6 열 빼기 후 포커스 이동 순서

### D. 기능 흐름 (브라우저에서 실제 조작)
1. 카탈로그에서 3개 담기 → 트레이 → `/compare` 진입
2. 선택·교체·해제, "이 레퍼런스로 전부 선택" + 되돌리기, 초안 비우기 + 되돌리기
3. 사용자 대표색 `abc`(오류) / `#C9A96E`(대비 경고 + "보정값 쓰기"), 폰트 3종 선택 가능
4. 확정 → `/profile/:id` 이동 → 돌아와 "v1 확정됨" → 변경 없이 재확정 불가(E2) → 변경 후 "새 버전으로 확정 (v2)"
5. 빈 보드(0개)·1개 상태, 6개 가득 참에서 "레퍼런스 추가" 비활성 표시와 안내
6. 새로고침 후 보드 선택 유지 여부 기록(메모리 저장소라 초기화되면 "현재 설계상 한계"로 기록, 결함 아님)
7. 콘솔 오류 0, 네트워크 4xx·외부 도메인 요청 0
8. 카탈로그·상세 회귀: 트레이 담기/빼기·6개 제한·포커스 이동(D07) 기존 동작 유지
