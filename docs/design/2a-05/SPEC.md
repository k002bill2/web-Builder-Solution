## 2. IA · 라우트 · 흐름

### 2.1 프로젝트 단위 (Q1=A · ADR-005 Q1 이행)
- **프로젝트 = 이름 + 프로필 계열 1개 + 편집 문서 1개(Q3) + 발행(2a-05b).** 프로필 계열과 1:1이다 — 프로필 버전은 프로젝트 안의 이력이고, 편집 문서는 그중 한 버전(과 한 안)을 가리키는 필드를 가진다(Q3).
- 프로젝트는 **보드 확정 때만** 생긴다(Q2 · ADR-005 Q1 "확정 시 프로젝트를 만들거나 골라"). 이름 입력 대화상자는 없다 — 기본 이름으로 만들고 나중에 바꾼다(Q2).
- 기본 이름 = `"<기준 레퍼런스 제목> 프로젝트"`(기준 = 프로필 `baseReferenceId`, 2a-04 A-Q1). 같은 이름이 있으면 `" 2"`, `" 3"`…을 붙인다(순수 함수 `defaultProjectName(title, existingNames)` — 목록에서 두 줄을 구별하기 위해서다).
- 보드는 사용자당 1개(ADR-005 Q1)라 **보드 `confirmed`가 가리키는 프로젝트 = "보드의 현재 프로젝트"**다. 이 SPEC은 확정 때 "고르기"를 **"현재 프로젝트 새 버전 / 새 프로젝트" 두 가지**로 둔다(추천안 — **EQ-7**, Q1 "만들거나 고른다"의 범위를 좁히는 결정이라 질문으로 남긴다). 이유: ① 보드는 1개라 다른 프로젝트의 보드 선택 상태를 다시 불러오는 흐름이 없다 ② 다른 프로젝트로 확정하면 그 계열의 마지막 보드 확정 base가 비교 기준이 되고, 지금 보드 선택은 다른 프로젝트에서 온 것이라 대부분의 필드가 "바뀜"으로 잡혀 그 프로젝트의 조정이 거의 다 지워진다(2a-04 6.1-3 규칙은 정의되지만 손실이 크다).

### 2.3 흐름

```
GNB "새 프로젝트" ──▶ /compare?new=1
                       ├─ 보드가 비었음 ──▶ 기존 보드 빈 상태("카탈로그에서 고르기")

/profile/:id ── 3안에서 안 선택 ── "B안으로 편집 시작" ──▶ /studio/:projectId
                                     (문서 없음 = 선택한 안·버전으로 문서 생성 · 문서 있음 = EQ-2)
GNB "프로젝트" ──▶ /projects ── 줄 "편집기 열기" ──▶ /studio/:projectId

/studio/:projectId ── 툴바 "프로젝트로 돌아가기"(Q4) ──▶ /projects
```

- 편집 문서는 **2a-04c "편집 시작"에서 처음 만든다**(선택한 `CandidatePlan` → PageDoc, L4 composer). `/projects`와 편집기는 문서를 만들지 않는다.
- "프로젝트로 돌아가기"의 목적지는 `/projects`다(Q4의 접근 이름 그대로). 프로필로 가는 길은 편집기 오른쪽 패널 "테마" 영역의 "프로필 보기" 링크(5.8)다.

## 5. 상호작용

URL 상태는 `projectId`뿐이다. 선택 섹션 · 미리보기 폭 · 탭 · 스냅샷 미리보기는 화면 상태다(문서 정본은 저장소 — 2a-04 2.1과 같은 원칙). 모든 편집 연산은 **문서를 새로 만드는 순수 함수**(L4 엔진, 8.2)이고 화면은 결과만 그린다.

### 5.1 섹션 선택
- 섹션 줄 = `button`(이름 + 변형 이름표 캡션 + 게이트 표시 글자 "경고 1"/"차단 1" Tag). 선택 줄: `aria-current="true"` + 굵기 700 + `primary-container` 면 + 왼쪽 막대 `primary`(3:1, 7절) — 색 외 단서 2개(B-01의 "색만 다른 이름" 해소).
- 맨 위 "페이지 정보" 줄은 섹션이 아니다(이동·삭제 없음). 고르면 편집 패널이 SEO 메타 필드(5.6)를 보인다.
- 캔버스에서 섹션을 누르면(포인터) 같은 선택이 된다. 캔버스 섹션은 Tab 정지가 아니다 — 같은 기능을 목록·`Select`·탭이 키보드로 준다(2.1.1 충족, Tab 정지 중복 방지).
- 선택이 바뀌면 캔버스는 그 섹션이 보이게 스크롤(`scrollIntoView({block:"nearest"})`, `prefers-reduced-motion`이면 즉시). 포커스는 옮기지 않는다.

### 5.2 순서 바꾸기 (Q6=A — 1280·1024·390 같은 버튼 한 벌, 드래그 없음)
- 편집 패널 머리(≥1024)와 "섹션" 탭·"편집" 탭(<1024)에 **같은 부품** "위로" · "아래로"(글자 버튼, 아이콘 없음 — P-B3). 선택 섹션을 한 칸 옮긴다.
- 옮긴 뒤 포커스는 누른 버튼에 그대로(버튼이 편집 패널에 있어 움직이지 않는다). 섹션 목록에서 누른 경우(<1024 "섹션" 탭)는 버튼이 선택 줄 옆에 따라 붙어 있으므로 역시 그대로. 알림 `role=status` "Services를 4번째로 옮겼습니다".

| 맨 위 본문 바로 아래가 Hero | "위로" `aria-disabled` | "Hero 위로는 옮길 수 없습니다 (R-02 Hero는 첫 본문)" |
| Hero 자체 | 둘 다 `aria-disabled` | "Hero는 첫 본문 자리에 고정됩니다 (R-02)" |
| Header · Footer | 둘 다 `aria-disabled` | "Header는 맨 위에 고정됩니다" / "Footer는 맨 아래에 고정됩니다" (R-01) |
| 마지막 본문 | "아래로" `aria-disabled` | "Footer 아래로는 옮길 수 없습니다" |

- 목적 R-03("문의" → cta-band·contact가 후반 1/3)을 깨는 이동은 **막지 않는다** — 게이트 "필수 섹션"이 차단으로 알린다(편집 중 임시 상태 허용).

### 5.3 섹션 추가 (E-08 · R-01)
- "섹션 추가"(아이콘 `plus` + 보이는 글자 "섹션 추가" — 목업은 아이콘뿐, B-10) → 모달 대화상자(네이티브 `dialog`, 5.15) "섹션 추가": ① 유형 라디오 목록(라이브러리 순서, 이름표 + 한 줄 설명) → ② 그 유형의 변형 라디오 목록(이름표 + 구조 썸네일 `aria-hidden`) → "추가"(primary) · "취소".
- Header·Footer는 이미 있으면 유형 목록에서 `aria-disabled` + 이유 "Footer는 하나만 둘 수 있습니다". Hero도 같음(R-02 정확히 1개).
- 넣는 자리: 선택 섹션 바로 뒤(선택이 Header·"페이지 정보"면 Hero 뒤, Footer면 Footer 앞). 새 섹션의 슬롯 = 엔진 기본 슬롯 콘텐츠(TRD 6.2 "기본 슬롯 콘텐츠"), 모션 = 문서 모션 프리셋과 L1 중 낮은 값(R-07 예산을 새로 쓰지 않음).
- 추가 뒤: 대화상자 닫힘 → 새 섹션 선택 → 포커스 = 새 섹션 줄(<1024는 "섹션" 탭의 그 줄) → 알림 "FAQ를 6번째에 추가했습니다".
- 상한: 본문 9개면 버튼 `aria-disabled` + 이유(E-S12). 대화상자는 열리지 않는다.

### 5.4 삭제 · 되돌리기 (Q7=A)
- "삭제"(글자 버튼, 편집 패널 머리 "위로·아래로" 옆 — 목업 2a-07 314행 배치). 확인 대화상자 없음, 즉시 삭제.
- 알림 줄(섹션 목록 위, <1024는 탭 목록 아래 — 늘 보이는 자리): "Services를 삭제했습니다" + "되돌리기"(버튼). **다음 편집 연산이 생기면 사라진다**(Q7). 알림 줄은 `role=status` 영역 안의 글자 + 형제 버튼(D-QA06 "담았습니다 + 보드 열기" 형식).
- 포커스: 삭제 → 다음 섹션 줄(없으면 이전 줄). 되돌리기 → 되살린 섹션 줄 + 선택 복원 + 알림 "Services를 되돌렸습니다".

| 삭제할 수 없는 섹션 | 조건 | 이유 문장 |
|---|---|---|
| Header · Footer | 늘 | "Header는 페이지에 꼭 하나 있어야 합니다 (R-01)" |
| Hero | 늘 | "Hero는 첫 본문으로 꼭 있어야 합니다 (R-02)" |
| Contact(예약 변형) | 목적 "예약"이고 그것이 유일 | "목적이 '예약'이라 Contact(예약)가 필요합니다 (R-04)" |
| cta-band · contact | 목적 "문의"이고 둘 중 남은 하나 | "목적이 '문의'라 문의 섹션이 하나는 필요합니다 (R-03)" |
| 본문 | 본문이 5개 | 막지 않는다 — 게이트 "필수 섹션" 차단으로 알린다(추가로 고칠 수 있음) |

- 목적은 프로필 조정 값(`adjustments.purpose`, 2a-04 Q5)이다. 편집기는 목적을 바꾸지 않는다(프로필 소유) — 이유 문장 옆 링크 "프로필에서 목적 바꾸기".

### 5.5 변형 교체 (E-11)
- 편집 패널 머리 "변형: 풀블리드 이미지 + 좌측 카피" + "변형 바꾸기"(`details`/펼침). 펼치면 라디오 목록: 변형 이름표 + 캡션 **"유지 4 · 잃음 1 (부제)"**(슬롯 스키마 비교 — 같은 키·같은 종류면 유지, 없으면 잃음, 8.2 `diffSlots`). 잃음 0이면 "슬롯 모두 유지".
- 고르면 바로 적용(확인 없음, Q7과 같은 되돌리기 모델) → 알림 줄 "스플릿으로 바꿨습니다 · 잃은 슬롯 1개(부제)" + "되돌리기". 포커스는 라디오에 그대로.
- 목업의 `chevron-down` 버튼("fullbleed-left ▾")은 변형 **키**를 보인다 → 이름표로(2a-04 M-06 원칙, EM).

### 5.6 필드 편집 (E-13 · FR-EDT-05)
- 슬롯 종류: 짧은 글(`TextField`) · 긴 글(`textarea`, 같은 토큰) · 링크 라벨 · 이미지(5.9). 라벨 = 슬롯 이름표(한국어), 필수 표시 = 라벨 옆 글자 "(필수)".
- 카운터 "18 / 24자"(`tabular-nums`, `aria-describedby`로 입력과 연결, **알림 영역 아님** — 매 글자 낭독 금지). 슬롯 스키마의 두 값: **상한**(`maxLength`, R-13 차단) · **권장**(넘치면 2줄·잘림 위험, FR-EDT-05 경고). 권장이 없으면 상한만.
- 권장 초과: 카운터 뒤 "권장 28자 — 넘으면 2줄이 될 수 있습니다"(`status-cautionary-text`, 경고). 상한 초과: `aria-invalid=true` + "상한 40자를 6자 넘었습니다 — 내보내기를 막습니다 (R-13)"(`status-negative-text`). 두 경우 모두 **입력은 막지 않는다**(붙여 넣고 줄이는 흐름 보호).
- 필수 슬롯 빈 값: 포커스를 떠날 때(blur) "필수 입력입니다" + `aria-invalid`(입력 중에는 알리지 않음).
- "페이지 정보"(SEO 메타, R-11): 제목(title) · 설명(description) — 문서 단위 필드. 권장 길이 제목 60자 · 설명 160자(검색 결과 표시 폭 관행, L3 — 정본은 L4 슬롯 스키마), 빈 값 = 차단. canonical은 캡션 "발행 주소가 정해지면 채웁니다(2a-05b)" — 2a-05에서는 검사하지 않는다(발행 도메인이 없다 — TRD R-11 부분 이행. 목업 차이가 아니라 TRD와의 차이이며 canonical 검사는 2a-05b 몫, 8.3 TRD 개정 대상 ⑤).
- 입력마다 문서가 바뀌고 자동 저장·게이트 재계산이 디바운스로 따라온다(5.10·5.12). 실행 취소 기록은 **입력칸 포커스가 떠날 때 한 번**(글자마다 쌓지 않음).

### 5.7 캔버스 표시 (Q12 · FR-EDT-05 "경고가 섹션을 가리킴")
- 섹션 블록 = 2a-04c 구조안 와이어프레임(블록·막대, 프로필 토큰 색) + **실제 슬롯 글자**. 색은 문서 테마(프로필 버전 적용된 팔레트)를 CSS 변수로 넘긴다 — 컴포넌트 hex 0(`noHardcodedStyle`, 목업 252~260행 hex는 EM).
- 캡션 상시(캔버스 머리): **"구조 미리보기 — 섹션 구성과 실제 문구입니다. 실제 페이지는 생성기 연결 후(M2) 만들어집니다."**
- 선택 섹션: 2px `primary` 테두리 + 라벨 칩 "Hero · 풀블리드 이미지 + 좌측 카피"(12px·700, `on-primary` 글자 / `primary` 면 4.95, B-12).
- 문제 표시(B-03): 문제 요소에 **2중 테두리**(안쪽 2px 흰 간격 `background-normal` + 바깥 2px `status-cautionary-text`(경고) / `status-negative-text`(차단)) + 모서리 번호 배지 글자 "경고 1"/"차단 1"(상태 글자 토큰 on 흰 면). 요소 아래 문장 "3번 카드 제목이 권장 28자를 넘었습니다 (34/28자)"(상태 글자 토큰). 흰 간격 때문에 사용자 데이터 색(프로필 면) 위에서도 테두리는 늘 흰 면과 맞닿는다 → 3:1 판정이 데이터와 무관(7절).
- 문제 문장 ↔ 필드 연결: 필드의 `aria-describedby`가 캔버스 문장과 카운터를 함께 가리킨다. 캔버스 배지를 누르면(포인터) 그 필드로 포커스.
- **(r4.8 — M2a부터, D6-1·B-7-3) 렌더 문서 캔버스에서의 선택·문제 표시 위치.** 캔버스가 별도 렌더 문서(iframe, `sandbox="allow-scripts"`)로 바뀌어도 위 시각 규칙(선택 테두리·라벨 칩 · 2중 테두리 · 흰 간격 · 배지 · 문장)은 그대로이고, **그리는 문서만 바뀐다.**
  - **부모 문서(편집기)가 그린다.** 선택 테두리·라벨 칩·2중 테두리·배지·문제 문장은 iframe 위에 겹친 **오버레이 층**(부모 DOM)에 둔다. 위치는 렌더 문서가 보고하는 섹션·슬롯 사각형(`rects` 메시지: `instanceId`·slot key → x·y·w·h)에 맞춘다. 렌더 문서에는 문제 문장·배지·편집기 UI를 넣지 않는다(내보내기·PNG에 섞이지 않게).
  - **이유 — 접근성 연결.** `aria-describedby`는 문서 경계를 넘지 못한다. 문제 문장이 iframe 안에 있으면 필드 ↔ 문장 연결이 끊긴다. 그래서 문장은 늘 부모 문서에 있고, 필드의 `aria-describedby`는 지금처럼 그 문장과 카운터를 함께 가리킨다.
  - 오버레이의 테두리는 `aria-hidden`, 포인터 통과(`pointer-events: none`). 배지만 누를 수 있고 누르면 그 필드로 포커스(지금과 같음). 캔버스 섹션 선택은 렌더 문서의 `click{instanceId}` 메시지로 받는다.
  - 사각형을 아직 받지 못한 동안(렌더 문서 준비 전·다시 그리는 중)에는 오버레이를 그리지 않는다. 문제 문장은 부모 DOM에 남아 있어 `aria-describedby` 연결은 끊기지 않는다.
  - **폴백 섹션 표식.** 렌더러가 아직 없는 변형의 섹션은 렌더 문서가 와이어프레임 폴백으로 그리고(ADR-004 개정 2 결정 3), 섹션 머리에 보이는 표식 **"구조 미리보기"**를 단다. 이 표식은 PNG 캡처에도 남는다(D6-4). 표식 글자·위치의 시각 명세는 M2a Designer가 확정한다.
- 이미지 슬롯: 자체 플레이스홀더 패턴(대각 줄무늬 토큰, `aria-hidden`) 또는 사용자 로컬 이미지(EQ-3). 외부 URL·레퍼런스 캡처 0(PRD 원칙 4).
- 사용자 사이트 글자 대비(프로필 색 위 글자)는 앱 UI 대비가 아니라 **게이트 "대비 AA"의 검사 대상**이다(B-12). 캔버스는 불투명도 글자를 쓰지 않는다(목업 `rgba(255,255,255,.6)` → EM).

### 5.8 테마 바꾸기 (E-12 · FR-EDT-03)
- 테마 = **문서가 가리키는 프로필 버전**(Q3 "프로필 버전은 문서 필드"). 무드 테마(M2)는 같은 자리로 확장한다.
- "테마 바꾸기" → 대화상자: 이 프로젝트의 프로필 버전 라디오 목록(버전 · 출처 · 요약 — 2a-04 3.5 줄 문장 재사용 · 대비 결과 "대비 미달 1"/"대비 통과" 글자) → "바꾸기".
- 적용 = 문서의 프로필 버전 필드만 바뀐다. 섹션·변형·슬롯 값은 그대로 → **검증 결과를 글자로**: 적용 전후 모든 슬롯 값을 비교(`diffSlotValues`)해 "슬롯 값 23개 모두 그대로입니다". 다르면(결함) "슬롯 값 2개가 달라졌습니다: Hero 제목, …" + 자동 되돌리기 없이 "되돌리기" 제공(E-AC로 0건 보장).
- 새 버전이 목적(`purpose`)을 바꿨다면 필수 섹션 판정이 바뀐다 → 게이트가 다시 계산해 알린다(편집기는 섹션을 자동 추가하지 않는다).
- "프로필 보기" = `/profile/:profileId?v=<문서 버전>` 링크(같은 탭 이동. 메모리 store는 유지).

### 5.9 이미지 슬롯 (E-14 · B-18)
- 스위치 = `button role=switch aria-checked` + 보이는 라벨 "배경 이미지 사용"(`aria-labelledby`) + 캡션 "끄면 이미지 없이 색 면으로 보이고 대체텍스트 검사에서 빠집니다"(B-18). Switch 부품이 DS에 없다 → studio 청크 안 작은 부품(10.2 S-B6).
- 켜진 슬롯: 이미지 미리보기(플레이스홀더 또는 EQ-3 로컬 이미지) + "대체텍스트"(`TextField`, 필수 — 비면 게이트 R-09 차단) + `Checkbox` "장식 이미지 — 대체텍스트 없이 둡니다"(체크하면 대체텍스트 입력 `aria-disabled` + 이유, 게이트 통과).
- 파일 고르기·교체·실패(형식·크기)는 EQ-3 결정에 따른다. 추천안 A의 실패 문장: "JPEG·PNG·WebP만 쓸 수 있습니다" · "5MB까지 쓸 수 있습니다 (7.2MB)" — 필드 오류(`aria-invalid` + 설명), 이전 이미지 유지.
- **자원 한도(r1 — Codex j1 medium, EQ-3 A 유지: 브라우저 안 · 서버 전송 0 · JPEG·PNG·WebP · 파일당 5MB · SVG 불가).** 값은 L3 제안 — L4 슬롯 스키마(섹션당 이미지 슬롯 수)가 나오면 다시 본다.

| 한도 | 값 | 근거 (L3) | 넘을 때 (필드 오류, 이전 이미지 유지) |
|---|---|---|---|
| 문서당 개수 | **12개** | 섹션 상한 11(header + 본문 9 + footer)마다 1장 + 1. 목업 이미지 슬롯은 섹션 배경 1곳뿐 | "이미지는 한 페이지에 12개까지 쓸 수 있습니다 — 다른 슬롯의 이미지를 끈 뒤 고르세요" |
| 문서당 합계 | **30MB** | 파일당 상한 5MB × 6. 웹용 사진 한 장 1~2MB면 12장이 20MB 안쪽 — 큰 원본을 여러 장 그대로 넣는 경우만 막는다 | "이 페이지의 이미지가 합계 30MB를 넘습니다 (31.4MB) — 더 작은 파일을 고르세요" |
| 탭 전체(살아 있는 고유 이미지) | **24개 · 60MB** | 문서 한 벌(12개 · 30MB)을 한 번 통째로 바꿔도 스냅샷·실행 취소가 이전 것을 붙잡을 자리. 스냅샷은 지울 수 없어(5.11) 문서 한도만 걸면 "교체 + 수동 스냅샷" 반복으로 메모리가 끝없이 는다 | **(r2 — Codex j2 medium) 먼저 계산, 그다음 비움.** ① 기록을 건드리지 않고, 실행 취소·다시 실행 기록에서 오래된 항목부터 버렸을 때 풀려날 로컬 id(현재 문서·모든 스냅샷·남는 기록 어디에도 없는 것)의 개수·바이트를 **계산만** 한다. ② 그 회수량으로 새 이미지가 한도 안에 들어오면 **필요한 만큼만** 오래된 기록을 버리고 추가한다(알림 "실행 취소 기록 3개를 비워 이미지 자리를 만들었습니다"). ③ 모두 버려도 넘으면(스냅샷이 붙잡음) **기록을 하나도 버리지 않고** 거부: "스냅샷이 이전 이미지를 보관하고 있어 더 넣을 수 없습니다 (24개 · 60MB까지) — 더 작은 파일을 고르세요". 거부된 선택은 문서·기록·보관소를 바꾸지 않는다 |

- **로컬 참조와 URL 수명(r1).**
  - 문서·스냅샷·저장 요청·계측에는 **로컬 참조 id만** 넣는다(8.1 슬롯 값 `source` "로컬 이미지 참조" — 이름 그대로, 값 = 로컬 id 문자열). object URL(`blob:`) 문자열은 어디에도 저장하지 않는다. **로컬 id는 다시 쓰지 않는 고유값**(네이티브 `crypto.randomUUID()`, 새 의존성 0) — 보관소를 비워도 번호를 재사용하지 않는다(8.3 "store마다 1부터" 관례를 쓰면 돌아와 고른 새 이미지가 잃은 슬롯·옛 스냅샷에 끼어든다).
  - 이미지 보관소(탭 메모리, studio 조작 뒤 청크 — S-B5) = 로컬 id → Blob · object URL · 바이트. 캔버스·미리보기 `<img>`는 보관소에서 URL을 받는다.
  - **참조 집합** = 현재 문서 ∪ 모든 스냅샷 ∪ 실행 취소 스택 ∪ 다시 실행 스택. 연산(교체·끄기·삭제·되돌리기·기록 밀려남·스냅샷 복원) 뒤 **참조 집합 어디에도 없는 id만** `revokeObjectURL` + Blob을 버린다. 살아 있는 URL 수 = 참조 집합의 고유 로컬 id 수.
  - **편집기를 떠날 때(언마운트 — 앱 안 이동 포함)** URL 전부 해제 · 보관소 비움 · 실행 취소·다시 실행 스택 비움(5.14). 문서·스냅샷의 로컬 id는 값으로 남는다.
  - 슬롯 아래 캡션(상시): "고른 이미지는 이 탭의 편집기 안에서만 보관됩니다 — 편집기를 나가거나 새로고침하면 다시 골라야 합니다". 떠나기 경고 조건(E-S10)은 바꾸지 않는다.
  - **잃은 이미지**(보관소에 없는 로컬 id — 다시 들어옴 · 스냅샷 복원 · 실행 취소): E-S20 변형(3.2). 슬롯 켜짐·대체텍스트·장식 표시는 **보존**, 미리보기 자리는 자체 플레이스홀더 + "이미지를 다시 골라 주세요" + "이미지 고르기". 게이트 8줄·판정은 그대로(R-09는 대체텍스트만 본다 — 줄을 더하지 않는다, Q14 가드).

### 5.10 자동 저장 (Q5=A · FR-EDT-06)
- 문서 연산이 생기면 **마지막 변경 뒤 2초 디바운스, 첫 미저장 변경부터 최대 30초**(maxWait)에 저장한다. 저장은 한 번에 하나 — 저장 중에 생긴 변경은 끝난 뒤 다음 저장에 모은다.
- 저장 요청 = 문서 전체 + `expectedRevision`(보고 있던 revision) + 문서 해시. 불일치 → `STALE_DOC`(E-S09). 같은 revision·같은 해시 재요청은 멱등(응답 실패 뒤 재시도가 두 revision을 만들지 않음 — 2a-04 6.3 멱등 선례).
- 상태 전이·문구는 E-S06~E-S10. 알림은 **단계가 바뀔 때만**: "저장하지 못했습니다"(alert 1회) · "다시 저장했습니다"(실패에서 회복할 때만 status). 평상시 "저장됨"은 낭독하지 않는다(글자로만) — 매 2초 낭독 금지.

### 5.11 스냅샷 (Q5=A · E-07)

| 종류 글자 | 언제 | TRD `kind` |
|---|---|---|
| 수동 | "지금 상태 저장" | `manual` |
| 자동 · 내보내기 전 | **저장소**가 `requestExport` 안에서 잡을 만들 때(같은 트랜잭션, 8.3.2). 화면은 만들지 않는다. 생성기 없음(`GENERATOR_UNAVAILABLE`)·렌더러 없는 섹션(`UNRENDERED_SECTIONS`, r4.8)·차단·충돌이면 만들지 않는다 | `auto` (+ `reason: export`) |
| 자동 · 복원 전 | 복원 직전 | `auto` (+ `reason: restore`) |
| 자동 · 충돌 보존 | `STALE_DOC` 해결(E-S09) | `auto` (+ `reason: conflict`) |
| 자동 · 새로 시작 전 | EQ-2 추천안 A의 "새로 시작" | `auto` (+ `reason: restart`) |
| (2a-05b) 발행 | 발행 | `published` |

- 스냅샷 = 그때 문서 전체의 불변 사본(프로필 버전·안·해시 포함). 복원은 스냅샷을 바꾸지 않고 **새 문서 revision**을 만든다(2a-04 "되돌리기 = 새 버전" 원칙).
- 이름: 수동은 입력 가능(30자, 빈 값이면 기본 "수동 · 14:02"), 자동은 종류 + 시각. 이름 바꾸기·지우기는 2a-05 범위 밖(보존 쪽이 안전).
- 주기적 자동 스냅샷은 없다(Q5=A — B안 기각).

### 5.13 내보내기 (E-05·E-06 · EQ-1)
- 게이트 영역 아래 버튼 두 개: "React 프로젝트(zip) 내보내기" · "정적 HTML 내보내기"(outline, 아이콘 없음 — `download` 파일 없음, P-B3). 목업의 "…site 발행"(primary 전체 폭)은 두지 않는다(Q16 — 발행은 2a-05b).
- 차단 1건 이상: 두 버튼 `aria-disabled` + 보이는 이유 "차단 1건(SEO 메타: 설명 없음) — 고치면 열립니다" + 링크 "첫 차단으로 이동"(B-09).
- **(r4.8 — M2a부터, D6-4) 렌더러 없는 섹션 1개 이상**: 두 버튼 `aria-disabled` + 보이는 이유(초안) "구조 미리보기 섹션 2개 — 실제 렌더가 있는 변형으로 바꾸거나 지우면 열립니다" + 링크 "첫 구조 미리보기 섹션으로 이동". 게이트 차단과 함께 있으면 게이트 차단 이유를 먼저 보인다(8.3.2 판정 순서와 같은 순서). 문구 최종안은 M2a Designer. 저장소도 같은 조건을 다시 판정한다(8.3.2 7단계 — 화면 판정을 믿지 않는다).
- **(r4.8) PNG 캡처는 `requestExport`를 거치지 않는다** — 잡·스냅샷·멱등 기록 0. 폴백 섹션이 있어도 허용하고, 그 섹션은 "구조 미리보기" 표식(5.7)이 남은 채 캡처된다. 버튼 위치·문구·파일 이름은 M2a Designer 명세.
- 경고만: 누르면 확인 대화상자(E-S24). 경고 목록(원인 · 이동 링크는 대화상자를 닫고 이동) + "경고를 확인했습니다 · 내보내기" / "취소". 체크박스 확인은 요구하지 않는다(Q8=A — B안 기각).
- 시작: 게이트 결과가 오래됐으면 먼저 다시 계산 → 저장 전 변경이 있으면 먼저 저장(자동 저장 즉시 실행 — 저장 실패·`STALE_DOC`면 요청하지 않고 E-S07·E-S09) → `requestExport(projectId, format, docRevision)` **1회** → E-S27. **화면은 스냅샷을 만들지 않는다** — "내보내기 전" 스냅샷은 저장소가 잡과 같은 트랜잭션에서 만들고, 생성기 없음이면 만들지 않는다(r1, 8.3.2). 같은 (문서 revision · 형식) 재요청은 같은 잡이고 스냅샷을 새로 만들지 않는다(멱등).

### 5.14 실행 취소 모델 (E-20 · Q7)
- 문서 연산(추가·삭제·이동·변형·필드 확정·이미지·테마·복원)은 기록 스택에 쌓인다(최대 50). 실행 취소도 **새 문서 상태**를 만들고 자동 저장된다.
- Q7 알림 줄의 "되돌리기" = 바로 앞 연산 하나의 실행 취소와 같다. 다음 연산이 생기면 알림 줄은 사라지지만 기록 스택으로는 계속 되돌릴 수 있다(E-20 범위, 단계 a4 — 13.1).
- 복원·충돌 해결은 스냅샷으로도 보존되므로, 기록 스택은 **편집기가 열려 있는 동안만** 유지한다 — 편집기를 떠나면(언마운트, 앱 안 이동 포함) 실행 취소·다시 실행 스택을 비운다(r1, 5.9 이미지 URL 해제와 같은 시점).

### 5.15 대화상자 공통
- 네이티브 `dialog` + `showModal()`(새 의존성 0). 제목 h2 = 접근 이름(`aria-labelledby`). 열 때 포커스 = 첫 입력(없으면 제목), 닫을 때 = 연 버튼. Esc = 취소. 바깥 클릭으로 닫지 않는다(입력 보호).
- 쓰는 곳 4개: 섹션 추가 · 테마 바꾸기 · 스냅샷 · 경고 확인. 모두 **조작 뒤 로드 청크**(10절).

## 6. 접근성

### 6.1 제목 구조 (B-05)
- **편집기**: h1 = 프로젝트 이름(툴바 안, 시각 크기는 툴바 글자 — `text-body1` 700, 제목 요소만 h1). h2 = "섹션" · "테마" · "구조 미리보기" · "편집 · Hero" · "품질 게이트". h3 = 게이트 안 "내보내기". 대화상자 제목 = h2. <1024 탭에서도 같은 h2가 각 탭 패널 안에 있다(탭 이름 ≠ 제목이어도 된다 — "검사" 탭 안 h2 "품질 게이트").
- `document.title` = "<프로젝트 이름> 편집"(B-05) · `/projects` = "프로젝트".
- **프로젝트 목록**: h1 "프로젝트", 줄마다 h2 = 프로젝트 이름(제목 탐색으로 줄 이동).
- 목업의 `t-h2` 모양 `span`(Hero · 품질 게이트)은 제목 요소로(EM).

### 6.2 랜드마크 · 영역
- 편집기 툴바 = `header`(앱 GNB 대신, 랜드마크 banner 1개 유지). 섹션 열 = `nav aria-label="섹션"`(문서 안 이동 목록), 캔버스 = `section aria-labelledby`(h2 "구조 미리보기"), 오른쪽 열 = `aside`가 아니라 `section` 둘(편집 · 품질 게이트 — 보조 정보가 아니라 주 작업 영역).
- <1024 탭: `role=tablist aria-label="편집 도구"` + `role=tab`(`aria-selected`·`aria-controls`) + `role=tabpanel`(`aria-labelledby`, `tabindex=0`). 방향키 ←/→ · Home/End, **자동 활성**(패널이 가볍고 이미 그려져 있음). 기존 `rovingFocus.ts` 재사용. Tabs 부품이 DS에 없다 → studio 청크 안 작은 부품(10.2 S-B6).

### 7.2 규칙
- **사용자 데이터 색 위의 표시는 2중으로**: 캔버스 섹션 면은 프로필 색(데이터)이라 대비를 미리 알 수 없다. 그래서 선택 테두리·문제 테두리 모두 **안쪽 2px 흰 간격(`background-normal`) + 바깥 2px 토큰색**(v2 3.4 포커스 2중 링과 같은 방법) → 테두리는 늘 흰 간격과 맞닿아 N-1·N-2·N-6 값이 보장된다. 배지·라벨 칩은 자기 면(흰 면 · `primary`)을 가지므로 데이터와 무관하다.
- 목업 경고 점·테두리 `--warning`(`--status-cautionary` 계열, 흰 면 1.80 — v2 3.4)은 **혼자 알리는 곳에 쓰지 않는다**(B-01·B-03). 장식 점(게이트 줄, 6.6 표)만 `--status-*`.
- 목업 게이트 값 글자 `--warning-text` 4.26 · `--danger-text` 3.84 · 통과 `--caption` 3.61(v2 원값, 배경 집합 최저 — B-02) → 보정 토큰 `status-cautionary-text` · `status-negative-text` · `label-alternative`(v2 3.2 최저 4.64~4.68).
- 입력 테두리 = `line-strong`(3:1, v2 Q4 — B-13). 목업 `.in` `--border-strong` 1.45는 쓰지 않는다.
- 캔버스의 사용자 사이트 글자(프로필 색 위)는 앱 UI 대비 대상이 아니다 → 게이트 "대비 AA"(5.12)가 판정한다. 불투명도 글자(`rgba(255,255,255,.6)`, 목업 260행)는 캔버스에서 쓰지 않는다(C-12 opacity 금지 이어받음).
- 다크: 앱에 `data-theme="dark"`를 켜는 코드가 없다(v2 3.1). 2중 테두리의 간격 색이 `background-normal`이므로 다크에서도 "상태 글자 토큰 / 자기 배경"이 되고, 그 값은 v2 3.2 다크 상태 글자(최저 4.62 이상)로 이미 검증돼 있다.

### 8.2.1 `startDoc` 어댑터 · 변형 매핑 표 (r4 — Q-17 A · Q-21 A, 이 절이 정본)

생성 잡의 구조안(2a-04c 컴포저 결과)은 **픽스처·라이브러리 어휘**(`services/grid-3` 등)이고 엔진 레지스트리는 **엔진 어휘**(`services/cards-3` 등)다. 둘을 잇는 곳은 `startDoc` 쓰기 경로의 **어댑터 한 곳**이다.

- **어댑터가 하는 일**(8.3.1 판정 5 `create`·`restart` 쓰기 안, 순서대로): ① 저장소가 (계열, `profileVersion`)의 생성 잡과 `candidateId` 안을 읽는다(없으면 판정 3 `NOT_FOUND` — 이미 8.3.1) → ② 섹션마다 **변형 매핑 표**로 엔진 변형을 구한다 → ③ 표 밖 쌍이 하나라도 있으면 **쓰기 0**으로 `UNKNOWN_VARIANT`(아래 (b)) → ④ `createDocFromCandidate({candidateId, sections: 매핑 결과, libraryVersion, generatorVersion}, profileVersion, {projectId, updatedAt})` → ⑤ 문서 저장. `updatedAt` = 같은 쓰기에서 저장소가 쓰는 **주입된 `now()` 한 번**의 값(프로젝트 `updatedAt`과 같은 값, 저장소마다 `now` 옵션 주입 — 현행 `memoryProfileRepository`·`memoryCompareBoardRepository` 방식). 엔진 예외(`EngineOpError`)는 어댑터가 ④에서 잡아 **쓰기 0**으로 끝낸다(`commit` 전). 멱등 기록은 성공만(8.3.1 그대로).
- **표는 한 곳**: 표와 매핑 함수는 새 모듈 파일 1개에만 둔다. 부르는 곳은 `startDoc` 쓰기 본문 1곳. **컴포저(2a-04c)·`toEngineCandidate`(`domain/generation.ts`)에 두지 않는다** — 컴포저는 그리드 축(`grid-3`·`grid-2`·`masonry`)이 3안 차이를 만드는 어휘라 바꾸면 병합된 3안 화면·lint가 바뀌고, `domain/generation.ts`는 `/profile` 진입 직후 청크에 런타임으로 들어가 있어(2a-04c REPORT 3절 — 공유 청크 사례) 표를 거기 두면 `/profile` 진입 직후(여유 0.2대, a1-β REPORT 1절)가 는다. 표·어댑터·엔진 `createDocFromCandidate`는 **"편집 시작"을 눌렀을 때만 로드**(조작 뒤 청크, 2a-04 Q-F4-1 분류)한다.
- **키 = `type/variant` 쌍**: 같은 변형 이름이 유형마다 뜻이 다르다(`services/grid-3` → `cards-3` · `portfolio/grid-3` → 그대로). 유형은 바꾸지 않는다(목적 필수 섹션 R-03·R-04 판정이 유형을 본다).
- **표 내용**: 현재 픽스처(`fixtures/referenceComparisons.ts` `sectionPlan`) 49줄 · 고유 30쌍 + 컴포저가 만드는 쌍(그리드 축 · Footer 대체 · 목적 섹션) + 엔진 변형 자체(그대로) — 전체와 grep 줄번호는 **`docs/design/2a-05/VARIANT-MAP.md`**. 요약: header·hero·footer 14쌍 = 그대로(엔진 bound 변형이 라이브러리 1.4 키에서 만들어짐) · 본문은 **가장 가까운 엔진 변형**(유형 안에서): about → `story` · services 카드형 → `cards-3`, 목록·표형 → `list` · portfolio → `grid-3` · testimonials → `quotes-2` · pricing → `tiers-2` · contact 폼형 → `form`. 현재 어휘에서 **표 밖 쌍은 0**이다.
- **변형이 바뀐 섹션 (a) — 표 안, 모양이 다름**: 정상으로 연다(E-S05). `startDoc` 성공 결과에 바뀐 쌍 목록(`{type, from, to}`)을 싣고, 화면은 이동 뒤 편집기 첫 표시 때 **편집 알림 1문장**(6.3 "편집 알림" 영역 — 8.3.1 `DOC_EXISTS` "이미 편집 중인 문서를 엽니다"와 같은 방식): **"구조안의 섹션 N개를 편집기 변형으로 바꿔 열었습니다 — Services 2열 → 카드 3개 · Portfolio 마소니 → 이미지 그리드 3칸"**(이름표로, 변형 키 아님 — E-AC-20 원칙). 0개면 알림 없음. 멱등 재생(8.3.1 판정 2 — 이전 결과 그대로라 목록도 같다)도 **성공이므로 이동 뒤 1회 알린다**(재생은 첫 응답을 잃었을 때만 생기므로 사용자는 아직 못 봤다). `DOC_EXISTS`·새로고침·다시 열기에는 알리지 않는다(목록은 `startDoc` 성공 결과에만 있고 문서에 저장하지 않는다). 그리드 축만 달랐던 두 안은 문서에서 같은 변형이 될 수 있다 — 이 알림이 그 사실을 알린다.
- **표 밖 변형 (b) — `UNKNOWN_VARIANT`**(지금 픽스처로는 발생 0 — 픽스처·라이브러리·컴포저가 표보다 먼저 바뀐 경우의 방어): 판정 1~4 뒤, 쓰기 전에 거부 → 문서·스냅샷·멱등 기록 변화 0. **결정적 결과라 "다시 시도"를 주지 않는다**(같은 인자 재시도 = 같은 실패). 프로필 화면(2a-04c 편집 시작 자리) `role=alert` 1회: **"이 안에는 편집기가 아직 열 수 없는 섹션이 있습니다(<유형 이름표> · <변형 키>) — 다른 안을 고르세요"**. 이동 없음 · 편집 시작 버튼 상태 그대로. 엔진이 던진 다른 예외(`BAD_VALUE` — 구조 R-01·R-02·검증 실패)도 같은 경로(쓰기 0 · 재시도 없음)이되 문구는 "이 안으로 편집 문서를 만들 수 없습니다 — 다른 안을 고르세요"(원인 코드는 계측 `reason`에만). 새 E-S 번호를 주지 않는다 — 편집기 밖(프로필 화면) 결과이고 8.3.1 결과 표의 한 행으로 읽는다.
- **저장소 오류 코드**: 8.3 오류 코드 모음에 `UNKNOWN_VARIANT`(8.2.1 (b), 결정적, 재시도 없음)를 더한다 — a2가 `ProjectErrorCode`에 추가. 8.3 표·8.3.1 결과 표 본문은 이 절을 정본으로 두고 a2 구현 때 옮겨 적는다.

### 8.3.1 `startDoc` 경쟁 · 멱등 (r1 — Codex j1 high)

문서는 프로젝트당 1개(Q3)다. 두 탭이 동시에 "편집 시작"을 누르거나 응답 실패 뒤 재시도해도 **문서는 하나만 생기고, 먼저 생긴 문서를 덮지 않는다.**

- **멱등 키** = (`projectId`, `mode`, `profileVersion`, `candidateId`[, `expectedRevision` — `restart`만]). 기록 범위 = **프로젝트마다 마지막으로 성공한 `startDoc` 1건**(2a-04 10.0.2 Q-F3 선례 — 계열마다 마지막 1건). 새 `startDoc`가 성공하면 기록을 바꾼다 → `restart` 뒤에 옛 `create` 키가 늦게 도착해도 재생되지 않고 판정 4에서 `DOC_EXISTS`가 된다.
- **판정 순서**(2a-04 10.0.2 Q-F2 형식 — 모양 먼저):
  1. 모양 — 인자 모양 · `mode` 값 · `restart`인데 `expectedRevision` 없음 → `SCHEMA_INVALID`
  2. 멱등 키 — 마지막 기록과 같으면 **이전 결과 그대로**(쓰기 0)
  3. `NOT_FOUND` — 프로젝트 없음 · 프로필 버전이 그 계열에 없음 · 안이 그 버전의 3안에 없음 · `restart`인데 문서 없음
  4. 문서 상태 — `create`: 문서 있음 → **`DOC_EXISTS`**(기존 문서 동봉, 쓰기 0) / `restart`: `expectedRevision` ≠ 현재 → **`STALE_DOC`**(최신 문서 동봉, 쓰기 0)
  5. 쓰기 — `create`: 문서 생성(`createDocFromCandidate`, revision 1) / `restart`: `auto·restart` 스냅샷 + 문서 교체(**revision = 현재 + 1** — 1로 되돌리지 않는다. 열려 있던 편집기 탭의 다음 `saveDoc`가 `STALE_DOC`로 걸려야 한다) + 멱등 기록 — **한 트랜잭션**(`commit` 실패 → 문서·스냅샷·기록 변화 0)
- **원자성**: 메모리 구현은 판정 3~5를 `await` 없이 한 동기 구간에서 한다(`delay` 주입은 `request`·`commit`·`response` 지점에만 — 판정과 쓰기 사이에 다른 요청이 끼지 않는다). 서버 구현은 조건부 쓰기(create = 없을 때만 삽입 · restart = revision 조건 갱신)로 같은 결과를 낸다.
- **화면 처리**(2a-04c "편집 시작", 12.3):

| 결과 | 화면 |
|---|---|
| 성공(처음 · 멱등 재생) | `/studio/:projectId`로 이동. 편집기는 **`getDoc`으로 최신 문서**를 연다 — 재생 결과에 담긴 문서 사본으로 그리지 않는다(재시도 사이에 저장이 있었어도 덮지 않음) |
| `DOC_EXISTS` | 이동 + 편집 알림 "이미 편집 중인 문서를 엽니다 (B안 · 프로필 v3)". **자동 `restart`로 넘어가지 않는다** — EQ-2 A "편집기 열기"로 수렴. 다른 안으로 새로 시작하려면 프로필에서 "C안으로 새로 시작"(EQ-2 A)을 다시 누른다 |
| `STALE_DOC`(`restart`) | 이동하지 않는다. 프로필 알림 `role=alert` "다른 곳에서 편집 문서가 바뀌었습니다(r8). 새로 시작하지 않았습니다 — 편집기에서 확인한 뒤 다시 고르세요" + 링크 "편집기 열기". 문서·스냅샷 변화 0 |
| `SCHEMA_INVALID` · `NOT_FOUND` · 실패 · 응답 실패 | 2a-04c 실패 문형 "편집을 시작하지 못했습니다 · 다시 시도"(`role=alert`). "다시 시도" = 같은 인자 → 멱등 |

- `restart`가 이긴 뒤 열려 있던 편집기 탭은 다음 저장에서 `STALE_DOC` → E-S09(내 편집은 화면에 그대로, "내 편집으로 저장"/"다른 편집 불러오기").
- (r4 — Q-17 A) 8.3은 저장소 계약이다. 판정 5 `create` 쓰기의 `createDocFromCandidate`는 8.2 3인자 모양이고, 생성 잡 결과 → 엔진 입력 변환·변형 매핑·`DocStart` 값은 **8.2.1 어댑터**가 맡는다(`startDoc` 인자는 그대로).

### 8.3.2 `requestExport` 스냅샷 책임 · 판정 순서 (r1 — Codex j1 medium)

"내보내기 전" 스냅샷 책임은 **저장소 한쪽**(`requestExport` 안)이다. 화면(5.13)은 스냅샷을 만들지 않는다 — 둘 다 만들면 내보내기 1회에 스냅샷 2개, 재시도마다 사본이 쌓인다.

- **멱등 키** = (`projectId`, `format`, `docRevision`). 기록 범위 = 프로젝트·형식마다 마지막으로 잡을 만든 요청 1건. **쓰기 0인 결과(아래 3~7)는 기록하지 않는다** — 결정적이라 다시 판정해도 같은 결과다(r4.8: 7은 같은 빌드의 렌더 레지스트리 안에서 결정적).
- **판정 순서**(8.3.1과 같은 형식):
  1. 모양 — `format` 값 · revision 정수 → `SCHEMA_INVALID`
  2. 멱등 키 — 마지막 기록과 같으면 **이전 결과(같은 잡)**. 스냅샷을 새로 만들지 않는다. 그 잡이 재시도 가능 실패(`JOB_TIMEOUT`·`INFRA`)로 끝났으면 **같은 잡을 다시 실행**한다(새 잡·새 스냅샷 0 — 첫 요청의 스냅샷을 그대로 가리킨다)
  3. `NOT_FOUND` — 프로젝트·문서 없음
  4. `STALE_DOC` — `docRevision` ≠ 저장된 revision(저장 전 변경을 내보내지 않는다 — 화면은 저장 먼저, 5.13)
  5. `GATE_FAILED` — 저장된 문서로 서버 게이트(`runGate`)를 다시 돌려 차단 1건 이상
  6. `GENERATOR_UNAVAILABLE` — **요청 형식의** 생성기 없음(EQ-1 A). 사용자가 고칠 수 없는 환경 조건이지만, 게이트 뒤에 두어 생성기가 생겼을 때와 같은 차단 안내를 먼저 받게 한다. (r4.8) M2a부터 `static-html`은 브라우저 생성기가 생겨 이 단계를 지나고, `react-zip`은 생성기가 생길 때(M4, 또는 Opus B-7-7 성립 시 M2b)까지 여기서 끝난다
  7. **(r4.8 — D6-4) `UNRENDERED_SECTIONS`** — 저장된 문서에 **렌더러가 없는 섹션이 1개 이상**(판정 = 그 빌드의 렌더 레지스트리에 `type+variant`가 없음). 결과에 개수와 `instanceId` 목록(문서 순서)을 싣는다. 폴백(와이어프레임)이 정적 HTML·zip에 섞여 나가지 않게 한다. 6단계 뒤에 두는 이유: 생성기가 없는 형식에서 "섹션을 바꾸라"는 안내는 풀 수 없는 조건을 고치게 만든다. 사용자가 고칠 수 있는 차단이지만 게이트(5단계)와 성격이 달라 게이트 줄(R-01~)로 넣지 않는다 — 렌더러 커버리지는 문서 품질이 아니라 제품 진행 상태다
  8. 쓰기 — `auto·export` 스냅샷 + 잡 생성 + 멱등 기록 — **한 트랜잭션**(`commit` 실패 → 스냅샷·잡·기록 변화 0)
- (r4.8) D6-4 원문은 "`GENERATOR_UNAVAILABLE` 자리를 '렌더러 없는 섹션 N개' 사유로"다. `react-zip`이 M2a 뒤에도 생성기 없음으로 남으므로 **자리를 바꾸지 않고 바로 뒤 단계로 더했다**(Jarvis 해석 → 영환님 승인 2026-10-03). PNG는 이 판정 순서 밖이다(5.13).
- **결과 모양**: 잡 + 첫 쓰기가 만든 "내보내기 전" 스냅샷 id·이름 + **이번 호출이 썼는지 여부**(멱등 재생·재실행이면 아님). E-S27 완료 문구의 스냅샷 이름과 9절 `snapshot_created`(썼을 때만)가 이것을 쓴다. 8.1 `ExportJob` 필드는 바꾸지 않는다(호출 결과의 모양이다).
- 결과: 판정 3~7은 **스냅샷 0 · 잡 0**. 같은 revision으로 연속 내보내기 = 스냅샷 **+1 이하**(첫 쓰기 1회만).
- EQ-1 A와의 관계: 결정(흐름·게이트 연동·자동 스냅샷·잡 인터페이스)은 그대로다. 자동 스냅샷은 8단계(r4.8 전 7단계) 트랜잭션 안에 있고, 판정이 먼저라 생성기 없음 경로에서 0개가 될 뿐이다(결정 변경 아님 — EQ-8 불필요).
