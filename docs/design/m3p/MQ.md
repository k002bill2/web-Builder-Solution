## MQ-M3P-1 썸네일 생성 방식 (빌드 파이프라인 변경 포함)

| 선택지 | 내용 | 트레이드오프 |
|---|---|---|
| **★A** | 빌드 시 킷을 서버 렌더해 **SVG(foreignObject) 실렌더 파일** 생성 → 카드 `<img loading="lazy">` | 추정 위험(r2): SVG-in-img에서 킷 `@media` 42개가 이미지 크기 기준으로 평가될 수 있음·중첩 svg 네임스페이스 → 빌드에서 `@media` 1280 기준 해소 + 네임스페이스 보존 직렬화를 S0 통과 조건으로(SPEC 3절). 사실: 킷·`PageDocument`에 effect·window·document 사용 0(grep), `react-dom/server`는 기존 react-dom 패키지에 포함 → **새 의존성 0, 바이너리 커밋 0**. 대가: `package.json` `build`에 단계 1개·vite SSR 모드 추가(이 승인에 포함), 썸네일 글꼴 = 시스템 대체 글꼴(사이트 글꼴 파일 1개 350KB대라 내장 불가 — 사실). 추정: SVG 장당 gzip 12~18KB, `/catalog` 첫 화면 +0.02~0.10KB |
| B | preview에서 Ego Lite로 기존 PNG 캡처 경로를 돌려 **PNG를 저장소에 커밋** | 사이트 글꼴까지 정확. 대가: 바이너리 약 0.6~1.5MB(추정) 커밋, 킷·생성기 바뀔 때마다 사람이 재캡처·재커밋(갱신 누락 위험), 바이트 비결정 |
| C | 카탈로그에서 **런타임 캡처**(숨은 렌더 iframe → canvas) | 저장소 0. 대가: 캡처 청크 +10.05KB(사실)·렌더 JS 84KB를 카탈로그 진입마다 받음(ADR-004 개정 2 "우회 금지" 취지 충돌), 카드 21장 순차 캡처 수 초(추정), 새로고침마다 반복 |
| D | 경량 SVG **와이어**(섹션 블록)로 정교화만 | 가장 쌈. 대가: 실렌더가 아님 → M3′ 목표("실렌더 썸네일") **범위 축소** 결정이 됨 |

- 사전 생성 PNG를 헤드리스 브라우저로 빌드에서 만드는 안은 **제외**: Playwright·Puppeteer 설치 금지(사용자 전역 규칙) + 새 의존성.
- A가 S0 스파이크(정적 마크업 ≠ 실제 렌더)에서 실패하면 레인이 멈추고 B/C 중 재결정을 요청한다.

## MQ-M3P-2 대상 업종·개수 (FR-CAT-06 "베타 5업종 × 4")

사실: 개발계획 187행의 베타 5업종 제안(병·의원 / 음식·카페 / 교육·학원 / 제조·B2B / IT·스타트업)은 코드 `IndustryId`(cafe-fnb·beauty·medical·fitness·professional·education·retail)와 다르다 — 제조·IT 코드 없음. 기존 6개 = cafe 2·beauty·medical·fitness·professional 각 1.

| 선택지 | 내용 | 트레이드오프 |
|---|---|---|
| **★A** | 기존 코드 안 5업종(cafe-fnb·medical·education·professional·beauty) 각 4개 → **생성 15 · 총 21**(fitness 1 유지) | 업종 코드·필터·라벨 변경 0(첫 화면 예산 영향 0). 베타 제안의 제조·IT는 professional로 흡수되지 않음 |
| B | 업종 코드에 `manufacturing-b2b`·`it-startup` 추가 후 제안 5업종 × 4 | 제안과 정확히 일치. 대가: `IndustryId`·필터 라벨·칩(첫 화면 청크) 변경 → 첫 화면 여유 0.35에 부담(추정 +0.05~0.15), 기존 테스트 추가 영향 |
| C | 7업종 전부 × 4 = 총 28(생성 22) | 필터 어느 업종도 4개. 대가: `/compare` 진입 여유(추정 0.6 → 음수 가능) — MQ-7 분리 청크가 필수 |

## MQ-M3P-3 레퍼런스 데이터 필드 (도메인 타입 확장)

사실: TRD 4.1에 `source_kind enum[library_composition, licensed_asset]`·`thumbnail_key`가 이미 있다. 앱 `DesignReference` 타입에는 없다. 생성 레퍼런스는 측정 점수가 없다.

| 선택지 | 내용 | 트레이드오프 |
|---|---|---|
| **★A** | 앱 타입에 `sourceKind` 추가(TRD 4.1과 같은 뜻) + `scores`를 "측정됨 | 미측정" 합 타입으로 | TRD와 일치, 정직한 표기. 대가: 점수를 읽는 곳(카드·정렬·상세·비교 셀) 분기 추가 — M3P-1·3에서 처리. 엔진·PageDoc 계약 변경 0 |
| B | 타입 변경 없이 id 접두어 `gen-`로 구분 + 점수는 임의 기본값 | 코드 변경 최소. 대가: 지어낸 점수 노출(FR-CAT-02 "측정일 표시" 위반) — 비추천 |

## MQ-M3P-7 생성 데이터 로딩 위치 · 예산 (r2 — Codex r1 P1로 재작성, **기동 차단**)

사실: 카드·상세 픽스처는 `main.tsx`가 **모든 라우트에서** 받는다(`check-bundle-size.mjs` `EAGER_DYNAMIC`가 /catalog·/references·/compare·/profile·/projects·/studio 전부에 들어감). `/studio` 진입 128.62 — 판정선 128.70까지 **0.08**. `/catalog` 첫 화면 여유 0.35. 추정: 생성 15개 3벌을 기존 파일에 붙이면 모든 라우트 +약 6~9KB → `/studio` 즉시 초과.

| 선택지 | 내용 | 트레이드오프 |
|---|---|---|
| **★A** | 생성 데이터 = **별도 청크**, 로더는 **카탈로그·상세 라우트 쪽**에 두어 `/studio`·`/profile`·`/projects` 증가 0 목표. 비교 보드는 생성 레퍼런스가 담겼을 때만 조건부 로드. M3P-1 S0에서 배치 실측 → `/studio` 128.70 또는 `/catalog` 첫 화면 99.90을 넘으면 멈춤 보고 | 예산 상향 0. 대가: 저장소가 "큐레이션 + 생성" 두 출처를 합치는 로직·로딩 상태 1개 추가, 배치가 까다로움(실패 시 B로) |
| B | ADR-004 개정(예: 상쇄 레인 선행 또는 공통 지연 저장소 증가분 한정 판정선 조정) 후 기존 파일 경로에 병합 | 구현 단순. 대가: 상향 선례 누적, 개정 5 "다음 상향 금지 조건"(구조 점검 재실행)과 부딪힘 |
| C | 생성 레퍼런스를 카탈로그 전용(비교 추가 불가)으로 축소 | 예산 안전. 대가: 벤치마크 → 비교 흐름이 끊김(SPEC 1절 목표 위반) — 비추천 |
