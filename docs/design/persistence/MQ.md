# PERSIST MQ — 문서 영속 결정 항목 (영환님 회신용)

- 근거: `docs/design/persistence/ADR-007-DRAFT.md` · `dev/active/persist-adr/FACTS.md`. [L1] 코드·문서 확인 · [L3] 외부 일반 지식(네트워크 확인 안 함) · [추정] 측정 없음.
- 회신 형식 예: "P0 A · P1 A · P2 A · P3 A · P4 A · P5 A · P6 A · P7 A"
- ★ = 추천. 새 의존성·백엔드·계정·외부 서비스·개인정보·예산은 모두 여기서 결정한다.

| 선택 | 내용 | 얻는 것 | 잃는 것 |

| **A ★** | (a) 브라우저 IndexedDB 먼저(P1) → (b) 파일 묶음(P2) → (c) 서버는 별도 ADR | 서버·계정·비용 0으로 새로고침 생존 · ADR-001 부합 · 인터페이스 불변 | 다기기·공유 없음 · 브라우저 축출 위험(파일 백업으로 보완) |
| B | (b) 파일 묶음만 | 가장 작음 · 디스크 잔존 없음 | 새로고침 생존 0(매번 파일 열기) — 문제를 풀지 못함 |
| C | (c) 서버 영속 바로 | 다기기·공유(FR-CMP-04·PUB-06 P1) | 계정·호스팅·비용·처리방침·운영 · ADR-001 관계 결정 선행 · 가장 긺 |
| D | 지금 유지(탭 메모리) | 구현 0 | B-M2C-03 계속 |

## MQ-P1 — 공용 PC 개인정보: 로컬 저장을 기본으로 켤까 (MQ-C2 ★A 근거를 뒤집는 결정)

- [L1] MQ-C2 ★A의 장점 중 하나가 "공용 PC에 사진이 남지 않음"이었다. IndexedDB는 탭을 닫아도 디스크에 남는다.
- [L1] 저장 이미지는 재인코딩 변형본이라 원본 EXIF(GPS 등)는 저장되지 않는다 — 남는 것은 사진 내용 자체와 문서 텍스트.

| 선택 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 기본 켜짐 + 저장 상태에 "이 브라우저에 저장됨" 상시 표시 + "이 브라우저 데이터 지우기"(확인 대화상자) + 첫 저장 때 1회 안내 | 대부분 사용자 기대(새로고침 생존)와 맞음. 공용 PC 사용자는 직접 지워야 함 |
| B | 기본 꺼짐, 프로젝트별 "이 브라우저에 저장" 켜기 | 개인정보 보수적. 켜지 않은 사용자는 지금과 같이 소실 — 문제 해결이 반쪽 |
| C | 문서·스냅샷은 기본 켜짐, 이미지만 선택 켜짐 | 사진만 보호. 이미지 없는 문서 복원 = 잃은 이미지 경로 상시화(MQ-S1의 지적과 반대 방향) |

## MQ-P3 — 스냅샷 보존·삭제 정책 (영속하면 무한 누적)

- [L1] 지금 스냅샷은 상한·삭제가 없다(2a-05 5.11). 메모리에서는 탭 수명이 상한이었지만, 영속하면 디스크와 스냅샷이 붙잡은 이미지(탭 한도 거부 메시지 ③)가 계속 늘어난다.

| 선택 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | 수동 스냅샷은 삭제 가능(확인 대화상자) · 자동(내보내기 전·복원 전·충돌 보존·새로 시작 전)은 프로젝트당 최근 20개만 보존(오래된 자동부터 정리) · 2a-05 5.11 개정 | 디스크·이미지 한도 회복. SPEC 개정 1건 + 화면 1건 |
| B | 지금처럼 삭제 없음, 프로젝트 삭제로만 정리 | SPEC 불변. 장기 사용 시 이미지 한도 거부가 늘어남 |
| C | 수동 삭제만 추가, 자동 상한 없음 | 중간. 자동 스냅샷 누적은 그대로 |

## MQ-P5 — 번들 예산 (`/studio` 진입 여유 0.07KB, 개정 8 배분 끝)

- [L1] 실측 128.51 · 판정선 128.58. 저장 코드는 모두 지연 청크로 두지만, 대기 Promise·`"local"` 문구 분기·떠나기 경고 조건은 진입에 닿는다. 최근 레인 추정 대비 실측이 2~10배였다(ADR-004 개정 5·6) — 이 문서는 KB를 추정하지 않는다.

| 선택 | 내용 | 트레이드오프 |
|---|---|---|
| **A ★** | P1-E0 스파이크로 실측 먼저. 128.58 안이면 진행, 넘으면 멈추고 그 실측으로 예산 개정 MQ 재상신(ADR-004 개정 4 결정 3 구조 점검 포함) | 근거 있는 결정. 1레인 지연 가능 |
| B | 지금 `/studio` 기준선을 +0.3KB 미리 배분(판정선 128.88, 한도 129 안) | 바로 진행. 추정 기반 배분 — 개정 5·6 반복 위험 |
| C | 상쇄 레인을 먼저 돌려 여유 확보 후 진행 | 예산 불변. 상쇄 몫 불확실 |
