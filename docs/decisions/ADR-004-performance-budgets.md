# ADR-004 — 앱 성능 예산과 생성 홈페이지 예산 분리

- 상태: **승인** (영환님, 2026-09-25 Slack 선택 1) · 개정 1 승인(2026-09-26) · **개정 2 승인(2026-10-03 — 결정 D6-2 + 세부 조건 결정 3·5, 영환님 "★A, 확인 1~3 승인")**
- 작성: Jarvis

## 배경
TRD 8절의 "초기 JS ≤ 90KB gzip"은 **생성되는 홈페이지(export)** 성능 예산이다. M1-UI-01-FIX는 이 값을 Design Studio 앱에 적용해 공통 청크(`index`)만 측정했다(87.3KB). 첫 화면에 실제로 받는 JS 합계는 카탈로그 95.3KB, 상세 93.5KB다.

## 결정
| 대상 | 측정 | 예산 |
|---|---|---|
| **Design Studio 앱** | 라우트별 **첫 화면 JS 합계**(공통 청크 + 해당 라우트 청크, gzip) | **≤ 100KB** |
| **Design Studio 앱** (2026-09-26 개정) | 라우트별 **진입 직후 자동 로드 포함 합계**(첫 화면 합계 + 조작 없이 바로 받는 dynamic import, gzip) | **≤ 125KB** |
| 생성 홈페이지(export) | 초기 JS gzip | ≤ 90KB (TRD 8절 그대로) |
| **렌더 문서**(`render.html`, 편집기 캔버스 iframe) (2026-10-03 개정 2) | 렌더 엔트리의 **진입 직후 자동 로드 포함 JS 합계** · 같은 범위의 **CSS 합계** (gzip) | **JS ≤ 90KB · CSS ≤ 30KB** (생성 홈페이지 예산, TRD 8절 277행) — 앱 예산과 **별도 판정** |

- `app/scripts/check-bundle-size.mjs`는 라우트별 첫 화면 합계를 **예산 대상**으로 검사하도록 바꾼다(현재 공통 청크만 대상, 라우트 합계는 참고 출력). 다음 Developer handoff에 포함.
- 라우트가 늘면 각 라우트가 예산을 지켜야 한다. 초과 시 빌드 실패.

## 개정 1 (영환님 2026-09-26 Slack 선택 1)
- 배경: M1-UI-03b에서 `/compare` 정적 합계 99.93KB(여유 0.07KB), 보드 엔진을 데이터와 함께 지연 로드해 **진입 직후 실제 합계 120.51KB**. 정적 합계만 보면 지연 로드로 예산을 우회할 수 있다.
- 결정: 정적 합계 **≤ 100KB 유지** + 라우트별 **진입 직후 자동 로드 포함 합계 ≤ 125KB**를 실패 조건으로 추가(참고 출력 → 검사). M1-UI-03b 보완에서 적용.

## 개정 2 — 렌더 문서 예산 분리 (영환님 2026-10-03 D6-2 확정 · 문안 Jarvis)

- 근거 문서: `docs/06-handoff/REF-LLM-PIPELINE_BRIEF.md` D6-1·D6-2 · `docs/00-research/buzz/claude-opus-5.5-r2.md` B-1(③ 설계 요점 2~4)·B-7-2.

### 배경
- M2a(VS-1)는 편집기 캔버스를 실제 섹션 렌더로 바꾼다. 렌더러는 **별도 렌더 문서(iframe, `sandbox="allow-scripts"`)** 로 확정됐다(D6-1).
- `/studio/:projectId` 진입 직후 합계는 **124.31 / 125KB**다(`dev/active/editor-a3-2/REPORT.md:41-44`). 멈춤선 0.3KB를 지키면 실제로 쓸 수 있는 여유는 약 0.39KB다. 섹션 킷(컴포넌트 + 킷 CSS + 토큰 CSS 주입)은 이 안에 들어가지 않는다.
- 렌더 문서는 "내보낼 사이트의 런타임 + 편집기 다리"다. 앱 UI가 아니므로 앱 예산이 아니라 생성 홈페이지 예산으로 판정하는 것이 맞다.

### 결정
1. **렌더 문서는 생성 홈페이지 예산으로 따로 판정한다.**
   - JS: `render.html` 엔트리 청크와 그 정적 import 전부 + 렌더 문서에서 조작 없이 바로 받는 dynamic import → **≤ 90KB gzip**.
   - CSS: 위 JS 범위가 싣는 CSS 파일 전부(미리 컴파일한 킷 CSS 포함) → **≤ 30KB gzip**.
   - 렌더 문서에서 사용자 조작 뒤에만 받는 코드(예: PNG 캡처)는 앱과 같은 분류 규칙으로 **예산 판정 밖, 크기만 출력**한다.
   - 단위·측정 방식은 앱과 같다(Node zlib 기본 레벨, KB = 1000 bytes).
2. **앱 예산 상수는 바꾸지 않는다.** 100KB · 125KB 그대로다. `/studio/:projectId`의 앱 예산에는 iframe을 띄우는 **호스트 코드**(프레임 · 메시지 브리지 · 선택·문제 오버레이)만 들어간다.
3. **우회 금지 — 개정 1의 취지를 유지한다.** 개정 1이 막은 것은 "지연 로드로 예산 계산에서 빠지는 것"이다. 이 개정은 코드를 빼는 것이 아니라 다른 상한(90 < 100)으로 옮겨 재는 것이며, 아래 조건을 지킨다.
   - **공유 청크는 양쪽에 다 센다.** 앱 엔트리와 렌더 엔트리가 함께 쓰는 청크(react 등)는 앱 라우트 합계와 렌더 문서 합계 **모두**에 들어간다. 어느 쪽에서도 빼지 않는다.
   - **앱 코드를 렌더 문서로 옮기는 것은 명시 항목만 허용한다.** 현재 허용 항목은 1건이다: 와이어프레임 폴백 그리기(`StructureCanvas`의 섹션 블록 · `features/studio/canvasLayouts.ts` 모양표·팔레트)를 렌더 문서 안의 폴백으로 옮기는 것. 옮길 때는 이동 전후 `/studio/:projectId`와 렌더 문서 합계를 **둘 다** 실측해 보고한다. 다른 앱 코드를 옮기려면 이 ADR을 다시 개정한다.
   - **렌더 문서는 렌더에 필요한 것만 싣는다.** 킷 컴포넌트 · 킷 CSS · 토큰 CSS 주입기 · 메시지 수신기 · 사각형 보고기 · `validatePageDoc`(과 그것이 쓰는 섹션 정의 레지스트리 — 데이터) · 위 폴백. 앱 DS 컴포넌트(`components/ds`) · 엔진 문서 연산 · 게이트 · zod는 싣지 않는다. 가드 테스트로 강제한다(`engineImportGuard.test.ts`와 같은 방식).
4. **이 예산은 실제 내보낸 사이트의 예산을 대신하지 않는다.** 렌더 문서는 편집기 다리·폴백을 더 실은 문서라 같은 상한이 더 엄격하다. 내보낸 정적 HTML·React zip은 TRD 8절 예산(JS 90 · CSS 30 · 폰트 ≤ 2계열 · 이미지 AVIF/WebP)으로 내보내기 단계에서 따로 판정한다(M2a 정적 HTML부터).
5. **번들 검사 스크립트를 렌더 엔트리 도입과 같은 브랜치에서 고친다**(M2a 첫 handoff).
   - 엔트리 판정을 이름으로 고정한다. 지금 `Object.keys(manifest).find(isEntry)`(`app/scripts/check-bundle-size.mjs:113`)는 엔트리가 하나라고 가정해, 엔트리가 둘이 되면 렌더 엔트리를 공통으로 잡아 조용히 틀린 값을 낼 수 있다. → 앱 = `index.html`, 렌더 = `render.html`. 그 밖의 엔트리가 manifest에 있으면 실패로 본다.
   - 렌더 문서 판정(JS 90 · CSS 30)을 SCENARIOS와 별도 항목으로 추가한다. 렌더 엔트리를 만든 커밋부터 `render.html`이 manifest에 없으면 실패로 본다.
   - 공유 청크 이중 계산(결정 3)을 스크립트 출력으로 보인다: 렌더 문서 합계 중 앱과 공유하는 파일 목록과 크기를 참고 출력한다.
   - 스크립트 머리 주석 9행("생성 홈페이지 예산은 이 스크립트의 대상이 아니다")을 개정 2에 맞게 고친다.

### 결과
- `/studio/:projectId` 진입 직후 여유(약 0.39KB 실사용)는 호스트 코드에만 쓴다. 폴백 이전으로 순감이 생기면 그 값도 실측으로 보고한다.
- 렌더 문서 합계가 90/30KB를 넘으면 빌드 실패다. 넘을 것으로 보이면 예산을 바꾸지 않고 멈춰 보고한다(앱 예산과 같은 원칙).
- 대체안(이 개정이 철회될 때): 캔버스 기본은 와이어프레임으로 두고 "실제 페이지 보기" 조작 뒤에만 킷을 받는다(Opus R2 B-1 "대체안"). 첫 화면이 와이어프레임으로 남는다.
