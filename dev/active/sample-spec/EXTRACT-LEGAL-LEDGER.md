# URL 기반 추상 디자인 특징 추출 — 법무 게이트 판단용 근거 원장

보고 대상: Jarvis / 최종 결정: 영환님
기준·조회일: 2026-10-25 KST. 법률 의견이나 적법성 보장이 아니라 공개 원문 기반 조사입니다.
대상: 사용자 입력 단일 URL에서 색 팔레트 값·글꼴 계열 이름·간격 리듬·섹션 구조 태그만 추출하여 새 시안의 출발점으로 제공하는 경로 B입니다. 브리프의 비저장·비재배포 전제는 구현 검증 사실이 아닙니다.

## 1. 결론 / 핵심 발견

리스크 등급: 중간 — 조건부 검토 가능, 공개 출시 법무 게이트 통과로 간주하지 마십시오. 아래 등급은 Newton의 정성적 판단이며 법원 판단이나 확인된 보안 취약점 등급이 아닙니다.

1. 추상적 속성만 추출하면 원본 표현을 복제·재현하는 방식보다 위험을 줄일 수 있습니다. 그러나 창작적인 선택·배열·구성은 보호 가능하므로 팔레트·폰트·정밀 구조를 합쳐 원본을 재현하면 별도 평가가 필요합니다. [추정, 신뢰도 중간][16][7][8]
2. 사용자 클릭 1회·공개 URL·영구 저장 없음은 포괄적 면책 조건이 아닙니다. 접근권한, 약관, 일시적 복제, 서비스 전체의 누적 수집을 따로 판단해야 합니다. [사실 및 적용 추정, 신뢰도 높음/중간][17][20][23]
3. 유사 도구의 존재는 상업적 이용 허락의 증거가 아닙니다. CSS Peeper는 원사이트 소유자의 명시적 허락 없이는 추출 속성을 개인·교육 목적으로만 사용하도록 약관에서 제한합니다. [사실, 신뢰도 높음][12]

### ★ 권고 허용 조건 — 다섯 가지를 모두 충족하는 제한 경로

★ 1. 접근 자격: 소유·관리하거나 추출 및 후속 상업 이용을 허락받은 사이트를 우선 허용하십시오. 그 밖의 공개 사이트는 약관상 허용 근거가 확인된 대상만 승인 목록으로 운영하는 보수적 출시를 권고합니다. 사용자 확인 체크는 보조 기록이지 원사이트 권리자의 허락을 대신하지 않습니다. 로그인·유료벽·CAPTCHA·접근거부·우회 필요 대상, GDWEB·dbcut·갤러리 수집은 차단하십시오. [정책 권고][11][19][20][23]

★ 2. 수집 범위: 사용자 명시 요청의 단일 페이지로 제한하고 링크 순회·자동 재방문·백그라운드 갱신·공동 갤러리화를 금지하십시오. 서버 fetch에는 식별 가능한 에이전트와 보수적 robots 존중 정책을 적용하고 도메인 단위 누적량·동시 요청도 통제하십시오. robots 조회·리디렉션·외부 CSS는 추가 요청이므로 ‘한 번 클릭’과 ‘총 HTTP 요청 1개’를 구분하여 PRD에 명시하십시오. 차단 신호나 불명확한 권한은 재시도·프록시 우회 대신 중단하십시오. 수치 한도는 법적 안전선으로 제시하지 않습니다. [정책 권고][1][10][18][20]

★ 3. 저장 범위: 결과 스키마를 팔레트 값·font-family 문자열·정규화한 간격 범주·통상적 섹션 태그로 제한하십시오. 이미지·로고·본문·HTML/CSS 원문·DOM 스냅샷·스크린샷·폰트 파일·원사이트 자산 URL을 결과/로그/캐시/외부 모델 입력에 남기지 마십시오. 원문 분석이 필요한 경우 처리 중 일시적 복제와 폐기 시점을 명시하고 법무 확인을 받으십시오. font-family를 추출해도 폰트를 자동 다운로드·핫링크·재호스팅하지 않고, 시안에는 별도로 사용권 확인된 폰트만 적용하십시오. [정책 권고][6][16][17]

★ 4. 표시·생성: 값과 일반적인 패턴 태그만 보여 주고 원본 화면·정밀 DOM 트리·요소별 좌표·동일한 섹션 순서를 복원하는 템플릿은 제공하지 마십시오. 생성은 독립 레이아웃·새 문구·허가 자산으로 하고 원사이트의 특징적 조합이나 브랜드 출처 혼동을 재현하지 않도록 하십시오. 출처 링크는 권리 허락이 아니며, ‘복제/클론’이나 제휴·보증을 암시하는 문구를 쓰지 마십시오. [정책 권고][3][7][9]

★ 5. 고지·중단: 추출 전 권한·약관 준수 확인, 결과의 비보증 고지, 권리자 신고·삭제·향후 차단 절차를 마련하십시오. ‘참고용’ 문구나 사용자 책임 전가만으로 운영자 책임이 사라진다고 표시하지 마십시오. 보관 정책과 후속 생성 정책을 함께 법무 승인받은 뒤 공개하십시오. [정책 권고; 책임 범위는 법무 확인 필요][12][17][23]

### 법무 확인이 꼭 필요한 질문

- 원문을 일시적으로 읽고 속성만 남기는 상업 서비스가 제35조의2의 필요 범위에 들어가는지, 그렇지 않다면 제35조의5 공정이용 또는 권리자 허락 중 어느 근거를 사용할 것인지요? 비저장만으로 충족된다고 가정하면 안 됩니다.[17]
- 원사이트 약관이 비회원·서비스 운영자에게 성립·편입되는 조건과, ‘접근’ 금지인지 ‘취득 정보 이용’ 금지인지 구분하는 검토 기준은 무엇인지요?[11][19][20]
- palette + font-family + spacing + section 순서의 어느 정도 구체성이 창작적인 배열·성과 사용 또는 출처 혼동 문제로 이어지는지요? 법적 임계값·안전한 유사도 수치는 [미확인]입니다.[3][16]
- 사용자별 1회 요청이 서비스 전체에서 누적되는 경우 제93조와 부정경쟁방지법 현행 (카)/(파)목을 어떻게 평가할 것인지요?[3][18][20]
- 미국 대상 제공 시 웹사이트 외관을 product design·packaging 중 어떻게 분류하고, 비기능성·식별력·혼동 가능성 및 준거법을 검토할 것인지요? Wal-Mart는 웹사이트 직접 판례가 아닙니다.[9]

## 3. 출처 간 충돌 / 오해하기 쉬운 차이

- 브리프의 ‘(카)목 성과도용’은 구법 번호입니다. 현재 성과도용 일반 조항은 (파)목이며, 현재 (카)목은 데이터 부정사용입니다. 과거 판결은 당시 번호로 읽고 현행 대응을 병기해야 합니다.[3][4]
- ‘레이아웃은 비보호’와 ‘창작적 배열은 보호 가능’은 서로 다른 대상을 말합니다. 미국 등록 실무·Darden의 일반 format과 구체 콘텐츠의 배열을 분리하고, 이를 한국의 홈페이지 전체 비보호 결론으로 수입하지 않습니다.[7][8][16]
- RFC는 REP를 인가와 구분하고 Google은 자사 사용자 요청 fetcher의 운용을 설명합니다. 서로 모순하는 법률 판단이 아닙니다. 본 서비스에서 robots를 존중하자는 권고는 보수적 운영 정책이며 RFC가 모든 사용자 트리거를 반드시 차단한다고 주장하는 것이 아닙니다.[1][10]
- CSS Peeper의 추출 제품 존재와 상업 이용 가능성은 다른 문제입니다. 실제 이용약관 제한을 마케팅 기능 소개보다 우선하여 읽었습니다.[12][21]
- 약관상 정보 이용 제한과 형사상 접근권한 제한은 같지 않습니다. 2021도1533은 이를 구분했으므로 ‘약관 위반 = 침입죄’ 또는 ‘형사 무죄 = 계약·저작권도 적법’으로 쓰면 안 됩니다.[20]
- 2026년 API 판결은 통상적 요소의 독점을 제한하는 보조 사례입니다. API·리뷰 데이터와 창작적 웹사이트 외관의 보호 범위가 같다는 근거로 사용하지 않습니다.[22]

## 4. 제외·한계 / [미확인]

1. [미확인] 한국 웹사이트 룩앤필·홈페이지 배열에 직접 대응하는 판결의 원문 및 사건별 최신 후속 판결. 관련 한국저작권위원회 상담사례 PDF는 검색되었으나 문서 추출 시간초과·직접 다운로드 HTTP 400으로 원문을 확보하지 못했습니다. 검색 요약과 잡지의 법률 해설은 판례 근거로 사용하지 않았습니다. 본 원장은 저작권법 제2조와 인접 대법원 판례에 기반한 제한적 판단입니다.
2. [미확인] 개별 색 조합·글꼴 선택·섹션 태그 조합의 보호 여부 및 안전한 추출 해상도. 개별 속성 이름을 붙였다는 사실만으로 창작적인 결합까지 제거되었다고 보지 않습니다.
3. [미확인] 본 구현의 메모리·네트워크·로그·캐시·외부 모델 전달·폰트 자동 로딩과 일시적 복제 적법성. 실제 사이트 추출, 저장소 실행, 네트워크 실험은 하지 않았습니다.
4. [미확인] 각 대상 사이트의 약관 동의·편입·준거법, 자동 접근 허용 여부 및 서버·브라우저 확장 경로의 책임 차이. 네이버·LinkedIn 두 사례는 일반 패턴의 예시이지 사이트 전체 시장 조사 결과가 아닙니다.
5. [미확인] CSS Peeper의 전체 통신 구조, Fontanello의 제3자 권리 이용 제한 약관, Stylify Me의 현재 배포 및 서비스 권리 고지. 공식 제품 설명·약관이 존재한다는 것과 준법성이 독립 검증되었다는 것은 다릅니다.
6. [미확인] 개별 상용 웹폰트 EULA, 명칭 관련 상표·브랜드 사용 제한, 미국 웹사이트 특화 trade dress 직접 판례·관할별 차이와 본 서비스의 준거법. 폰트 이름 기록이 파일 취득과 다르다는 점만으로 파일 라이선스가 해결되지 않습니다.
7. [미확인] 다수 사용자의 요청을 합친 도메인별 누적 추출이 DB·성과도용 요건에 이르는 지점과 권리자 요청 이후 운영 책임. 숫자상 안전선은 제시하지 않습니다.

제외 준수: 대량 크롤링·갤러리 수집·GDWEB·dbcut 조사·추출 실험·계정 생성·외부 발송을 하지 않았습니다. 정적 검색/HTTP 조회는 법령·판례·공개 설명·약관 문서 열람에만 사용했습니다. 원사이트 분석 기능은 실행하지 않았습니다.

원문 품질: 일부 web_extract 응답은 본문 중간을 생략하거나 아주 짧게 반환했습니다. 부정경쟁방지법과 네이버 약관 후반부는 동일 공식 URL을 curl로 정적 조회하여 보완했습니다. 2026년 API 판결은 반환된 발췌 범위만 인용했습니다. 일반 검색 요약은 최종 사실 근거로 승격하지 않았습니다.

## 5. Jarvis 전달용 사실 묶음

- Hemingway: ‘추상 디자인 속성을 참고하며 원본 자산·코드·브랜드를 복제하지 않는 제한 기능’으로 설명하십시오. ‘공개 사이트는 자유롭게 복제 가능’, ‘robots 미적용’, ‘저작권 문제 없음’이라고 쓰지 마십시오. 이는 위 근거에서 도출한 편집 권고입니다.[1][12][16]
- Designer: 색상·타입·간격 범주·일반 섹션 태그를 각각 제시하되 원본 정밀 배치·대표 화면·동일 순서 템플릿으로 묶지 않는 방향이 권고됩니다. 그 자체가 법적 안전을 보증하는 것은 아닙니다.[7][16]
- Developer: 접근·약관 승인 게이트 → 단일 페이지 수집 → 허용 스키마 검증 → 원문 폐기 → 권리 확인된 자산으로 새 생성의 경계를 PRD에 분리하십시오. 누적 수집 통제·차단 도메인·신고 중단을 운영 기준으로 명시하십시오. 구현·보안 검증은 이번 조사의 범위 밖입니다.[17][18][20]
- ADR-009 게이트 5: ‘중간 / 조건부 법무 검토 대기’가 권고 상태입니다. 법무가 접근 권한·일시적 복제·구체적 조합·상업 생성 경계를 승인하기 전 ‘법무 통과’로 표기하지 마십시오. 이는 본 조사 판단입니다.

### 고지 문구 초안 — 법무 승인 전 사용 금지

“이 기능은 접근·분석 권한이 있는 단일 공개 페이지의 제한된 디자인 속성을 참고 정보로 제공합니다. 원사이트의 이미지·로고·본문·코드·폰트 파일 이용권이나 원디자인 재현 허락을 제공하지 않습니다. 결과를 실제 서비스에 적용할 때에는 해당 사이트 약관과 관련 권리, 폰트 라이선스를 별도로 확인해야 합니다. 권한이 없거나 자동 접근이 금지된 사이트는 사용할 수 없습니다.”

이 문구는 법적 요건을 충족한다고 확인된 약관이 아니라 제품 고지 초안입니다. 실제 시스템이 비저장 조건을 이행하는지 검증하기 전 ‘저장하지 않습니다’라는 확정 문구를 추가하지 마십시오.
