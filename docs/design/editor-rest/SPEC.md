## 3. 재명세

### 3.1 테마 바꾸기 (2a-05 5.8 · E-S17·S18 대체)

**실렌더 이후 바뀐 사정**: 캔버스는 실렌더 iframe이고 색은 `docKitTokens(series, doc.profileVersion)`이 정한다(L1 `StudioLayout.tsx:300`). 즉 **버전 필드 하나만 바꾸면 캔버스·게이트(대비·목적 필수 섹션)·모션 판정이 모두 따라온다** — 별도 색 주입 작업이 없다.

- **연산(엔진 L4, 신규 2개)**: `swapTheme(doc, profileVersion) → doc'`(문서 `profileVersion`만 바꾼 새 문서 · 입력 불변) · `diffSlotValues(docA, docB) → 달라진 {instanceId, slotKey}[]`(meta 포함). PageDoc 계약 **변경 없음**(필드 추가 0) → MQ 아님. 소유는 Q-18 선례대로 L2 레인의 **범위 예외 엔진 파일**(PLAN 2절).
- **진입**: "테마" 영역(`ThemePanel`)에 버튼 **"테마 바꾸기"**(primary 아님, outline). E-S18: 문서 버전 < 계열 최신이면 캡션 **"프로필 v4가 새로 있습니다"** + 같은 버튼이 이유를 받는다(자동 적용 0).
- **대화상자(조작 뒤 청크)**: 네이티브 `dialog`(2a-05 5.15). 라디오 = 이 프로젝트 계열의 버전 전부(최신 먼저). 줄마다 **"v4 · 조정: 대비 강화 · 대비 통과"** / **"v1 · 대비 미달 2"**(대비 결과 = 그 버전으로 `contrastIssues` 개수 — 게이트와 같은 함수, 글자로). 현재 버전은 "지금 쓰는 테마" 표시 + 선택 불가 아님(고르면 "바꾸기" `aria-disabled` + 이유 "지금 쓰는 테마입니다").
  - **실렌더 미리보기를 대화상자 안에 두지 않는다**(MQ-R4 ★A): 적용 → 캔버스가 실렌더로 바로 보여 주고, "되돌리기"가 같은 자리에 있다. 3안 비교 화면처럼 버전 3개를 나란히 그리는 것은 렌더 iframe 추가 비용(렌더 JS 85.03KB/문서 — 빌드 로그)이라 하지 않는다.
- **적용**: `swapTheme` → `diffSlotValues(before, after)` → 0이면 편집 알림 **"테마를 프로필 v4로 바꿨습니다 · 슬롯 값 23개 모두 그대로입니다"** + "되돌리기"(Q7 알림 줄). 0이 아니면(결함) "슬롯 값 N개가 달라졌습니다: Hero 제목, …" + "되돌리기"(자동 되돌리기 0).
- **게이트 연동**: 적용 뒤 게이트 재계산(500ms, 기존 `useGateReport`). 목적이 바뀌어 필수 섹션 차단이 생기면 편집 알림 두 번째 문장 **"목적이 '예약'으로 바뀌어 필수 섹션 1건이 차단입니다"**(섹션 자동 추가 0).
- **되돌리기 경계**: 테마 바꾸기는 기록 스택 연산(3.5) · Q7 알림 줄 "되돌리기" 대상. 스냅샷 복원·자동 저장과 같은 문서 연산 경로.
- **"프로필 보기"** 링크에 `?v=<문서 버전>`을 붙인다(2a-05 5.8 원문 회복).
- **3안 비교와의 관계**: 테마 바꾸기는 **같은 안(candidateId)·같은 섹션 구조에 색·목적만** 바꾼다. 다른 안으로 바꾸기는 "새로 시작"(EQ-2 A, 프로필 화면)이고 이 SPEC 범위 밖(BACKLOG 후보 — 4절).

### 3.2 스냅샷 (2a-05 5.11 · E-S28~S30 대체)

**전제**: MQ-R1 ★A = 메모리(탭) 스냅샷을 지금 만든다 — 새로고침하면 프로젝트·문서와 함께 사라진다(서버 0, 기존 고지 문구와 같은 수명). 백엔드 영속은 MQ-R1 B·별도 ADR.

- **저장소(메모리 구현)**: `createSnapshot(projectId, name?)` · `restoreSnapshot(projectId, snapshotId, expectedRevision)` · `resolveConflict(projectId, choice, myDoc)`를 `memoryDocBook`(조작 뒤 청크 — 지금 export와 같은 자리)에 구현. 판정·트랜잭션은 2a-05 8.3 · E-AC-31 그대로(복원 = "복원 전" 자동 스냅샷 + 새 revision 한 트랜잭션, `commit` 실패 → 변화 0). id는 기존 관례 `snapshot-N`(store마다).
  - `resolveConflict`를 이 레인에 묶는 이유: 같은 스냅샷 쓰기 경로(충돌 보존 = `auto·conflict`)이고 지금 `missing`이다. 제품 흐름 도달은 여전히 어렵다(1.1) — **단위·컴포넌트 테스트로만 보증**(ER-AC-S5).
- **툴바 "스냅샷"**(≥1280 툴바, <1280 "더보기" 안 — 2a-05 4.2) → 대화상자(조작 뒤 청크): "지금 상태 저장"(이름 30자, 빈 값 = "수동 · 14:02") + 목록(이름 · 종류 글자 · 시각 · "프로필 vN · B안" · "미리보기"). 최근 10 + "이전 스냅샷 N개 더 보기".
- **미리보기(실렌더)**: 대화상자를 닫고 캔버스 iframe이 **스냅샷 문서**를 그린다(같은 렌더 경로 — 새 렌더 코드 0). 위 `Callout informative` "스냅샷 '수동 · 14:02'를 보고 있습니다 · 편집은 멈췄습니다" + "이 스냅샷으로 복원" · "편집으로 돌아가기". 편집 컨트롤 `aria-disabled` + 이유 "스냅샷을 보는 중에는 편집할 수 없습니다". **자동 저장·게이트 재계산 멈춤**(보는 문서는 편집 문서가 아니다). 게이트 패널은 편집 문서 기준 그대로 + 캡션 "스냅샷 보는 중 — 편집 문서 기준 결과".
- **이미지와의 관계(MQ-S1 A 전제 유지)**:
  - 스냅샷에는 로컬 id만 있다(`blob:` 0 — 2a-05 5.9). 보관소(편집 틀 state)는 그대로 편집기 수명이다.
  - **참조 집합 확장**: `retainedIds`를 **문서 ∪ 모든 스냅샷 ∪ 실행 취소 ∪ 다시 실행**으로 넓힌다(2a-05 5.9 원문 회복 — a3-3 T3의 축소를 해제). 편집기가 열려 있는 동안 스냅샷이 가리키는 이미지는 해제하지 않는다.
  - 탭 한도(24개·60MB) 거부 문장 "스냅샷이 이전 이미지를 보관하고 있어 더 넣을 수 없습니다"가 **처음으로 도달 가능**해진다(스냅샷은 지울 수 없다 — 2a-05 5.11). 문장·판정은 2a-05 5.9 표 그대로.
  - **복원 = 잃은 이미지가 생기는 둘째 경로**: 편집기를 떠났다 돌아온 뒤 복원하면 그 스냅샷의 이미지는 보관소에 없다 → m2c 잃은 이미지 표시(필드 "이미지를 다시 골라 주세요" · 캔버스 자체 그래픽 · 내보내기 개수 문구). 편집기 안에서 이미지 A → 스냅샷 → A 교체 → 복원이면 A는 참조 집합에 남아 있어 **잃지 않는다**.
- **복원 완료**: 편집 알림 "스냅샷 '…'으로 복원했습니다 · 복원 전 상태는 '복원 전 · 14:05'에 있습니다" · 포커스 h1(2a-05 6.4). 복원은 기록 스택 연산(3.5).

### 3.3 게이트 표시 — 차단을 편집기 안에서 푸는 길 (2a-05 5.12 보강)

원칙: **차단 줄마다 "편집기 안에서 누를 수 있는 다음 행동" 1개**. 글자 대체안만 있고 행동이 없는 줄을 남기지 않는다.
