## MQ-3-1 — B-RS-03: 미확인 쓰기를 어디서 이어받나

[사실 L1] 앱 안에서 `/studio/:id`로 가는 길은 세 가지다.
- 프로필 편집 시작: 미확인 기억이 이미 막는다.
- `/projects` 행 링크: `ProjectRow.tsx:52`.
- 브라우저 뒤로/앞으로.

편집기 저장 훅은 `idle`로 시작한다(`useAutosaveScheduler.ts:59`). 그래서 미확인을 알 길이 없고, 떠나기 경고·`leave()`도 없다. `/studio` 진입은 base 129.87 · 판정선 129.90(여유 0.03KB ≈ 30B)이며 판정선 수정은 금지다(BRIEF).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | **`/projects` 행 게이트**: 미확인 행은 "편집기 열기"를 숨기고 "저장 다시 시도"(같은 인자 `startDoc` 재생)를 둔다. 확인되면 링크를 되살린다(SPEC-3 5.2) | `/studio` 진입 0B · 저장소 계약 0 · RS-R7 주 경로 닫힘 | history 뒤로/앞으로 재진입은 남는다(RS3-R1). 편집 저장·복원·내보내기가 한 번 성공하면 닫힌다. **안전 경고(r2 P1-b)**: 그 전에 편집 저장이 실패한 채 목록으로 돌아가 새로고침하면 이전 IDB 문서는 남지만 새로 시작과 그 뒤 편집은 사라진다. 확인 전에는 그 프로젝트 편집기를 이 탭에서 못 연다(계속 실패하면 새로고침 안내) |
| B | **편집기 진입 인계**: 편집기가 기억 모듈을 읽어 저장 상태를 "미확인(실패)"으로 시작한다. 상태 글자·떠나기 경고·`leave()`·다시 시도(재생)·기억 삭제를 붙인다 | 모든 진입 경로를 닫는다 · 편집하면서 확인 가능 | `/studio` 일반·복원 진입 바이트가 는다. 초기 상태·가드·문구·재시도 배선 합이 30B 안에 들 가능성은 낮다(L3 — `useDocSave.ts:73` 주석은 `infra.ts` import 하나로 +0.76KB를 기록) → **판정선 상향(ADR-004 새 개정) 결정이 필요하다.** 고르면 구현 전 스파이크 실측 → 수치로 재상신 |
| C | 기록만(BACKLOG 유지), 문구로만 밝힌다 | 코드 0 | `/projects` 경로가 거짓 상태 그대로 남는다 |

근거: BRIEF "기존 권한·저장소 계약만으로 안전한 최소 수정" + "판정선 수정 금지". A는 두 조건 안에서 주 경로를 닫고, 남는 경로(history 재진입)는 저장 1회 성공으로 닫히지만, 그 전 새로고침에는 저장을 확인하지 못한 편집이 사라질 위험이 있다(안전 경고 — 해결하지 않고 밝힌다).

## MQ-3-2 — B-RS-02: create도 커밋 전에 잠금을 확인할까 (SPEC r2 MQ-S2 C 승격)

[사실 L1] create는 메모리 커밋 → flush 순서다(`memoryProjectRepository.ts:65-66,121-122`). 잠금 없는 탭에서는 메모리에만 문서가 생기고, 같은 안·다른 버전 재클릭 시 IDB에 없는 문서로 편집기가 열린다(SPEC-3 2.2). 지금 동작은 `restartLock.test.ts:136`이 고정한다.

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | restart와 같은 `guardWrite()`를 create에도 건다. 단 **메모리에 문서가 없을 때만**이다(조건 `(mode === "restart" || !docs.docOf(projectId))` — 저장된 문서 열기·F4 진입 회귀 0, Codex r1 P2). 잠금 소유자는 탭당 `LocalSync` gate 하나이고 흐름별 잠금은 0이다 | 갈라짐 0 · 진입 바이트 수 바이트(실측 필수) · 인터페이스·스키마 불변 | **저장소 내부 순서 변경**(MQ-S2 A와 같은 종류) · 기존 단언 유지(`restartLock.test.ts:136-142`) · 읽기 전용 탭에서 "저장 안 되는 편집기"로 가던 길이 막힌다(RS3-D5) |
| B | 계약 그대로 두고 문구만 정직하게("탭 안에서는 만들었지만 저장되지 않았습니다") | 코드 최소 | 갈라짐이 남는다 · IDB에 없는 문서 편집기 진입이 남는다 |

## MQ-3-3 — create 커밋 뒤 실패를 어떻게 말할까

[사실 L1] 가드를 넣어도 flush INFRA(quota·중단·cleared)와 응답 단계 실패는 커밋 뒤에 난다. 응답 단계 실패에서는 flush가 0번 실행된다(`memoryProjectRepository.ts:66,79-81`). 지금 문장은 "편집을 시작하지 못했습니다"이다(`restartFlow.ts:51`).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | restart 3.3.1과 같은 **커밋 확인 → 사유** 순서(`DOC_EXISTS`만 예외). 양성이면 C-E4 "미확인" + 기억, 불가면 C-E5, 음성이면 사유별(C-E2·2b·2c·3) | 결과를 단정하지 않는다 · restart와 같은 규칙 · 다시 시도 중복 0 | 실패 때 `getDoc` 1회(조작 뒤) · 문장 5개 추가(조작 뒤 청크) |
| B | 커밋 뒤도 일반 실패 문장 + 다시 시도 | 코드 최소 | 거짓 "변화 0" 문장이 남는다 |

## MQ-3-4 — 미확인 상태에서 새로고침·탭 닫기 경고를 넣을까

[사실 L1] 편집기는 `idle`·`saved`이면 `beforeunload` 경고를 하지 않는다(`useAutosaveScheduler.ts:67-70`). 프로필·목록 화면에는 언로드 가드가 없다. 미확인 쓰기는 새로고침하면 사라지고 메모리와 IDB가 일치한다(이전 IDB 문서는 보존된다. 그러나 저장을 확인하지 못한 새 문서·새로 시작·후속 편집은 사라질 수 있다 — r0.2 정정, "내용 손실 0" 단정 삭제).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | 경고 없음. 문장(R-E4·C-E4·P-U5)이 미리 밝힌다 | 진입 바이트 0 · 브라우저 기본 경고창 남발 0 | 문장을 읽지 않은 사용자는 새로고침으로 새로 시작을 잃을 수 있고, 편집 저장이 실패한 뒤라면 그 편집도 잃는다(r2 P1-b로 정정 — 이전 IDB 문서는 보존) |
| B | 기억이 있는 동안 `beforeunload` 경고 | 실수 새로고침 방지 | 등록 지점이 진입 청크(프로필·목록·편집기)라 바이트가 늘고, 편집기까지 넓히면 MQ-3-1 B와 같은 예산 결정 |
