기준·조회일: 2026-10-20 KST. 가격은 USD, 별도 표기 없으면 월 단위이며 세금·환율·도메인 등록비·구현 인건비를 제외합니다.

## 1. 결론 / 핵심 발견

1. ★ 단일 조건부 추천: M5 고객 사이트 호스팅은 Cloudflare Workers for Platforms(WfP) + R2를 우선 검증 대상으로 선택하고, 제품 저장소에는 최소 Linux GitHub Actions CI를 별도 신설하는 조합입니다. 이유는 wildcard Workers Route, R2의 강한 일관성, WfP의 End Users 대상 기능 제공을 명시한 약관 예외가 함께 확인되기 때문입니다. WfP 시작 가격은 $25/월이며 R2 사용료 등은 별도입니다. 단, 이는 채택 확정이 아니라 tenant별 원자적 release 전환·24시간 preview 만료·발행/rollback 성능을 검증한다는 조건의 판단입니다. 일반 Workers $5 플랜만으로 동일한 재판매 허용을 단정하지 않습니다.[17][28][30]
2. Cloudflare Pages 단독은 wildcard custom domain을 직접 지원하지 않습니다. Vercel은 wildcard와 빠른 rollback이 있으나 일반 multi-tenant preview URL은 Enterprise 전용이며, 일반 서비스 약관에는 재판매 제한이 있습니다. Netlify도 별도 서면 합의 없는 서비스 재판매 제한이 확인됩니다. 따라서 “기술적으로 SaaS 가능”과 “우리 사업모델이 해당 계약으로 허용됨”을 구분해야 합니다.[1][11][13]
   Netlify 제한의 직접 근거는 웹사이트 이용약관이 아니라 서비스 구독계약입니다.[41]
3. 어느 후보도 이번에 읽은 공식 문서만으로 M5의 발행 p95 ≤2분·rollback ≤1분을 계약상 보장한다고 판정할 수 없습니다. Vercel 문서는 rollback을 수초, Pages/Workers 문서는 즉시라고 설명하지만 이는 end-to-end p95 SLA가 아닙니다.[15][23][63] GitHub PRIVATE Actions 포함분은 Free 2,000, Pro/Team 3,000, Enterprise Cloud 50,000분/월이며 Linux 2-core 초과 단가는 $0.006/분입니다. “PRIVATE라 CI가 곧 유료”라는 전제는 틀립니다.[53]

시간 수용 기준 제안(추정): 이미 wildcard DNS/TLS가 준비된 상태에서 사용자 발행 클릭→validation→업로드→전환→외부 관측까지를 발행 시간으로 측정하고, 신규 도메인 DNS/TLS provisioning은 분리 계측합니다. DNS 추가·인증서 발급을 매 발행 critical path에 넣으면 문서의 “instant rollback”과 비교 자체가 어긋납니다.

## 3. 출처 간 충돌

1. Pages 사이트 무제한 vs100 projects: 공식 가격 랜딩은 `Unlimited sites`,현행 상세 limits는100projects/account·통상증액하지 않음이라고 명시합니다. 고객별 project 모델 판단에는 더 구체적인 limits를 적용합니다. 단일project 다중논리사이트 또는 다른 상품의 확장성과 혼합하지 않습니다.[12][64]
2. Pages paid100,000files vs create-deployment API20,000manifest entries: 서로 경로/클라이언트/설정 범위가 다를 수 있습니다. Paid100,000은 조건부이며 모든 raw API payload가100,000을 받는다고 확장하지 않습니다. 사용할 업로드 경로 확인 필요.[12][67]
3. Vercel Platforms 공식 multi-tenant 안내 vs 일반약관 third-party제공 제한: 기술 지원 문서가 계약 예외를 자동 생성하지는 않습니다. Pro로 우리 모델의 고객호스팅을 제공해도 되는지 [미확인];서면해석을 우선합니다.[1][11]
4. Cloudflare 일반 접근권판매 제한 vs WfP 특약: WfP에는 `Notwithstanding` 예외가 명시되어 있어 특약 범위의 End Users 제공을 더 강한 허용 근거로 채택합니다. 단 일반$5Worker+R2 전체에 예외를 확장하지 않습니다.[29][30]
5. Netlify “Deploy Previews unlimited/free” vs 트래픽 credits·예측URL: deployment 생성 자체0credits와 bandwidth/web request0원은 다릅니다. PR번호 URL의 unique는 unpredictable과 동의어가 아닙니다.[35][38]
6. GitHub 과거 OS배수 기억 vs 현재 SKU가격표: 구 URL도 현재 rate표를 반환합니다. 포함분 차감 배수는 [미확인]으로 남기고,현재 단가와 산술상 달러비율만 제공합니다.[53][54]
7. 요청문에서 보안헤더는 가점 vs TRD-SEC-08 필수문구: 제품정본 TRD는 보안헤더·서명·24h를 요구합니다. 최종ADR에서 이 항목을 정본수정 없이 가점으로만 낮추면 안 됩니다. 우선순위 충돌은 영환님 확인 필요(내부 정본 L290).
8. AWS를 PAYG-only로 비교하면 최신 flat-rate Free/Pro를 놓칩니다. 두 가격제도는 별도이며,standard distribution·SaaS multi-tenant distribution도 별도로 평가해야 합니다.[42][43][60]

## 4. 제외·한계

- Firebase Hosting은 선택범위라 제외했습니다. 필수4개 사업자와 Cloudflare 하위구성을 비교했으며,Firebase에 대한 우열 주장은 하지 않습니다.
- API·계정 생성·DNS변경·배포·트래픽시험·외부문의·결제는 하지 않았습니다. 2분/1분 성능·글로벌전파·TLS 초기발급·실제청구는 모두 [미확인]. “instant” 원문은 숫자SLA로 바꾸지 않았습니다.
- 사용자수·동시발행·사이트당 파일수/용량·보존버전수·월대역폭·GitHub plan/잔여분·DNS소유권이 없어 총비용·quota 충족 규모는 [미확인]. R2/S3 논리사이트수에 근거 없는 무제한 숫자를 붙이지 않았습니다.
- Vercel/Netlify raw service 재판매 제한은 확인했으나 통합웹빌더의 계약분류는 확인하지 못했습니다. AWS service-specific terms 전체·Cloudflare/Netlify 계정별 주문서·AUP의 모든 조항을 포괄 법률검토한 것은 아닙니다.
- Netlify wildcard는 공식support게시물로 기능조건을 확인했으나,현재credit-based Pro 계약에서도 동일조건으로 신규활성화되는지 [미확인]. 공식문서·가격페이지보다 증거등급을 낮췄습니다.
- GitHub 포함분의 최신OS차감배수는 영문공식문서에서 재확인하지 못했습니다. legacy1/2/10표를 현재사실로 쓰지 않았습니다. Linux-only 예산 예시는 이 불확실성을 회피합니다.
- 일부 URL404는 대체공식페이지로 회복했습니다(Workers rollback 경로, Vercel rollback API 문서명, AWS update distribution 문서명). 실패한 URL은 근거원장에 넣지 않았습니다. 검색snippet은 원문근거로 사용하지 않았습니다.
- 내용은조회일현재 공개원문 snapshot입니다. 이후가격/정책변경·계정별legacy플랜에는 자동적용되지 않습니다. source본문 개정일이확인되는 예: Vercel multi-tenant2026-09-08,Cloudflare Developer Platform특약2026-09-28,Netlify 서비스계약2025-10-01,AWS Customer Agreement2026-08-14. 계약문구는해당본문을우선합니다.[1][30][41] AWS 계약개정일은해당원문상확인.[52]

## 5. Jarvis 전달용 요약

Developer용 사실 묶음:
- Cloudflare Pages≠wildcard multi-tenant runtime. Workers Route를 검토하되자사wildcard TLS 깊이부터고정합니다.[13][17][31]
- R2 immutable release+tenant별active참조전환은설계안이지기성rollback상품이아닙니다. 캐시된포인터·외부asset우회·동시쓰기·구release보존을수용시험에넣어야합니다.[22][66]
- WfP user Worker에는일반Worker Version URL이없습니다. 고객preview는제품의난수/서명24h주소와모든asset만료검사를설계합니다.[27]
- 제품PR CI와고객publish gate를분리합니다. PRIVATE Actions포함분으로Linux CI를시작할여지가있지만현재GitHub plan/잔여분과private branch보호자격을확인해야합니다.[53][58]

Hemingway / Designer용 사실 묶음:
- “발행2분/rollback1분보장”,“preview주소만알면24h뒤자동비공개”,“고객사이트무제한무료”는현재확정카피로사용하지않습니다.
- 발행중·검증중·전환완료·실패·rollback완료상태를구분하는UI가필요하다는판단입니다. 작업API성공과방문자가보는버전검증을동일시하지않습니다.
- 단가요약은WfP$25+R2종량,일반Workers$5와별도,Vercel Pro$20,NetlifyPersonal$9/Pro$20부터,CloudFrontflat-ratePro$15/distribution입니다. 포함량과약관제약을반드시같이표시합니다.[3][19][21] WfP·Netlify·AWS의각가격근거.[28][33][42]

PM용 결정기록 초안(판단): 조건부추천조합을선택하더라도최종ADR상태는‘계약적합성확인·preview24h우회차단·발행p95/rollback실측통과전보류’로둡니다. 기존Vercel제품preview연동은고객사이트호스팅사업자선택과별건이므로이결과만으로이전/삭제하지않습니다.
