## 5. 검증 게이트 (Codex)
- `codex-companion review --scope branch --base fbc6803` 1라운드(`/tmp/wbs_codex_v22a_r1.txt`): **P2 1건**. Codex 쪽 Vitest는 샌드박스 파일 권한 때문에 실행되지 않았습니다(V2-1과 같음). 테스트 근거는 1절의 로컬 fresh 실행입니다.
- **[P2] 모바일 헤더 포커스 순서 ≠ 보이는 순서** (`AppHeader.tsx:28-29`) — **반영하지 않음(보류, 결정 요청)**.
  - 현상: <768에서 주 메뉴가 `order-last`로 둘째 줄에 보입니다. Tab 순서는 브랜드 → 메뉴(둘째 줄) → 새 프로젝트(첫 줄)입니다.
  - 반영하지 않은 이유: 주 메뉴를 한 벌만 두는 한(두 벌은 `getByRole` 충돌과 번들 증가), DOM 순서 하나로는 데스크톱(브랜드·메뉴·버튼 한 줄)과 모바일(브랜드·버튼 / 메뉴) 둘 다 맞출 수 없습니다. DOM을 모바일 기준으로 바꾸면 키보드 사용이 더 많은 데스크톱에서 같은 불일치가 생깁니다. 지금 순서(로고 → 메뉴 → 작업 버튼)는 의미상 논리적이라 WCAG 2.4.3의 "의미·조작 보존"은 충족한다고 판단했습니다(L2).
  - 대안: (a) 모바일에서 주 메뉴를 헤더 밖 첫 줄 아래 별도 영역으로 옮기되 DOM도 버튼 뒤에 두고, 데스크톱은 `md:` 절대 배치로 가운데에 놓기(레이아웃 복잡도·공통 청크 증가). (b) 모바일에서만 버튼을 둘째 줄로 내리기(목업과 더 멀어짐). Designer/영환님 판단이 필요합니다.
- 라운드 상한: 브리프 지시대로 1회만 실행했습니다.
