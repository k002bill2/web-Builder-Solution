## MQ-4-1 — history 재진입: 편집기가 미확인을 이어받을까

[사실 L1] 편집기 저장 상태는 늘 `idle`로 시작하고 초기 상태 옵션이 없다(`useAutosaveScheduler.ts:59,83`). 진입 state는 1번 읽고 지운다(`useStudioDoc.ts:48-56`). 선언형 라우터라 `useBlocker`가 없다(`routes.tsx:15-17`). `/studio` 진입 129.87 · 판정선 129.90(허용 0.03KB).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | **편집기 인계(CP4) — 예산 관문 조건부.** 진입 때 기억을 읽어 "저장 확인 전" 상태·"저장 확인" 버튼·경고로 시작, 저장 성공 시 기억 삭제, `failed`·`saving` 언마운트 시 `PendingRecord`. 스파이크 S2/S3(SPEC-4 9절)를 먼저 재고, 판정선 안이면 진행. 넘으면 감량 1회 → 그래도 넘으면 CP4 복원·중단·raw 수치로 재상신 | 모든 진입 경로에서 거짓 `idle` 0 · history 재진입 닫힘 · `/projects` `PendingRecord` 링크 복원 가능 | `/studio` 진입 바이트 증가(L3 — 30B 안에 들 가능성 낮음). 넘으면 **판정선 상향 결정**이 별도로 필요(이 MQ는 상향을 승인하지 않는다) |
| B | 인계 없음. `/projects` 게이트 + 모듈 수준 경고만 | `/studio` 0B | history 재진입 시 편집기가 거짓 `idle`을 보여 준다(경고는 있음). RS4-R1·R2가 남는다 |
| C | 인계 없이 편집기 진입 때 기억이 있으면 편집기 대신 안내만(차단) | 거짓 idle 0 | `/studio` 바이트가 A와 비슷하게 든다(조회 + 분기) · 사용자가 편집을 못 함 — 이득 대비 비용이 나쁨 |

## MQ-4-2 — `PendingRecord`의 "저장 확인"을 무엇으로 할까 (F2 수단)

[사실 L1] 확인 수단은 flush하는 쓰기의 resolve뿐이다(`localSync.ts:43-56` 인터페이스에 확인 메서드 없음). `kept`는 성공한 쓰기 뒤에만 현재 메모리 레코드 전체를 IDB 커밋까지 flush한다(`memoryProjectRepository.ts:65-66` · `localSync.ts:152-161`).

| 선택 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| ★**A** | `deleteSnapshot(projectId, "")` — 계약상 "없는 id = 변화 0으로 성공(재시도 멱등)"(`projectRepository.ts:157` · `memoryDocBook.ts:290-291`) | 인터페이스·스키마 변경 0 · revision·내용·스냅샷 변화 0 · 미확인 없으면 IDB 쓰기도 0(`writeQueue.ts:88-92`) · 같은 쓰기 문 잠금 규칙 | **의미 차용**(삭제 메서드를 확인에 씀). 빈 id가 영원히 없는 id여야 하고, 계약("없는 id = 성공 + flush")이 바뀌면 깨진다 → 계약 테스트로 고정(RS4-AC-13). 호출부는 `confirmRecord()` 한 함수로 감싸 이름으로 의도를 드러낸다 |
| B | 저장소에 `confirmDoc(projectId)`(flush만) 추가 | 의미가 정확함 | **새 인터페이스** — 이번 승인 밖 → 구현 차단, 별도 승인 필요 |
| C | 같은 내용 `saveDoc`(사용자 버튼으로만) | 기존 공개 쓰기 | 새 키면 revision +1(`memoryDocBook.ts:364`)·저장 세대 +1·다른 탭 `saved` 브로드캐스트(`localSync.ts:125-131,148`) — 사용자 편집 없는 변경 신호. 진행 중 편집기 `revisionRef`와 엇갈릴 수 있음 |

## MQ-4-3 — 조건부 인계 본문(S3)을 고를 때 새 측정 시나리오의 한도

[사실 L1] 조건이 있어도 자동 dynamic import는 예산 대상이며, 조건이 참인 시나리오를 따로 둬야 한다(`check-bundle-size.mjs:25`). 지금 목록에 "/studio (미확인 인계)" 시나리오는 없다.

| 선택 | 내용 |
|---|---|
| ★**A** | S2(정적)·S3(lazy) 둘 다 재고, S3를 고를 때만 이 질문을 다시 연다. 새 시나리오의 한도는 **수치를 본 뒤** ADR-004 개정으로 정한다(Designer가 한도를 정하지 않는다) |
| B | S3를 쓰지 않는다(S2만) |
