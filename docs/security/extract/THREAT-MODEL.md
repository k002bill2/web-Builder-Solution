## 3. 완화책 + 검증 방법

원칙: Zero Trust(응답·추출값 전부 불신) · Defense in Depth(사전판정 + 연결 시점 판정 + 정규화 + 앱 2차 검증) · Least Privilege(JS 끔·권한 최소·egress 제한) · Fail-Secure(판정 불가 = 차단).

| 위협 | 완화 | 검증(고정 픽스처·단위·계약 테스트) |
|---|---|---|
| T01·T02·T03 | ① URL은 WHATWG URL 파서 1회 파싱 후 **정규화된 host만** 사용, userinfo 있으면 거부 ② 스킴 `https:`만, 포트 443만(다른 포트 거부) ③ host를 **직접 resolve → 모든 A/AAAA**를 CIDR 거부 목록(T01·T02 전부 + `0/8`·`224/4`·`240/4`·`255.255.255.255`·IPv4-mapped/NAT64는 내장 IPv4로 다시 판정)과 대조, 하나라도 걸리면 전체 거부 ④ IP 리터럴 host는 기본 거부 ⑤ 판정 불가(파싱 실패·DNS 실패) = `unsafe_target` | 주소 표 픽스처(우회 표기 30+행: T03 목록 전부) → 전 행 `unsafe_target` 기대 · 판정 함수는 순수 함수(리졸버 주입)로 단위 테스트 |

## 4. 추출 결과 정규화 계약 (SAMPLE-SPEC 2.1 키 기준)

경로 B 정규화기 출력 = `design-tokens.json`의 **부분집합 + 출처 블록**. 규칙: **허용 형식만 통과 → 정규형으로 재직렬화 → 실패 항목은 삭제하고 `partial` 목록에 기록**(값 보정·추측 금지). 전체 출력은 정규화기가 새로 만든 객체.

| 키 | 허용 형식(정규형) | 거부 규칙 | 상한 |
|---|---|---|---|
| `$schema` | 상수 `"design-sample/tokens@0"` | 다른 값 = 파일 전체 거부 | — |
