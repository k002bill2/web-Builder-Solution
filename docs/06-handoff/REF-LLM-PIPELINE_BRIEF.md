## 1. 제품에 dbcut 크롤링 자료를 넣지 않는 근거

| 항목 | 내용 | 수준 |
|---|---|---|
| robots.txt | `Googlebot`·`Bingbot`·`Yeti` 등 검색엔진만 `Allow`. `ClaudeBot`·`GPTBot`·`ChatGPT-User`·`Google-Extended`·`Bytespider`는 `Disallow: /` — AI 용도 수집 거부 의사가 명시적 | [사실] 2026-09-28 `https://www.dbcut.com/robots.txt` 직접 조회 |
| 이용약관 제12조 | "게시물의 저작권은 게시자 본인에게 있으며 회원은 서비스를 이용하여 얻은 정보를 가공, 판매하는 행위 등 서비스에 게재된 자료를 상업적으로 사용할 수 없습니다." | [사실] `https://www.dbcut.com/content/provision` 직접 조회 |
| 캡처 속 디자인의 권리 | 캡처된 디자인의 저작권은 dbcut이 아니라 각 원 사이트에 있다. dbcut 허락을 받아도 해소되지 않는다 | [추정] 법무 확인 대상 |
| 우리 정책 | PRD 4절 원칙 2(타 사이트 이미지·문구 금지) · 원칙 5(외부 URL 스크린샷 수집 MVP 제외) · FR-SEL-06(URL 모사 입력 없음) · CLAUDE.md 규칙 6 · TRD 238행 | [사실] |

같은 판단을 GDWEB에 이미 적용했다 (PRD 39행, robots `Disallow: /`·약관 제13조). dbcut은 같은 부류로 취급한다.

**개인 비상업 사용일 때 달라지는 점** (D5의 전제):
- 약관 제12조는 **상업 사용**을 금지하므로 개인 비상업 열람·보관에는 직접 걸리지 않는다 [사실: 조항 문구].
- 캡처 보관은 저작권법 사적 이용 복제 범위에 들 가능성이 있다 [추정, 법무 확인].
- robots의 AI 크롤러 차단은 그대로다. 일반 크롤러 규칙은 없다(`User-agent: *` 항목 없음) [사실]. 수집 자료를 LLM에 넣는 것은 운영자가 거부한 용도라 **회색지대**로 본다.
- 결과물을 공개하면 용도와 무관하게 원 사이트 유사성에 대한 저작권 문제가 생긴다 [추정].

## 2. 확정 결정 (영환님, 2026-09-28)

### D1. 빠진 "알맹이" = 눈에 보이는 결과물(렌더러)이 먼저다 ★
- 현재 렌더 컴포넌트는 30변형 중 0개다 [사실] (`engine/contracts/sectionDefinition.ts:3`, R2 G1).
- 카탈로그가 비어 보이는 문제(썸네일이 와이어프레임, `ReferenceCard.tsx:16`)는 렌더러가 생기면 internal 레퍼런스의 **실렌더 썸네일**로 해소된다 (R2 G9).
- 따라서 착수 순서는 R2의 **M2a = VS-1**(변형 4개 실렌더 + PNG + 정적 HTML, 브라우저 단독)이다.

### D2. dbcut은 "사람 열람 → 추상 패턴 태그만 기록"으로 활용한다 ★
- R2 C-2의 경로 (3)이다. 큐레이터가 브라우저로 열람하고, 아래만 기록한다.
  - 기록함: 업종 · 목적 · 무드 · 섹션 순서 패턴(예: `header → hero(fullbleed) → services(cards-3) → …`) · 레이아웃 태그 · 색 계열 이름 · 타이포 성격
  - **기록하지 않음**: 이미지·캡처 · 문구 · 원 사이트의 구체 수치(hex·px) · 자동 수집 스크립트 결과
- 산출물은 카탈로그 항목이 아니라 **근거 코퍼스**다. 변형·프리셋 설계의 근거(TR-POL-04 "근거 3개")와 LLM 입력 컨텍스트(4절 Q6)로만 쓴다.
- 자동화 금지(제품 층): 제품 코퍼스를 만들기 위해 크롤러·스크래퍼·브라우저 자동화로 dbcut을 수집하지 않는다. 개인 전용 층의 수집 방식은 D5·Q14에서 정한다.
- [확인 필요] 사람이 열람해 만든 추상 태그가 약관 제12조의 "가공"에 해당하는지 법무 판단 (4절 Q11).
- 제휴·라이선스 문의(경로 b)는 채택하지 않았다. 원 사이트 권리가 남아 썸네일 노출 이득이 작기 때문이다.

### D3. LLM은 구조화 문서(PageDoc)를 채우고, 그림은 결정적 렌더러가 그린다 ★
- LLM 출력 = PageDoc 스키마에 맞는 JSON: 섹션 선택·순서 · 변형 ID · 슬롯 문구 · 이미지 지시(자체 그래픽 파라미터).
- 검증 경로: 스키마 검증(zod) → 기존 lint(`domain/lintPlan.ts`) → 게이트(`engine/gate/runGate.ts`) → 렌더.
- 기각안: LLM이 HTML·코드를 직접 생성. 편집기·게이트·내보내기를 우회하고 FR-GEN-03 결정성을 깬다.
- 기각안: LLM은 문구만. 구조 선택의 품질 향상 여지를 버린다(현행 FR-GEN-07 수준).

### D4. "최종 시안" 정의 = R2 A-1 권장안 ★
- **F2 등급 실렌더 페이지가 정본**이다. PNG와 정적 HTML은 같은 `(PageDoc 리비전, 라이브러리 버전, 생성기 버전)`에서 파생된다.
- React 프로젝트 zip은 P0 유지, 단계는 M4(빌드 검증 워커 필요).
- R2 A-6 결정 후보 1·7(시안 등급 F0~F3 채택)을 확정으로 본다.

### D5. 외부 수집 자료는 "개인 전용 층"에만 두고 제품과 분리한다 ★ (영환님, 2026-09-28)
- 전제: 지금은 영환님 개인 비상업 사용이고, **나중에 서비스할 수 있다** (grilling Q12 = c).
- 개인 전용 층 = PRD·TRD의 `external_observed`(비공개·조직 격리)에 해당한다. 원자료(캡처·원 URL)는 **이 층에만** 둔다.
- **저장소 밖에 둔다.** CLAUDE.md 규칙 6(외부 URL·캡처·이미지를 카탈로그와 코드에 넣지 않음)을 지키기 위해 git 추적 경로·픽스처·카탈로그에 넣지 않는다.
- **LLM 생성 입력에는 파생된 추상 태그만** 넣는다. 캡처·문구·원 URL은 생성 입력에 넣지 않는다(TRD 238행 "생성 입력 사용 금지"와 같은 선).
- 모든 파생 태그에 출처 층(`external_observed` / `internal` / `licensed`)을 기록한다. **서비스 전환 시 이 층과 파생물을 떼어 낼 수 있어야 한다** (처리 방식은 Q17).
- 세부 설계(저장 위치·수집 방식·저장 항목·태깅·전환 처리·유사도 가드)는 4a절 Q13~Q18.

## 3. 목표 파이프라인

```
[개인 층]   (저장소 밖·비공개) 외부 수집 원자료 ─▶ 태깅 ─▶ 파생 태그(출처 층 표시)
                                           │ 태그만 전달
                                           ▼
[근거 층]   큐레이터 열람(dbcut 등) ─▶ 근거 코퍼스(추상 태그만, 이미지·문구 0)
                                           │ (검색·요약된 패턴)
                                           ▼
[생성 층]   확정 프로필 + 사업 정보 + 섹션 라이브러리 스키마 ─▶ LLM ─▶ PageDoc JSON 초안
                                                                      │
                                   스키마 검증 → lint → 게이트 ◀──────┘
                                           │ 통과 시 PageDoc 리비전으로 저장 (이후 전부 결정적)
                                           ▼
[표면 층]   렌더러(M2a) ─▶ 캔버스 미리보기 ─▶ PNG 캡처 · 정적 HTML ─▶ (M4) React zip
                                           │
[카탈로그]  internal 레퍼런스도 같은 렌더러로 썸네일 생성 (G9)
```

- LLM OFF·실패 시: 기존 결정적 3안 생성기(`domain/composeCandidates.ts`)로 폴백한다. FR-SEL-04 "LLM OFF에서도 동작" 원칙을 생성에도 적용한다.
- 결정성: LLM 호출 자체는 비결정적이다. 그래서 **결정성의 경계를 "LLM 출력이 PageDoc 리비전으로 저장된 뒤"로 옮긴다.** 같은 리비전이면 같은 렌더·같은 해시다.

## 3a. 보조 데이터 경로 평가 (2026-09-28 추가)

영환님이 "합법적으로 웹사이트 리스트·디자인 데이터를 확보하는 방법" 목록을 받아 최선책을 물었다. 평가 결과를 남겨 같은 조사를 반복하지 않게 한다.

**결론**: 어느 경로도 우리 생성기의 핵심 입력인 **"업종별 홈페이지 섹션 구성"**을 주지 않는다. 주력은 D1(렌더러 → internal 조립)·D2(사람 열람 추상 태그)이고, 아래는 보조다.

**명확화 (D2 보강)**
- dbcut을 포함해 **어떤 아카이브에서도 도메인 목록을 수집하지 않는다.** 선정 목록 자체가 운영사의 편집물이다. [확인 필요] 한국 저작권법의 데이터베이스제작자 보호 해당 여부는 Q11 법무 확인에 포함한다.
- **LLM은 외부 사이트에 접속하거나 특정 사이트를 재현하지 않는다.** 입력은 Q6의 목록뿐이다. 이는 PRD 원칙 1·FR-SEL-06("이 URL처럼 만들기" 금지)과 같은 선이다.
- Q8의 "출처 도메인"은 큐레이터 관찰 위치의 감사 기록이다. LLM 입력과 카탈로그에는 쓰지 않는다.

**실제 사례의 신뢰를 주는 경로**는 이 표가 아니라 R2 C-2의 에이전시 opt-in 제출과 허용 라이선스 템플릿(HTML5 UP CC BY 3.0 · shadcn/ui MIT · Flowbite OSS MIT · Figma Community 무료 파일 CC BY 4.0)이다.

## 5. Jarvis 요청 사항

1. **4절 Q5~Q11과 4a절 Q13~Q18을 영환님께 확정받는다.** 권장안 일괄 승인도 가능하다.
2. **PRD·TRD 개정안을 만든다** (Hemingway/Newton 분장은 Jarvis 판단).
   - PRD FR-GEN-07(P2, 카피만)을 "LLM 구조 초안(PageDoc 채우기, 선택형, OFF 시 결정적 폴백)"으로 확장하고 우선순위를 재산정한다.
   - PRD FR-GEN-03 결정성 문장에 "LLM 출력은 PageDoc 리비전 저장 이후 결정적" 경계를 추가한다.
   - PRD 4절에 dbcut을 GDWEB과 같은 취급(이미지·태그 할당 데이터 수집·저장 금지, 사람 열람 기반 추상 태그만)으로 명시한다.
   - TRD에 근거 코퍼스 스키마(Q8)와 LLM 프록시(Q5)를 추가한다.
   - PRD 원칙 5·TRD 238행의 `external_observed` "MVP 제외"를 D5에 맞게 고친다: **소유자 개인 전용 층으로만 허용**, 저장소 밖·비공개·생성 입력은 파생 태그만·서비스 전환 시 분리. 이 변경은 ADR로 남긴다.
3. **실행 순서를 개발계획서에 반영한다.**
   1. M2a = VS-1 렌더 슬라이스 (R2 A-4) — 즉시
   2. 근거 코퍼스 수집 절차 — M2a와 병행, 사람 작업, Q11 법무 확인 후 시작
   3. LLM 구조 초안 — M2a 이후. 렌더러 없이 LLM 결과를 눈으로 검증할 수 없기 때문
   4. internal 레퍼런스 대량 조립 + 실렌더 썸네일 — M2b 이후 (R2 C-5 결정 2)
4. 이 브리프의 결정 D1~D4를 ADR로 남길지 판단한다. 제안 제목: "ADR-007 레퍼런스 근거 코퍼스와 LLM 구조 초안".
