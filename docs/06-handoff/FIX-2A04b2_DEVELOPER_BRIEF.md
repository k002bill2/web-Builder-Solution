## 1. 과제
### F1. 동적 import 실패 뒤 "다시 시도"가 영원히 실패 (D-2A4-01 P2 · D-2A4-02 P3)
- 재현(QA 실측, Chromium): 확정 본문 `memoryBoardConfirm` 청크 요청을 한 번 차단 → "프로필 확정" 오류 → 차단 해제 → "다시 시도"가 **요청조차 보내지 않고** 매번 실패. 같은 URL에 `?retry=1`을 붙이면 성공 → 브라우저 모듈 맵이 실패한 URL을 기억함(기전 L2). P-S25 `carryOverPanel`(다시 시도·Hero 재선택)도 같다. 되돌리기·조정 저장 본문(`memoryProfileAdjust`)은 같은 구조라 같은 결함으로 추정.
- 기대: 네트워크가 돌아온 뒤 "다시 시도" 1회로 성공. 앱 안에서 복구(새로고침 불필요 — 새로고침하면 메모리 store가 지워짐).
- 적용 대상: 조작 뒤 로더 전부 — `app/src/data/writeBodyLoader.ts`(`loadBoardConfirm`·`loadProfileWrites`), `app/src/features/compare/carryOverLoader.ts`. 자동 로더(`boardEngine` 등)는 범위 밖(실패 시 경계로 감)이나, 같은 헬퍼로 싸는 비용이 0에 가까우면 REPORT에 판단만 적는다.
- 설계 조건:
  1. 재시도 시 **같은 청크를 새 URL로** 다시 요청(실패 캐시 우회). 실패 오류에서 URL을 얻는다면 **같은 출처 + 빌드 자산 경로만** 허용하고 그 밖이면 원래 오류를 그대로 던진다(임의 URL import 금지 — 보안 경계).
  2. 첫 시도는 지금과 같은 정적 `import()`(번들 스크립트의 manifest 분석·분류가 그대로 유지되어야 함). 성공한 모듈은 다시 받지 않는다.
  3. 실패 후 결과(저장 0건 · 선택 유지 · 오류 문구)와 a1 계약(transact 밖에서 로드 완료, P-AC-42·A-Q3·I-1~I-3)은 바꾸지 않는다.
  4. 개발 서버/테스트(Vitest)에서도 깨지지 않을 것.
- 테스트(RED 먼저): 로더 헬퍼 단위 테스트(주입한 importer가 1회 실패 → 재시도는 다른 URL로 → 성공 / 다른 출처 URL은 거부 / 성공 뒤 재요청 0) + 기존 `WriteBodyLoad`·`CompareBoardCarryOver` 실패 경로 테스트가 "다시 시도 → 성공"까지 가도록 1건씩.
- **브라우저 확인 필수**: `vite preview --host 127.0.0.1 --port 4337`에서 QA 재현 절차(`git show main:docs/qa/2a-04ab/tools/expose-studio.mjs` 참고, 복사해 쓰지 말고 필요하면 CDP `Network.setBlockedURLs`만)로 확정·P-S25 두 경로의 "차단 → 해제 → 다시 시도 성공"을 캡처·로그로 남긴다. 되돌리기 경로도 가능하면 1회.
