## 전제와 검토 범위

사용자는 사이트 정보를 복제물이 아닌 참조로 쓰고 AI로 새롭게 가공하며, 사진·폰트·색상은 유사한 자료로 대체할 예정이라고 설명했습니다. 상업 서비스는 기존 설계의 가정으로 자문을 요청하며, 이번 메시지에서 확정된 사실로 취급하지 않습니다.

기본 검토 경로는 권한이 확인된 단일 페이지의 로컬 분석 → 추상 속성만 AI 추론 입력 → 독립 정보구조·새 문구·별도 사용권 자산으로 새 시안 생성입니다. 새 모델 학습·미세조정·데이터셋 구축은 검토 승인 범위가 아닙니다. 모델·공급자·자산은 미선정이며, 로컬 CLI는 로컬 모델을 뜻하지 않습니다. OpenAI·Anthropic 계약은 비교 사례이지 채택 결정이나 유료 API 추천이 아닙니다.[1][6][9][12][18]

R1 외부 입력 배제는 원문·자산에 대한 것으로, 추상 속성까지 모든 AI 입력을 금지한 뜻으로 확장하지 않습니다. 앞선 Jarvis의 ‘AI 생성과 충돌’ 해석을 바로잡습니다. 원문 클라우드 입력은 기본 경로 밖의 미승인 별건입니다.[1][6]

‘유사 자산 치환’은 원사이트의 외관·특징적 조합을 유지할 수 있으므로, 요구 기능을 기준으로 정보구조·위계·문구·자산 선택을 새로 하는 독립 재구성과 구별해 주십시오. 참조 자체·일반 레이아웃·통상 섹션 순서를 일괄 금지하지 않으며, 저작권상 보호 표현의 실질적 유사성과 별도 혼동·성과 무단사용 요건을 나누어 판단해 주십시오.[2][7][18]

Newton의 ‘중간 유지’는 추상 속성 입력 제한 경로의 정성 판단입니다. 법률 의견·법무 승인·출시 허가가 아닙니다. 코드 없는 설계 단계이며 실제 전송·로그·캐시·폐기는 검증되지 않았습니다.

## R2 질문 Q1~Q7

### Q1. [수정] 단계별 복제·공정이용·허락 근거

로컬 일시 분석 → 추상 속성 기반 AI 추론 → 상업 시안 생성의 단계별로 제35조의2·제35조의5 또는 별도 허락 중 무엇을 근거로 삼습니까? 원문을 외부 API에 넣는 별도 경로는 어느 복제·처리 권한이 추가로 필요합니까? 학습용 TDM 논의를 추론 입력에 적용할 수 있는지도 구분해 주십시오.[1][12]

결정 요청: 단계별 허용 근거와 추가 허락·일시 복제·폐기 조건. 한국 상업 AI 추론용 특별 TDM 면책 및 최신 전체 개정 현황은 원장상 미확인이므로 보완 확인을 요청합니다. [12]는 법안이며 시행법으로 전제하지 않습니다.

### Q2. [수정] 원사이트 약관·허락 범위·API 입력 보증

비회원·로컬 CLI·운영자에 대한 원사이트 약관 성립/편입 및 허용 목록 기준은 무엇이며, 허락이 추출뿐 아니라 클라우드 처리와 후속 상업 이용까지 포함합니까? 실제 API 계약의 입력 권리 보증·배상 조항을 충족할 수 있습니까?[6][9]

결정 요청: 도메인별 허락 증빙, 사용자·운영자 책임 및 후보 계약 승인 조건. 비교한 두 공급자의 일반 계약을 모든 API나 개별 계약에 일반화하지 말아 주십시오. 비학습과 무보관·입력 허락도 구별해 주십시오.

### Q3. [수정] 보호 표현·혼동·성과 이용과 독립 재구성

팔레트·서체·간격·섹션과 대체 사진의 조합이 보호 표현의 재현 또는 영업표지 혼동·성과 무단사용이 되는 경계를 어떻게 검토합니까? 원본을 보관하지 않으면서 사람 검토 및 독립 재구성 근거를 어느 수준으로 남겨야 합니까?[2][7][18]

결정 요청: 입력 상세도·생성 지침·출력 보류 기준과 최소 검토 기록. 특징적 순서 재현 기능의 제한은 보수적 제품 정책이며, 통상 섹션 순서 자체의 일반 법적 금지로 전제하지 않습니다. 유사도 점수·색상 변경률의 법정 안전선도 전제하지 않습니다.

### Q4. [유지] 서비스 전체 누적과 DB·데이터·성과 보호

사용자별 단일 페이지가 서비스 전체에서 누적될 때 DB 제작자 권리와 현행 (카)/(파)목 적용·누적 통제·중단 기준은 무엇입니까? ‘1 URL’ 안전선을 전제하지 않습니다. R1 질문을 유지하며, 원장은 현행 (카)/(파) 구분을 다시 확인했습니다.[2]

결정 요청: DB 제작자 권리의 별도 적용 근거와 도메인별 누적 통제·중단 기준. [2]의 (카)목 데이터 부정사용과 (파)목 성과 무단사용 요건을 구별해 주십시오. R2에 없는 DB 조문 원문이 새로 검증되었다고 간주하지 않습니다.

### Q5. [수정] 미국 웹 외관·AI 상업 이용 및 EU 별도 적용

미국 제공 시 웹 외관 trade dress의 분류·비기능성·식별력·혼동 및 준거법을 어떻게 판단합니까? AI 변환의 공정이용은 구체적인 상업 사용별로 검토해야 하는지, EU 제공이 추가되면 제3/4조와 현지 이행법·권리유보를 어떻게 적용할지도 분리해 주십시오.[10][16]

결정 요청: 국가별 제공 허용 범위와 추가 검토·제한 조건. [16]은 AI·웹사이트 직접 판례가 아니며 한국법 판단을 대체하지 않습니다. EU 일부 조문 추출 누락, 회원국 이행법·추론 입력의 TDM 해당성 미확인도 보완해 주십시오.

### Q6. [추가] 대체 자산·글자체·색채·화상 디자인

대체 사진/폰트/생성 이미지의 실제 라이선스가 웹 공개·임베딩·고객 납품·재배포를 허용합니까? 글자체 디자인권의 통상 사용 예외와 파일 라이선스, 색채상표/화상 디자인권을 별개로 확인하는 절차는 무엇입니까?[13][14][15][19]

결정 요청: 자산별 증빙·검토 절차와 보류 조건. 폰트 계열명·서체 도안·프로그램 파일을 구별하고, 디자인보호법 기준일 현행본 전체 대조를 보완해 주십시오. 확보 조문·연혁본과 현행 표시 간 차이가 있어 완전 대조는 미확인입니다.[13][14][20]

### Q7. [추가] 모델·공급자 계약과 입력·출력 책임

확정할 모델·서비스 계약에서 입력 보증, 공급자 보관/학습, 출력 배상과 입력·상표 관련 제외를 어떻게 승인합니까? 원문 입력은 계속 차단하고 추상 속성만 승인할지 먼저 결정해 주십시오.[6][9]

결정 요청: 후보 모델·실제 계약 버전·주문서·처리 설정별 승인 범위와 추가 자료. 원문 입력 예외를 검토한다면 기본 경로와 분리하고 권리·계약·보관·처리 조건을 별건 승인해 주십시오. 완전 로컬 모델도 원문 처리·출력·모델 라이선스가 자동 면책되지는 않습니다.

## 현재 안전장치 — 최대 여섯 가지, 모두 정책·설계 권고

아래는 구현 완료 사실이 아닙니다. 허용 목록·단일 페이지·robots·BL-1 등 기존 제품 정책·법무 게이트를 모두 법정 필수 조건으로 취급하지 않습니다. 자동 해제·변경 실행은 없습니다.

1. 접근·허락: 로컬 CLI·허용 목록·단일 페이지를 유지하고 추출·후속 상업 이용·외부 AI 처리 허락 범위를 확인합니다. 사용자 체크만으로 대체하지 않으며 기존 접근 제한·차단·우회 금지와 GDWEB·dbcut 영구 제외를 유지합니다.[6][9]
2. 수집 최소화: 순회·자동 재방문·공동 갤러리화를 금지하고 robots 존중·중단·누적량 통제를 유지합니다. 이는 보수적 제품 정책이지 법적 면책 주장이 아닙니다.
3. 저장·입력: 팔레트 값·글꼴 계열명·정규화 간격 범주·통상 섹션 태그만 허용 스키마로 전달합니다. 원문 HTML/CSS/본문·이미지·로고·스크린샷·정밀 DOM·좌표·폰트 파일·원본 자산 URL은 결과·로그·캐시·외부 모델 입력에서 배제합니다. 모델의 URL 재취득도 사용하지 않고 로컬 일시 복제·폐기 시점을 확인합니다.[1][6][9][17]
4. 독립 생성: AI 새 시안은 허용 검토하되 원본 복원 입력·프롬프트·템플릿 대신 독립 정보구조·새 문구·다른 시각 위계를 생성합니다. 특징적 순서·구도·조합 재현 목적의 기능을 제한하되 통상 순서 자체가 항상 위법하다는 뜻은 아닙니다.[17][18]
5. 고지·중단: ‘참조/AI 생성’을 면책으로 광고하지 않고 신고·중단·삭제 절차와 역할을 유지합니다. 입력 방식·공급자·검토 결과·허용 근거를 원문 없이 최소 기록하는 정책을 승인받으며 무보관 고지는 검증 전 확정하지 않습니다.[1][6][9]
6. 자산·출력 게이트: 웹 이용·임베딩·수정·납품/재배포 사용권을 증빙하고 사진의 특징적 구도·조명·배치 재현과 원폰트 파일 변형을 피합니다. 색채상표·브랜드 혼동·전체 조합의 보호 표현을 사람이 검토하고 의심 결과는 보류합니다. 유사도 점수·색상 변경률을 법적 합격선으로 쓰지 않습니다.[2][7][15][18][19]

## 변호사 답변 요청 형식

각 Q별로 다음 순서의 답변을 요청합니다.

1. 결론: 허용 / 조건부 / 불가 / 추가 확인 필요. 추상 입력 기본 경로와 원문 입력 별건을 분리해 주십시오.
2. 적용 전제·관할·근거: 적용 법령·판례·계약의 버전과 시행 시점을 적고 시행법·법안·정책 권고를 구별해 주십시오.
3. 필요한 자료·조건: 허락 증빙, 스키마, 후보 모델·계약·보관 설정, 자산 라이선스, 출력 사례 중 필요한 자료를 지정해 주십시오.
4. 변경할 설계·출시 게이트: 사용자·운영자 역할, 추가 허락, 검토 기록, 중단 기준 및 승인 범위를 명시해 주십시오.

## 근거·검증 한계

새 조사·디자인 추출·외부 전송은 하지 않았습니다. 본 질문서는 R2 원장의 사실·추정·미확인을 보존한 편집본입니다. 최신 TDM 법안 전체 처리 현황과 안내서 전문, 디자인보호법 현행본 완전 대조, 실제 권리·계약·출력·구현 적합성은 미확인입니다. 특별 면책이 ‘없다’고 단정하지 않습니다.

Newton 원장 보고상 번호·URL·증거 연결은 `citations OK`이나 문장단위 커버리지는 39/134(29%)로 기준 50% 미달입니다. 이는 이 질문서에 새로 실행한 커버리지 검사 수치가 아니며 법률 해석 검증도 아닙니다. 법률 의견·출시 허가로 사용하지 않습니다.
