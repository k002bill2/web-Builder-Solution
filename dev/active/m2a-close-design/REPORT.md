### 3.2 원인 (코드 `app/src/components/studio/StructureCanvas.tsx` Overlay · issues.map)
1. **위치 계산** — 문장 `<p>`가 `absolute top-full left-0 mt-1`, 즉 슬롯 사각형 **바로 아래**에 붙는다. 렌더 문서는 슬롯을 세로로 쌓으므로 "바로 아래" = 거의 늘 다음 슬롯(부제·카드 본문·다음 섹션 제목) 자리다. 문장끼리·다른 배지와의 충돌 회피도 없다.
2. **축소 비율** — 슬롯 사각형은 × 0.56(1280) / × 0.27(390)로 줄지만, 문장은 축소 층 밖이라 13px(caption1) 원래 크기다(r4.10 설계 — 칩·배지·문장 글자를 읽히게). 그래서 문장이 그것이 가리키는 슬롯보다 크고, 축소가 셀수록 덮는 면적이 커진다.
3. **문장 길이 × 폭** — 절대 위치 `<p>`의 폭은 감싸개(= 슬롯 폭 + 8px)에 묶여 줄바꿈된다. 카드 제목처럼 좁은 슬롯에서 2줄(1280) → 4줄(390)로 세로로 길어져 섹션 경계를 넘는다.
4. **z 순서** — 오버레이 층이 iframe 위(DOM 뒤)에 있고 문장에 흰 면(`bg-background-normal`)이 있어, 겹친 렌더 글자를 **완전히 가린다**(반투명도 아님). 포인터는 통과(`pointer-events-none`)하지만 시각적으로는 내용이 사라진다.

결론: 겹침은 특정 문구·폭의 우연이 아니라 "축소된 캔버스 위에 원래 크기 문장을 슬롯 바로 아래 붙인다"는 배치 규칙의 구조적 결과다. 위치 미세 조정(위로 뒤집기·폭 고정)은 다른 슬롯을 덮을 뿐 0이 되지 않는다.

> 문제 표시(B-03): 문제 요소에 2중 테두리(…그대로) + 모서리 번호 배지 "경고 N"/"차단 N"(N = 캔버스 문제 목록 순번, 문서 순서). **문제 문장은 요소 아래가 아니라 캔버스 머리(캡션 아래·프레임 위)의 "문제 목록"에 한 줄씩 둔다** — 줄 = 배지와 같은 "경고 N"/"차단 N" + 문장(상태 글자 토큰 on `background-normal`, N-9/N-10). 문제가 0이면 목록은 그리지 않는다. 이유: 축소 보기(r4.10)에서 원래 크기 문장을 슬롯 아래 붙이면 렌더된 다음 글자를 가린다(M2A-CLOSE-DESIGN 3절). 문장 요소는 부모 문서에 있고 필드 `aria-describedby` 연결·배지 클릭 → 필드 포커스는 그대로(r4.8).

## 6. 접근성
- 문제 문장 연결: 오늘 구조에서 문장 `<p id="canvas-issue-…">`는 부모 DOM · 필드 `aria-describedby` = `field-hero-1-title-count` 등 카운터 id 확인(V2 `inputs`). 4절 모든 안이 문장 id를 부모 DOM에 남긴다(E-AC-49).
- 대비: 문장·배지 = 흰 면 위 상태 글자 N-9 6.46 · N-10 6.52(SPEC 7.1, ≥ 4.5). 추천 A는 목록 바탕을 `background-normal`(흰 면)로 두어 같은 행을 쓴다. 캔버스 바탕(`fill-alternative` · muted) 위에 직접 글자를 올리면 N-3/N-4(5.77/5.82)라 그것도 4.5 이상이지만 시안은 흰 면 기준.
- 겹침 자체가 접근성 문제: 문장 흰 면이 렌더 글자를 완전히 가려(3.2-4) 저시력 사용자는 가려진 부제·카드 본문을 캔버스에서 읽을 수 없다.
- Q2: 빈 필수 칸은 캔버스에 시각 표시 0 — 화면 판독기는 필드 `aria-invalid`/게이트에서 알 수 있으나 보는 사용자는 "사라진 버튼"만 본다.
- Q10: 배지 번호가 전부 1이라 "경고 1"이 무엇을 가리키는지 글자로 구분할 수 없다(색·위치에만 의존 — 6.6 "색 하나로만 알리지 않기"와 같은 결).
- 비활성 내보내기 버튼(Q8)은 1.4.3 예외.
