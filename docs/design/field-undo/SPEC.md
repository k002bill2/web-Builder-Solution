## 0. 요약

1. **필드 글자 편집도 실행 취소 기록에 넣는다**(MQ-R5 ★A 이행). 묶음 1건 = 같은 필드에서 이어진 입력. 닫힘 = **600ms 멈춤 · blur · 다른 필드로 이동 · 다른 기록 · 미리보기 열기 · 언마운트**.
2. **참조 집합은 기록 스택을 그대로 따른다**(`undoStack.ts:27-29`의 계약 유지). 필드 기록이 삭제 전 문서까지 닿게 되므로, "삭제 → 필드 입력"은 더 이상 이미지를 놓지 않는다 — Ctrl+Z 두 번이면 그 이미지가 든 섹션이 돌아오기 때문이다.
3. 그래서 **바꿀 단언 2건**: `StudioLayoutImages.test.tsx:111-128`("되돌리기 무효화 → 이미지 빠짐") · `UndoKeys.test.tsx:99-108`("스택 밖 변경 뒤 Ctrl+Z = 되돌리지 않음"). "무효화"는 실제로 사슬이 끊기는 경우(다시 실행 잘림 · 상한 50 · 충돌 "최신으로")로 옮긴다(6절).
4. **진입 예산**: 진입 closure에는 "열린 묶음의 시작 문서·필드 키" ref와 호출 1줄만, 타이머·IME·라벨·push는 조작 뒤 청크(`docEngine`)가 첫 입력 때 받는다(8절). 증가 실측이 0.27KB(여유 0.37 − 멈춤 여유 0.10)를 넘으면 그 자리에서 멈추고 MQ-F4.

## 1. 목적 · 범위 / 제외

### 1.1 목적

"Hero 제목을 실수로 지웠다 → 칸 밖에서 Ctrl+Z / 더보기 '실행 취소'로 돌린다"를 섹션 연산과 같은 사슬·같은 알림·같은 단축키로 제공한다(2a-05 5.14 "필드 확정" 원문 충족 · ER-D2 `:280`).

### 1.2 지금(L1)

- 기록 스택은 섹션 연산(추가·삭제·이동·변형)과 테마만 받는다 — `useSectionOps.run` → `opAfter.commitOp`(`opAfter.ts:30-45`).
- 필드 글자는 **스택 밖**: `EditFields.tsx:63` `onChange → onEdit(setSlot(...))`, `onEdit = snaps.edit`(`StudioLayout.tsx:361`) → `useDocSave.edit`. 페이지 정보도 같다(`EditFields.tsx:44`).
- 실행 취소/다시 실행은 "지금 문서가 그 기록과 이어질 때만" 동작한다 — `stepHistory`의 `entry.after !== docRef.current` 비교(`opAfter.ts:53`) · `peekStep`(`useSectionOps.ts:90-96`). 스택 밖 글자 변경이 생기면 사슬이 끊겨 Ctrl+Z가 아무것도 하지 않는다(ER-4 REPORT `dev/active/er-4/REPORT.md:43`).
- 참조 집합(캔버스 `images`를 남길 문서) = 문서 ∪ 스냅샷 ∪ `stack.reachable(doc)`(`useSectionOps.ts:149` · `StudioLayout.tsx:298-308`). `reachable`은 사슬이 이어진 만큼만 센다(`undoStack.ts:55-59`) — 그래서 지금은 "삭제 → 글자 1자"만으로 삭제 전 문서가 집합에서 빠지고 이미지가 놓인다(`StudioLayoutImages.test.tsx:111-128`).
- 이미지 패널 편집(켜기·고르기·끄기·대체텍스트·장식)도 스택 밖이다 — `ImageSlotField.tsx:115,212`가 `onEdit`(= `snaps.edit`)를 직접 부른다. ER 3.5(`:144`)는 "넣음"이지만 미이행(L1). → MQ-F3.

### 1.3 범위

- 필드 글자(섹션 글자 슬롯 `FieldEditor`) · 페이지 정보(`PageInfoFields` — ER 3.5 `:145` "필드와 같은 규칙").
- 묶음 경계 · 섹션 연산/테마/복원/충돌과의 순서 · 이미지 참조 무효화 규칙 · 미리보기 중 거절 · IME 조합 · 탭 간(읽기 전용 탭) 동작 · 알림·"더보기" 항목 이름.
- 바꿀 기존 테스트 단언과 사유(6절).

### 1.4 제외

- 입력칸 **안** Ctrl/⌘+Z — 브라우저 기본 그대로(ER-AC-U2, `historyKeys.ts:6-7,18`). 이 SPEC은 칸 밖 단축키·"더보기"만 다룬다.
- 이미지 패널 연산의 기록 편입 — MQ-F3 결정 뒤 같은 규칙(4.5)으로 따라온다. 이 SPEC은 규칙만 정하고 구현 범위는 MQ-F3이 정한다.
- 기록의 탭 간 공유·영속(새로고침 뒤 유지) — 하지 않는다(ER `:152` "언마운트에 비움" 그대로).
- 상한 50 변경 · 묶음 단위 "단어/문장" 분할 · 글자 단위 실행 취소.

## 2. 사용자 흐름

### 2.1 정상

1. Hero "제목" 칸에 "봄 신메뉴 출시"를 친다(멈춤 없이) → 문서는 글자마다 바뀌고(지금 그대로 — 캔버스·카운터·자동 저장 디바운스) **기록은 아직 열린 묶음 1개**.
2. 600ms 멈춘다 → 묶음이 닫혀 기록 1건 "Hero 제목 편집".
3. "설명" 칸으로 Tab → (멈춤 전이라도) 제목 묶음이 닫히고, 설명에 치면 새 묶음.
4. 칸 밖(섹션 목록·캔버스·툴바 등)에서 Ctrl/⌘+Z → 알림 "실행 취소: Hero 설명 편집" · 설명 칸 값이 입력 전으로. 한 번 더 → "실행 취소: Hero 제목 편집". Shift+Ctrl/⌘+Z · Ctrl+Y → "다시 실행: …".
5. "더보기" → "실행 취소: Hero 제목 편집" 항목 = 같은 동작(ER-AC-U4).

### 2.2 섹션 연산과 섞임

- "Services 삭제" → Hero 제목 입력(600ms) → Ctrl+Z = 제목만 되돌림(삭제는 유지) → Ctrl+Z = Services 복원. 기록은 시간 순서 한 줄(섹션·필드 구분 없음).
- 묶음이 열린 채(600ms 전) 섹션 버튼을 누르면: **묶음을 먼저 닫아 기록한 뒤** 연산을 기록한다 — 기록 순서 = 사용자가 한 순서.
- 알림 줄 "되돌리기"(Q7 — 바로 앞 연산 1개)는 지금 그대로: 연산 뒤 글자를 치면 사라진다(`useSectionOps.ts:19,139`). 단축키·"더보기"로는 계속 되돌릴 수 있다.

### 2.3 빈 상태

- 기록 0 → "더보기" 두 항목 `aria-disabled` + 이유 "되돌릴 편집이 없습니다"(`MoreMenuBody.tsx:5`, 지금 그대로). 단축키 = 아무 일 없음 · 알림 0.
- 묶음이 열려 있으면 기록이 있는 것으로 본다: "더보기"를 여는 순간(포인터 = 칸 blur) 묶음이 닫혀 항목 이름이 "실행 취소: Hero 제목 편집"으로 보인다.
- 입력 결과가 묶음 시작 문서와 같으면(쳤다 지워 원래대로) 기록하지 않는다 — 되돌려도 아무 변화 없는 기록을 만들지 않는다.

### 2.4 오류 · 거절

- **스냅샷 미리보기 중**: 필드는 `aria-disabled`(ER-AC-S3)라 입력이 없다. 늦게 도착한 편집이 편집 경계에서 거절되면(`useSnapshots.tsx:62-68` → `false`) **기록하지 않는다** — B-ER-05 규칙(거절 = 실패, `opAfter.ts:40`)과 같다. 미리보기를 **열 때** 열린 묶음을 먼저 닫는다(미리보기 중 묶음이 열린 채 남지 않음).
- 미리보기 중 단축키·"더보기"는 무시/비활성(ER `:149` · `historyKeys.ts:14` 그대로).
- 충돌(STALE_DOC) 해결 "최신으로 불러오기": 문서가 다른 탭 것으로 바뀌므로 그 전에 묶음을 닫는다. 이후 사슬은 문서 동일성 비교로 끊긴다(지금 규칙 그대로 — 새 거절 문장 0).

### 2.5 경고

- 상한 50: 글자 묶음이 기록을 빨리 채운다 — 가장 오래된 기록부터 밀려난다(지금 그대로 `undoStack.ts:39`). 밀려난 기록만 쥐던 이미지는 참조 집합에서 빠진다(4.4). 별도 경고 문구 0(ER `:152`).

### 2.6 진행 중

- 묶음이 열린 동안(입력 ~ 닫힘 전): 화면 표시 0(입력 중 낭독 금지 — `FieldEditor.tsx:18`). 참조 집합은 **묶음 시작 문서 기준**으로 센다(4.4 — 이 구간에 이미지가 놓이지 않음).
- 실행 취소/다시 실행이 진행 중(동적 import 대기)에 친 글자: 연산 사슬(`useSectionOps.ts:80`) 뒤에 이어 붙어 처리되므로 덮이지 않는다 — 실행 취소는 "지금 문서와 이어진 기록"만 옮긴다(`opAfter.ts:53`).

## 4. 규칙 (정본)

### 4.1 묶음 경계

묶음 = `{ 키: instanceId + slotKey (페이지 정보 = "meta" + 필드 key), 시작 문서 base }`. 같은 키의 입력이 이어지는 동안 하나다.

| 닫힘 계기 | 동작 |
|---|---|
| 마지막 입력 뒤 **600ms** 멈춤(조합 중 제외 — 4.6) | 기록 1건 push `{ label, before: base, after: 지금 문서 }` |
| 그 칸 **blur** | 같음 |
| 다른 키의 입력(필드 이동 · 섹션 바꿈 = `EditFields.tsx:59` key 변경 재마운트) | 같음 → 새 묶음 시작 |
| 다른 기록이 생기기 직전(섹션 연산 `run` · 테마 · 복원 · 실행 취소/다시 실행 `step` · 알림 줄 `undoLast`) | 먼저 닫아 push → 그다음 그 기록 |
| 미리보기 열기 · 충돌 해결 시작 | 먼저 닫아 push |
| 편집기 언마운트(앱 안 이동) | 버림(스택도 비워진다 — ER `:152`) |

- **DOM blur에만 기대지 않는다** — 재마운트·탭 전환은 blur를 보장하지 않으므로 "키 변경 · 다른 기록 직전 · 언마운트"가 같은 닫힘을 낸다.
- 길이 상한 없음(멈춤 없이 계속 치면 1건) — 자동 저장 maxWait 30초(2a-05 `:326`)와 맞춰 쪼갤지는 MQ-F1.
- 닫을 때 `after === base`(내용 동일)면 기록하지 않는다(2.3).

### 4.2 사슬 · 순서

- 기록은 한 줄(섹션·필드·테마·복원 구분 없음) · 커서 모델 그대로(`undoStack.ts:33-41`). 새 기록 push = 다시 실행 목록 버림(지금 그대로).
- 필드 기록도 `before`/`after`를 **문서 참조**로 든다 — `stepHistory`(`opAfter.ts:53`)·`peekStep`(`useSectionOps.ts:93`)·`reachable`의 동일성 비교가 그대로 성립해야 한다. 그러려면 필드 편집이 `docRef`를 **같은 틱에** 갱신해야 한다(지금 `docRef`는 effect에서 갱신 — `useSectionOps.ts:74-77`; `commitOp`는 `:41`에서 직접 맞춘다).
- 입력칸 안 브라우저 실행 취소(Ctrl+Z in input)가 낸 change도 일반 입력으로 같은 묶음에 들어간다(문서 = 화면 값 — 이중 상태 0).

### 4.3 실행 취소 · 다시 실행 실행

- 필드 기록 실행 취소 = `edit(entry.before)` — 섹션 연산과 같은 경로(`opAfter.ts:51-65`). 편집 경계 거절(false)이면 스택 그대로(B-ER-05).
- 알림: "실행 취소: {섹션 이름} {필드 라벨} 편집" / "다시 실행: …"(5절). 포커스는 그대로(지금 규칙 — 포커스 요소가 사라지면 h2 "섹션").
- 되돌린 값은 입력칸에 즉시 보인다(제어 컴포넌트). 실행 취소 결과도 새 문서 → 자동 저장 2초(2a-05 5.14 `:372`).
- 단축키 리스너: 지금은 첫 `run` 뒤에만 붙는다(`useSectionOps.ts:126`). **첫 필드 기록 뒤에도 붙인다** — 입력만 한 세션에서도 칸 밖 Ctrl+Z가 동작해야 한다(U1).

### 4.4 이미지 참조 · 무효화 (B-ER-08 충돌의 결정)

**규칙: 이미지는 "실행 취소/다시 실행으로 닿는 문서"가 쥐는 동안 놓지 않는다. 필드 기록은 사슬을 끊지 않으므로 이미지를 놓는 계기가 아니다.**

- 참조 집합 = 문서 ∪ 스냅샷 ∪ 알림 줄 되돌리기 대상 ∪ `reachable` (`StudioLayout.tsx:298-308` 그대로) — 여기에 **열린 묶음의 base와 `reachable(base)`** 를 더한다. 묶음이 열린 600ms 사이에 문서가 기록과 어긋나 이미지가 놓이는 구간을 없앤다(놓인 이미지는 다시 못 살린다 — `StudioLayout.tsx:307-308` prune은 되돌릴 수 없음).
- 이미지 **삭제·교체 뒤** 필드 입력: 이전 이미지는 기록(교체 전 문서)이 쥐므로 남는다 — Ctrl+Z로 교체를 되돌리면 이전 이미지가 그대로 보인다(ER-AC-S6 "참조 집합 = 문서 ∪ 스냅샷 ∪ 실행 취소 ∪ 다시 실행"과 일치).
- 이미지를 실제로 놓는 계기(무효화)는 사슬이 **진짜로** 끊기는 때뿐:
  1. 실행 취소 뒤 새 기록(필드 묶음 포함) → 다시 실행 목록이 버려진다 → 그 목록만 쥐던 이미지.
  2. 상한 50 밀려남 → 밀려난 기록만 쥐던 이미지.
  3. 충돌 "최신으로 불러오기" 등 기록 밖 문서 교체 → 지금 문서와 이어지지 않는 기록.
  4. 편집기 언마운트(스택 비움 — 스냅샷이 쥐면 남음, ER 3.2).
  5. (MQ-F3 B를 고르면) 기록 밖 이미지 패널 편집 — 지금과 같은 끊김.
- 왜 다른 안(필드 기록이 삭제 전 문서까지는 닿지 않게)이 아닌가: 그러면 Ctrl+Z 두 번으로 About 섹션이 돌아올 때 그 이미지가 이미 놓여 **빈 이미지 섹션**이 된다 — ER-AC-U1(3.5 "넣음" 연산마다 직전 문서) 위반이자 데이터 손실. 단언을 지키려고 기능을 깨지 않는다(ADR-003 순위 1 기능 > 기존 테스트 문장).

### 4.5 이미지 패널 편집 (MQ-F3 ★A일 때)

- 켜기·고르기·지우기·끄기·장식 = 즉시 기록 1건(묶음 없음 — 클릭 1회 = 1건). 고르기는 비동기 변환 뒤 `onEdit` 성공 때 기록(`ImageSlotField.tsx:115` 거절 = 기록 0).
- 대체텍스트 = 필드 규칙(4.1) — 키 = instanceId + slotKey + "alt".
- 라벨: "{섹션 이름} 이미지 고르기 / 지우기 / 끄기 / 켜기 / 장식", 대체텍스트 = "{섹션 이름} 대체텍스트 편집".

### 4.6 IME 조합

- 조합 중(`InputEvent.isComposing` true인 입력)에는 600ms 타이머로 닫지 않는다 — 조합 중간(자모)이 기록 경계가 되면 되돌린 문서에 반쪽 글자가 남는다. 조합이 끝난 입력(조합 아님) 뒤 600ms 멈춤, 또는 blur·키 변경·다른 기록이 닫는다.
- 판정 입력 = change 이벤트의 `nativeEvent.isComposing`(진입에 새 리스너 0). 한글은 띄어쓰기·문장부호에서 조합이 끝나므로 보통 단어 단위로 600ms 경계가 생긴다 **[L3 추정 — 브라우저별 `compositionend`와 마지막 `input` 순서 차이(Chrome·Safari)는 실측 안 함]**. 조합 중 멈춘 채로 다른 곳을 누르면 blur가 닫는다.
- 칸 밖 단축키는 조합 중 무시(지금 그대로 `historyKeys.ts:14`).

### 4.7 탭 간

- 기록 스택은 **탭 로컬 메모리**다. 탭 사이 공유·BroadcastChannel 전파 0(P1C `docs/design/persistence/P1C-SPEC.md:87-88`).
- 읽기 전용 탭("다른 탭에서 편집 중입니다 — 이 탭의 변경은 저장하지 않습니다" — `app/src/data/persistence/infra.ts:26` · P1C `:82`): 편집은 메모리에서 계속 되므로 **필드 기록·실행 취소도 그대로 동작**한다(저장만 안 됨). 실행 취소가 잠금을 요청하지는 않는다 — 잠금은 저장 경로가 첫 쓰기에 잡는다(P1C `:74`).
- 다른 탭 저장을 받아 문서가 바뀌는 경로(충돌 해결 "최신") → 4.1 "충돌 해결 시작 전 닫기" + 4.4-3.

## 7. 접근성

- **포커스**: 실행 취소/다시 실행은 포커스를 옮기지 않는다(지금 규칙). 포커스가 있던 요소가 사라지면 h2 "섹션"(`opAfter.ts:63`). 필드 값이 바뀌어도 그 칸으로 포커스를 끌어가지 않는다.
- **라이브 영역**: 편집 알림 1문장만(ER-AC-C1). 묶음이 닫힐 때 알림 0(입력 중·멈춤 때 낭독 금지 — `FieldEditor.tsx:18`). 새 `role=status` 0.
- **키보드**: 칸 밖 Ctrl/⌘+Z · Shift+Ctrl/⌘+Z · Ctrl+Y(한글 자판은 `code`도 본다 — `historyKeys.ts:11,16`). 칸 안 = 브라우저 기본(`defaultPrevented` false). "더보기" 항목 = 같은 함수.
- **입력칸 안에서 칸 밖 기록을 되돌리는 길**: Esc 등 새 단축키를 만들지 않는다 — Tab으로 칸을 떠나면(blur = 묶음 닫힘) 바로 Ctrl+Z.
